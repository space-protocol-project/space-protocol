Продолжение: [клиентский транспорт и навигация](SPACE-PLUGINS-P2-BUILTIN-CLIENT.md). Ниже сохранена приёмка серверного среза на указанной ревизии.

Добавлен серверный путь команд без переноса пользовательских данных. Полный CI
успешен; этот серверный блок принят в указанных ниже границах.

## Контракт и рабочее подключение

`protocol/proto/space/v1/builtin.proto` определяет `BuiltinExtensionService`:

| Метод | Результат |
| --- | --- |
| `ListBuiltinSections` | Доступные текущему пользователю экземпляры с установкой, версией, каналом и представлением |
| `OpenBuiltinSection` | Разрешённый экземпляр и первая страница прежнего API, упакованная в protobuf `Any` |
| `ExecuteBuiltinCommand` | Ответ прежней команды в `Any`; ошибки сохраняют исходный код |

Служба зарегистрирована в рабочем сервере с PostgreSQL и в HTTP Connect-мосте.
Демонстрационный сервер без PostgreSQL её не предоставляет. Контракт OpenAPI
описывает службу, но отдельный REST gateway для неё не включён: рабочие входы —
gRPC и Connect. Сгенерированные Go/Connect bindings сохранены в сервере.
Flutter пока не переключён на новый API; его генерация и прикладной транспорт
относятся к следующему клиентскому срезу P2.

`instance_id` разрешается через постоянный реестр. Команда содержит прежний
тип запроса с прежним `channel_id`; этот канал обязан точно совпадать с записью
экземпляра. Разрешены только канонические имена
`type.googleapis.com/space.v1.<Request>` из фиксированной таблицы
`internal/builtin/commands.go`. Нет произвольного имени метода, динамического
поиска службы, загрузки кода или вызова внешнего пакета.

## Поддерживаемые команды

| Адаптер | Прежние команды |
| --- | --- |
| Чаты | `CreateContent`, `UpdateContent`, `DeleteContent`, `ApplyContentMutation`, `SetReaction` |
| MLS-чаты | `PublishMls` с неизменными epoch, request_id, ciphertext, Welcome и вложениями |
| Комнаты | `JoinVoiceRoom`, `UpdateVoiceRoom`, `LeaveVoiceRoom` |
| Обсуждения | `CreateForumThread`, `ReplyForumThread`, `SetForumThreadPinned`, `MarkForumThreadRead`, `CloseForumThread`, `ModerateForumThread`, `ModerateForumReply`, `ReportForumContent`, `ResolveForumReport` |
| Лента | `CreateFeedPost`, `CommentFeedPost`, `UpdateFeedAccess`, `ModerateFeedPost`, `ModerateFeedComment`, `ReportFeedContent`, `ResolveFeedReport`, `MarkFeedPostRead` |

Всего 26 типов. Вложенные действия `ApplyContentMutation` проверяют канал
внутреннего update/delete/reaction. Пустые, неподдерживаемые, повреждённые команды
и несовпадения типа адаптера отклоняются до вызова записи. Подмена обычного чата
на MLS не разрешает открытый текст: окончательное правило остаётся в ядре.

Чтение последующих страниц, поиск, вложения, реакции/избранное сообществ,
настройка каналов и остальные общие службы пока используют прежний RPC.
Это подключение команд четырёх адаптеров, а не полная приёмка паритета P2.

## Один путь записи и проверка прав

1. Рабочий interceptor проверяет Bearer-сессию и устанавливает доверенный actor.
2. Реестр повторно сверяет actor и сессию, блокировку участника, доступ к каналу
   и архивность. Идентификатор экземпляра не является разрешением.
3. Таблица команд проверяет принадлежность адаптеру и точное совпадение канала.
4. Тот же объект `chat.Service`, `Store` или действующая `voice.Service`
   выполняет прежний обработчик с прежним контекстом. В нём остаются проверки
   сессии/ACL, отдельных прав ленты, принадлежности MLS, ревизий и транзакции.

Нового SQL writer, отдельной очереди записи, нового ключа идемпотентности или
копии голосового состояния нет. Повтор между старым и новым RPC использует
прежнюю запись/квитанцию. Автоматический повтор не добавлен: операции без
прежнего ключа повторов, в особенности вход в голосовую комнату, не стали
идемпотентными. Клиент должен учитывать исходный контракт каждой операции.

Разрешение экземпляра и выполнение команды не объединены в новую транзакцию:
итоговые проверки и запись остаются внутри прежнего обработчика. Новый общий
барьер отправки ответа, новые гарантии доставки и атомарность с изменением
типа канала этим срезом не заявляются.

### Завершение голосовой сессии

`LeaveVoiceRoom` сохраняет прежнюю возможность освободить собственную сессию
после потери доступа к чтению комнаты. Для этой единственной команды реестр
проверяет действующую сессию и связь экземпляра с голосовой комнатой без ACL
чтения; затем прежний обработчик проверяет владельца подключения. Этот путь
не возвращает содержимое комнаты и не разрешает вход или изменение состояния
после отзыва доступа. Чужую сессию завершить нельзя.

### Ограничения размера

Внешний gRPC-запрос команды ограничен 1 МиБ + 4 КиБ оболочки. Connect ограничивает
вход 2 МиБ с учётом JSON/base64 и выход 8 МиБ. После распаковки применяется
прежний предел конкретного метода (обычно 16 КиБ, публикации/SDP/MLS — по
существующим правилам). Прикладная проверка значений остаётся в прежней службе.

## Проверки

Стенд `plugin-p2-registry.yml`: Ubuntu, PostgreSQL 17.11, настоящие сессии,
gRPC и HTTP Connect. Целевые тесты запускаются пять раз с `-race` и запретом
пропусков. Отдельное задание проверяет всё ядро обычным и race-запуском,
`go vet`, `go mod verify`, `govulncheck`.

- Одна запись и одинаковый ответ при вызове через новый gRPC, старый RPC и Connect.
- Неавторизованный вход, право чтения без записи, отзыв ACL и сессии.
- Подмена канала и адаптера, пустая команда, прежний предел размера.
- Повтор прежних ключей обсуждений и ленты через новый RPC.
- Публикация MLS, повтор между API, отказ постороннему устройству и изоляция Welcome.
- Настоящее согласование WebRTC: вход через адаптер, управление через старый RPC,
  запрет чужого выхода и освобождение собственной сессии после отзыва чтения.
- Прежние проверки реестра, транзакций, смены представления и обновления базы.

Голосовой тест проверяет совместное состояние сигнализации и очистку, а не
качество звука или задержки. Linux CI не заменяет многоплатформенную нативную
приёмку клиента. Полная матрица старого/нового клиента и сервера, навигация,
ограниченные клиентские повторы, архивная совместимость и полный паритет P2
остаются открытыми. Схема базы остаётся 48.
