# P1: полный manifest, capabilities, результаты и события

11 ноября 2026 года. Статус: контрактный блок полного manifest принят в GitHub CI. Этот документ относится к серверному кандидату P1; локальные клиентские установки используют свои ранее зафиксированные контракты.

## Версия и совместимость

Новый `manifest_version=2` добавляет обязательный объект `contracts`. Канонические источники: [JSON Schema manifest v2](extensions/p1/manifest-v2.schema.json), [общий пример](extensions/p1/manifest-v2.json), [профиль схем значений](extensions/p1/value-schema.schema.json). Версии ABI `space_plugin_p1`, host API `space.plugin.p1`, UI `space.ui.p1` и protobuf не меняются: новые ограничения применяются к существующим JSON-байтам запросов, результатов и событий. Генерируемые Go/Dart/Connect/OpenAPI не требуют изменения.

Manifest v1 сохраняется как ограниченный stateless-профиль: `data_schema=1`, без permissions. Его нельзя повысить до мутации через клиентское поле `effect`, внешнюю таблицу событий или отсутствие нового исполнителя. Старые SDK-каркасы не переписываются автоматически. Manifest v2 без полного `contracts`, неизвестная версия, лишние поля, дубли JSON-ключей, отсутствующие или `null` обязательные значения отклоняются.

`commands` и `queries` по-прежнему связывают имя операции со схемой входа. `contracts.commands` и `contracts.queries` должны содержать в точности те же имена. Каждая операция объявляет четыре поля:

| Поле | Значение и проверка |
| --- | --- |
| `result` | Локальный путь `schemas/<name>.json`; схема результата query либо поля `document` результата мутации |
| `effect` | `none` или `mutation`; query допускает только `none` |
| `capabilities` | Уникальное подмножество верхнеуровневых `permissions`; неизвестные права запрещены |
| `events` | Уникальный список типов из `contracts.events`, до 16 типов на команду |

`contracts.events` связывает тип события с локальной схемой его `payload_json`. До 32 определений событий, команд и query в каждом соответствующем словаре. Входные схемы сохраняют профиль форм P1: ограниченные string/boolean/enum, без произвольных выражений. Contributions ссылаются на объявленные query; предельные размеры, локализация и неизменяемость реестра сохраняются.

## Права и эффект

В этом кандидате поддержаны `storage.own` и `events.own`. Команда `mutation` требует `storage.own`; непустой список событий требует также `events.own`. Право `events.own` без объявленных событий отклоняется. План сохраняет прежние 1–32 операции над данными; команда только с событиями, без изменения данных, не входит в этот профиль. Stateless-операции не получают этих прав и не публикуют события. Новые сетевые, файловые и межустановочные права не добавлены.

Manifest описывает запрошенные права, но не выдаёт их. Доверенный установщик передаёт отдельно `ExtensionP1MutationBinding.Capabilities` после согласия владельца: список должен точно соответствовать permissions, без дубликатов и неизвестных значений. Это программный интерфейс прототипа, не готовый экран согласия. Рабочая установка и управление согласием относятся к интеграции P2/P3.

Для manifest-регистраций старый внешний `Binding.Events` запрещён. Исполнитель получает эффекты и допустимые события непосредственно из проверенного manifest. Несколько mutation-команд одной установки используют существующие ключи квитанций, в которых уже присутствует имя команды. Неподключённый исполнитель не позволяет вызвать mutation как stateless-команду, даже с `effect=NONE`.

Схемы, manifest и WASM копируются при регистрации. Одобренные capabilities входят в идентичность привязки вместе с пакетом; их изменение не может незаметно переиспользовать старую привязку и квитанции. Старые архивные записи без capabilities сохраняют прежнее кодирование благодаря `omitempty`. Подтверждение обновления проверяет новый manifest, схемы и grants; `data_schema` целевого manifest должен совпасть с `schema_to` плана.

Сессии и ACL не заменяются capabilities. До WASM и после него проверяется актуальный допуск ядра; существующие барьеры COMMIT и доставки остаются действующими. Все изменения и события ограничены installation/instance, выбранными ядром. План гостя не получает SQL, идентичность другого пользователя или право выбирать чужую установку.

## Схемы результатов и событий

`valueschema` реализует ограниченный профиль JSON Schema. Все свойства объектов перечисляются явно; `additionalProperties=false` обязательно. Поддерживаются:

| Вид | Границы |
| --- | --- |
| object | До 32 свойств; обязательный список `required`, без дубликатов и ссылок на отсутствующие свойства; имя свойства — 1–64 байта UTF-8 |
| array | Обязательные `items` и `maxItems`, предел 1–128 |
| string | Обязательный `maxLength`, предел 1–4096 символов; необязательный уникальный enum из 1–32 значений |
| boolean | Только JSON true/false |
| integer | Явные minimum/maximum в диапазоне ±(2^53−1); проверка без округления float |

Одна схема ограничена 128 узлами и глубиной 8 от корня. Дополнительно действует прежний предел вложенности самого JSON из ABI: вложенные object-схемы могут достичь его раньше, поскольку содержат промежуточные словари properties. Числовая запись ограничена 32 символами, показатель степени — диапазоном −32…32; дробное значение не становится целым из-за округления. Предел размера JSON также сохраняется из ABI. Запрещены `$ref`, URL, regex, дополнительные ключевые слова, nullable-значения и неизвестные типы. Проверка JSON Schema подтверждает структуру профиля; связи полей, глубину, число узлов и дополнительные пределы проверяет Go.

Все входные, выходные и событийные схемы входят в подписанный индекс ZIP и проверку точного состава пакета. Отсутствующий или лишний файл, неподдерживаемая схема и внешняя ссылка отклоняются даже при корректной подписи. Прежние ограничения размера ZIP, количества файлов, путей и ключей издателя не ослаблены. Большое число операций не отменяет общий предел пакета.

Результат query/stateless-команды проверяется после WASM перед выдачей. Для mutation схема `result` проверяет именно UI-документ; оболочка `ui_api/document/plan` и операции плана дополнительно проверяются существующим строгим protobuf-контрактом. Каждое событие проходит два условия: тип разрешён конкретной командой и payload соответствует его схеме. Ошибка результата даёт `extension_failed`, некорректный план или событие — отказ InvalidArgument; ни данные, ни квитанция, ни outbox при этом не записываются.

Проверка схем не подменяет семантическую проверку декларативного UI клиентом. Пример результата в общих фикстурах минимален; рабочий пакет обязан описать собственные разрешённые поля документа. `sdk.ContractStarter` создаёт воспроизводимый пример с фиксированным WASM-ответом для приёмки, а не готовую бизнес-логику расширения.

## Приёмка

Полный [CI сервера 43044102083](https://github.com/space-protocol-project/space-server/actions/runs/43044102083) успешен на `681868587df81d07a9d3bf3cd3faf349a2c9fef5`: четыре задания (фикстуры, модуль Linux, модуль Windows, ядро). [CI схем 43043780271](https://github.com/space-protocol-project/space-protocol/actions/runs/43043780271) успешен на protocol `b30eb8c2c17b73051adc714120d2cf5aa19f3dd7`, закреплённом в серверном workflow. Проверенная матрица: положительные и отрицательные контракты, подписанный пакет, две команды и повторы после перезапуска, отсутствие одобренных прав, запрет stateless-обхода, некорректные результаты/события без записи, отзыв ACL перед COMMIT и настоящее изолированное WASM-исполнение с PostgreSQL.

macOS остаётся отложенным по решению пользователя. Проверки manifest не закрывают Windows E03, итоговую UI-матрицу E06 или общую приёмку E07/P1; релиз не объявляется.

При ревизии сохранена совместимость старого кодирования архивной привязки: пустой новый список capabilities не сериализуется. Локально целевые Go-тесты прошли; полная локальная WASM-регрессия не запускалась успешно из-за отсутствия wat2wasm, race — из-за выключенного CGO. Приёмка опирается на GitHub CI с подготовленными фикстурами. Промежуточный запуск 43043994020 отменён как повтор старого SHA после временного сетевого отказа push; он не является доказательством итоговой ревизии.
