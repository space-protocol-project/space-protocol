# P1 — восстановление Linux-службы WASM при загрузке ОС

Продолжение [обновления с откатом](SPACE-PLUGINS-P1-LINUX-UPDATE.md). Добавлена отдельная системная служба восстановления до открытия сокета WASM. Принято 5 ноября 2026 года полной матрицей GitHub CI, включая повторные загрузки Ubuntu VM.

## Порядок загрузки

`space-client-wasm-recovery.service` включается через `sockets.target`, запускается после доступности локальных файловых систем и завершается до сокета и процесса WASM. Это root oneshot с `RemainAfterExit=yes`. Восстановление имеет исключительную блокировку и ограничение времени; ни Flutter, ни пользовательское расширение не запускаются с повышенными правами.

Отдельные drop-in-файлы добавляют `Requires`/`After` для службы восстановления и запрет запуска при наличии `/run/space-client-wasm-recovery-blocked`. Они находятся вне трёх файлов обновляемой поставки. Неуспех recovery блокирует открытие сокета зависимостью systemd; частично восстановленная установка не принимает новые вызовы.

Сам код восстановления хранится отдельно, в root-owned каталоге `/usr/libexec/space-client-wasm-recovery-v1`, и не заменяется вместе с кандидатом. Установщик публикует полный каталог до создания `pending`; повторная установка сверяет его файлы, владельца и права. Изменение реализации/формата этой версии требует отдельного перехода, а не перезаписи работающего recovery. Для уже установленной службы без этого механизма нужна обычная административная переустановка из новой поставки.

## Журнал и решения

Новый журнал имеет `format=1`. Для каждого из трёх файлов сохраняется прежний файл с SHA-256 либо явный признак отсутствия. Все элементы проверяются **до** первой записи при восстановлении. Неизвестный формат, отсутствующий снимок, несовпадение хеша или неподходящий путь приводят к отказу с сохранением журнала.

| Состояние при запуске recovery | Действие |
| --- | --- |
| Нет `pending` и `committed` | Завершить без изменения установки |
| Есть `pending`, прежний сокет enabled | Проверить снимок, вернуть файлы, перечитать units, восстановить enabled и разрешить запуск сокета |
| Есть `pending`, прежний сокет disabled | Вернуть файлы и disabled; блокирующий файл не даёт уже поставленному в очередь запуску открыть сокет |
| Прервана первая установка | Удалить три частичных файла WASM, оставить сокет закрытым; независимый bootstrap recovery сохраняется для следующей попытки |
| Есть `committed` | Завершить перенос снимка в `previous`, не откатывая принятую поставку |
| Повреждённый/неизвестный журнал | Не менять файлы, сохранить журнал и оставить сокет закрытым |

Восстановление при загрузке возвращает постоянную настройку enabled/disabled. Активность процесса до выключения питания сама по себе не разрешает включить ранее disabled-сокет. После восстановления выключенной установки административный установщик может принять новую поставку и снять блокировку. Простое исправление журнала требует повторного запуска recovery; автоматического обхода проверки нет.

`pending` удаляется лишь после восстановления файлов, их синхронизации и возврата настройки включения. Повторное выполнение остаётся идемпотентным. Для живого отката сбрасываются состояния отказа **и службы, и сокета**: счётчики неудачных запусков кандидата не должны мешать запуску возвращённой установки.

Установщик сохраняет ручное восстановление старого журнала без `format`, созданного предыдущим прототипом; bootstrap устанавливается только после такого восстановления. Новый загрузочный recovery неизвестные форматы не интерпретирует. Автоматическое получение обновлений, миграция самого recovery между версиями, другие дистрибутивы и пользовательский интерфейс диагностики остаются открытыми.

## Приёмка

На настоящем systemd runner проверяются шесть сценариев: SIGKILL при enabled, SIGKILL при disabled, повреждение снимка, повреждение формата, незавершённая уборка `committed` и SIGKILL первой установки. Дополнительно проверяются повторное выполнение без журнала и успешный повтор после исправления повреждённого снимка. При отказе сравниваются файлы и подтверждается отсутствие слушающего сокета.

Отдельное задание QEMU загружает официальную Ubuntu 24.04, сверяет образ с SHA256SUMS по HTTPS и сохраняет его точный хеш. Сначала устанавливается настоящая служба, затем кандидат задерживается до окончания проверки работоспособности. Стенд завершает установщик через SIGKILL, выполняет `sync` внутри гостя и принудительно завершает QEMU. После новой загрузки проверяются:

- новый kernel boot ID;
- автоматическое восстановление без команды установки после загрузки;
- прежние хеши executable и service/socket units;
- завершение recovery раньше открытия сокета;
- настоящий WASM-вызов для enabled и отсутствие сокета для disabled.

Выполняются два аварийных выключения и три загрузки одного диска: исходная, восстановление enabled, восстановление disabled. Это реальное прекращение работы гостевой VM, но в контролируемой точке после `sync`. Случайный обрыв несинхронизированных записей и физическая потеря питания/накопителя не объявляются проверенными. В артефакты не включаются SSH private key, диск VM или пакет с временной авторизацией.
