# ADR-019: первоначальный владелец и встроенная панель

Историческое решение заменено [ADR-025](025-unified-administration.md): HTML-панель удалена, управление находится в основном Flutter-приложении.

Дата: 8 октября 2026. Статус: реализовано в локальном экспериментальном профиле; не production enrollment.

## Контекст

Self-hosted сервер должен настраиваться через `/space`, в том числе на машине без браузера. Знание адреса, доступ к loopback и первое посещение не являются доказательством владения. Транспорт административных операций следует ADR-015: общий `.proto`, gRPC и сгенерированный HTTP/JSON gateway.

## Решение

Локальная команда `space-server -setup-code` подключается к PostgreSQL, создаёт случайный одноразовый код и завершает работу. В базе сохраняются SHA-256 и срок 15 минут. Повторная команда заменяет код; после назначения владельца выдача закрыта. Публичный GET setup возвращает только initialized.

Browser enrollment создаёт root/device Ed25519 WebCrypto keys. Root подписывает существующий transcript с явно запрошенным дополнительным scope `space.manage`. Обычный grant Flutter остаётся chat.read/chat.write. Наличие management scope ещё не делает principal владельцем: ClaimOwner атомарно проверяет код и пустой owner_id под блокировкой. Конкурентные попытки имеют ровно одного победителя. Get/UpdateSettings проверяют действующий grant, сессию, scope и совпадение principal с owner_id на каждом запросе.

SpaceSettings содержат title, chat_title, chat_enabled, registration_policy и revision. Update требует expected_revision; конфликт возвращает Aborted/HTTP 409. Назначение владельца и изменения настроек имеют транзакционный аудит. Manifest берёт названия и доступность из этих настроек. Отключение чата запрещает Create/List/ListEvents и прекращает Subscribe; данные не удаляются. Закрытая регистрация запрещает только новые roots.

Статика встроена в бинарный файл. Нет внешних scripts/fonts, inline scripts и произвольного HTML; строгие CSP/frame ограничения и безопасный текстовый вывод. Host совпадает с настроенным origin, присутствующий Origin сверяется целиком, POST/PATCH требуют JSON. Сессии передаются Bearer, cookies не используются, токен хранится в памяти страницы. Logout удаляет сессию на сервере.

## Сервер без браузера

Сервер слушает loopback. Владелец использует SSH port forwarding и браузер своего компьютера. При другом локальном порте явно задаётся -origin, совпадающий с адресом в браузере. [Пошаговая инструкция](../ADMIN-GUIDE.md). Публичный TLS deployment отдельным решением ещё предстоит.

## Последствия и границы

Неэкспортируемые CryptoKey сохраняются через IndexedDB structured clone. Это программная защита, не WebAuthn/passkey; XSS может вызывать подпись. Browser root пока отдельный от Flutter root, pairing и восстановление отсутствуют. Потеря браузерного профиля может лишить owner доступа. Не добавляем автоматическую выдачу новых привилегированных grants при отказе старого: пользователь отдельно подтверждает повторное root enrollment.

Следующий обязательный срез — восстановление и связывание устройств. Несколько администраторов, роли, приглашения, произвольные views, public HTTPS, аппаратные ключи и полный backup ещё не реализованы.

## Проверка

Go-тесты используют отдельные PostgreSQL schemas: конкурирующее назначение владельца, замена кода, отказ обычному grant того же root, конфликт revision, отключение chat API, закрытая регистрация и отзыв administrative grant. Сквозной Node-сценарий использует тот же identity.mjs с настоящим WebCrypto и работающим Go API; проверяет назначение, настройки, manifest, CSP, гостевой отказ и logout. Flutter проверяется отдельно. Браузерная проверка IndexedDB между перезапусками и полноценное восстановление остаются отдельными критериями.
