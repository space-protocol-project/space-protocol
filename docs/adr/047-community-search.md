# ADR-047: поиск внутри раздела сообщества

Первый срез ищет буквальную подстроку в заголовке/тексте темы, тексте ответа,
публикации или комментария только одного forum/feed-раздела. MLS, файлы,
поиск по всем разделам и морфология не входят в контракт.

`CommunitySearchService.SearchCommunityContent`, capability
`core.community.search.v1`, миграция 32. Старый клиент не меняется; новый скрывает
поиск без capability. Общий RPC работает через gRPC и авторизованный Connect.

Запрос после trim содержит 1–256 байт UTF-8; limit 0 означает 20, максимум 50.
Нулевые символы, некорректные курсоры и пустые запросы отклоняются.
Используются существующие неизменяемые функции нормализации Unicode и индексных
2/3-грамм поиска чата. `%`, `_`, обратная косая черта и SQL не становятся шаблонами.
Запрос ограничен временем. Полные тексты и файлы в результаты не копируются:
возвращаются заголовок и обычный текстовый фрагмент до 240 Unicode code points.

Каждый запрос, включая продолжение, заново блокирует/проверяет сессию, grant,
членство, read ACL и раздел. Архив и chat/MLS-разделы не поддерживаются.
Скрытые родители и скрытые ответы/комментарии исключаются до пагинации.
Право manage не открывает скрытый текст в поиске. Общее количество не выдаётся.

Порядок: created_at DESC, kind DESC, id в C-порядке DESC; курсор исключительный,
ограничен размером и привязан к запросу, разделу и principal. Курсор не выдаёт
дополнительных прав. Новый контент перед курсором не дублирует уже просмотренное.
Скрытие и отзыв действуют на следующем запросе; уже полученные байты не отзываются.

Клиент использует отдельный Cubit/Freezed и поколение запросов. Смена раздела,
закрытие, новый запрос и обнаруженный отзыв доступа инвалидируют прежние ответы.
Открытие результата повторно проверяется обычным RPC темы/публикации; найденный
ответ/комментарий открывается через sequence с сохранением курсора дальнейших страниц.
Все подписи переводятся на русский, английский и китайский; Android проверяется
автоматически без физического устройства.
