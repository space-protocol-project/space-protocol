# ADR-035: несколько сетевых адресов пространства

Дата: 16 октября 2026 года. Статус: реализация этапов 1–2.

## Решение

Постоянный `identity_origin` из ADR-026 остаётся частью идентичности, а HTTPS endpoint становится одним из нескольких маршрутов. Перенос не создаёт новую личность устройства или MLS leaf.

Endpoint содержит `host`, `port`, `type=https`, `priority`. Допустимы IPv4, IPv6 без zone ID и ASCII-домен; не допускаются пути, userinfo, query, fragment, wildcard и управляющие символы. Не более восьми уникальных адресов. Приоритет — целое 0–255; меньший пробуется раньше. Прослушивание настраивается независимо от объявляемого внешнего порта. TLS туннеля должен завершаться на сервере Space.

Объявление подписывается существующим Ed25519-ключом сервера. Каноническая полезная нагрузка: `space/endpoints/v1\0` + JSON массива `[server_id, identity_origin, revision, tls_fingerprint, [[host, port, type, priority], ...]]`. Порядок endpoint значим. Revision — сохраняемое положительное целое не выше 2^53−1. Клиент сохраняет принятую версию и содержимое: меньшая версия или другое содержимое той же версии отвергаются до авторизации и изменения профиля.

Приглашение передаёт endpoint, список запасных адресов, server ID и точный SHA-256 сертификата. При первом подключении ключ идентичности подтверждает пользователь; для сохранённого пространства сверяются прежний ключ, server ID, постоянный origin и TLS. Подпись объявления не даёт права заменить эти якоря доверия.

Сертификат сохраняется при смене адреса; его SAN не задаёт идентичность Space. Проверка TLS-отпечатка и срока действия обязательна даже при сертификате, которому доверяет системное хранилище. Автоматическая смена TLS-ключа и Let's Encrypt требуют отдельного подписанного перехода и пока не разрешены. Обычный HTTPS вне Space продолжает проверять имя.

Выбор маршрута ограничен по числу адресов, параллельности и времени. Проверяются только discovery/TLS; авторизация и изменяющие RPC идут через единственное выбранное соединение. Ошибка адреса не очищает MLS outbox. Сохранённый рабочий маршрут предпочитается при следующем подключении; свежий подписанный список получают через доступный маршрут. Если не работает ни один, нужны DDNS/relay/новая карточка. Автоматическая погоня за непроверенными HTTP redirect запрещена.

Объявленные сервером адреса не должны разрешать скрытое сканирование локальной сети. Для локальных адресов требуется явный пользовательский маршрут; число попыток и разрешённых DNS-результатов ограничено. Relay получает отдельный тип транспорта и способ выбора server ID, а не маскируется под обычный HTTPS endpoint.

## Проверки

Домен, IPv6, внешний порт, отличный от локального; безопасный отказ и запасной маршрут; неизменность ключей при смене адреса; повреждённая подпись, чужой server ID/TLS и откат версии; сохранение конфигурации и её версии после перезапуска; отсутствие двойной отправки. Полный согласованный откат всех записей не объявляется обнаружимым без независимого монотонного якоря.
