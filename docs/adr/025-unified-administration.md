# ADR-025: управление сервером из общего приложения

Дата: 9 октября 2026 года. Статус: первый срез реализован; сквозная проверка native gRPC и Flutter Web выполнена. Перенос остальных функций продолжается.

## Решение

Пользователь общается и настраивает выбранное пространство в одном приложении Space.
Раздел управления доступен владельцу или администратору. Действия дополнительно
ограничены подписанным scope устройства space.manage; показ кнопки не даёт полномочий.

Браузерная /space остаётся способом доступа, когда приложение не установлено.
Flutter-веб-сборка — оболочка тех же административных экранов, а не отдельная
идентичность, сервер авторизации или новый обязательный продукт для пользователя.
На сервере не требуются браузер или Flutter SDK: Go раздаёт готовые файлы.

## Начальная структура

```text
client/                       существующее приложение общения и управления
apps/space_admin/             тонкая браузерная оболочка общего модуля
packages/space_admin_ui/      общие административные экраны
packages/space_api/           HTTP/JSON gateway и ошибки транспорта
packages/space_identity/      браузерный мост к проверенной авторизации
packages/space_ui/            начальная тема Gruvbox для браузерной оболочки
```

Перемещение client в apps/space_client пока не выполняется: оно не нужно для
первого переноса и усложнило бы сборки. Общие клиентские identity/transport/theme
компоненты будут выделяться постепенно; существующая native реализация пока в client.

## Первый срез

- Native клиент открывает модуль через свою текущую SpaceSession. Новые ключи и
  административный аккаунт при открытии не создаются; используется gRPC.
- В браузере доступен экспериментальный маршрут /space/flutter/ с тем же модулем.
  Вход использует существующие CryptoKey из IndexedDB текущей /space на том же origin.
- Перенесены настройки названия, общего чата, выключателя чатов, регистрации и
  optimistic revision. Native вход использует роль текущего пользователя.
- В браузерной оболочке также есть создание первой идентичности с явным согласием,
  setup-code claim и серверный logout. Native первичная выдача space.manage пока
  не реализована: для устройства используйте административное сопряжение/recovery.
- Восстановление, камера QR, устройства, pairing и root rotation пока остаются в
  проверенной /space. Наличие незавершённого журнала rotation блокирует новый web-вход.
- Каналы, ACL, участники и приглашения ещё не перенесены в общий Flutter-модуль.
  В существующей /space эти функции продолжают работать.

## Транспорт и безопасность

Общий UI получает адаптер. Native адаптер вызывает AdminService текущей сессии;
браузерный адаптер обращается к нашему HTTP/JSON API. PostgreSQL, gRPC и
cryptographic identity сохраняются; Hasura, GraphQL и SuperTokens не добавляются.

Мост WebCrypto повторно использует существующие proof/root-history проверки,
не экспортирует приватные CryptoKey, проверяет pin server_id/serverKey перед входом.
Токен хранится только в памяти Flutter. Logout отзывает сессию на сервере.
Новая identity создаётся только после отдельного явного выбора. Отозванный grant
не заменяется автоматически новым grant.

Native модуль не отдаёт токен в браузер и не закрывает сессию общения при закрытии
экрана настроек. Сам Go-сервер проверяет роль и scopes на каждом запросе. Ошибка
403 может означать, что владельцу не хватает разрешения именно этого устройства.

Flutter Web нужен WASM renderer и динамические стили. CSP ослабляется только на
экспериментальном /space/flutter/ (wasm-unsafe-eval и inline styles); строгая CSP
существующей HTML-панели сохраняется. Внешние CDN выключены; движок и лицензированный
Noto Sans лежат в сборке. Доступ камеры и микрофона для нового маршрута выключен.

SPACE_ADMIN_WEB_DIR задаёт каталог предварительно собранных файлов. Go os.Root
ограничивает доступ этим каталогом, включая symlink; листинг каталогов запрещён.
Сборка не содержит пользовательских ключей. Кеширование отключено в этом срезе,
чтобы старая административная сборка не оставалась после обновления.

## План переноса

1. Общий модуль, вход и настройки: native/Web, ошибки ролей/scopes/revision.
2. Каналы и ACL: перенести уже работающие формы, архив и фильтрацию доступа.
3. Участники, приглашения и устройства.
4. Восстановление, сопряжение, камера и root rotation с прежними тестовыми векторами.
5. Проверить перезапуск, отзыв доступа, обновление сборок, доступность и узкие экраны.
6. Сделать Flutter основной /space только после равенства функций. До этого HTML
   панель остаётся рабочей; не удалять её JS-крипты, используемые identity bridge.

Объединение UI не объединяет автоматически ключи разных устройств: для этого
по-прежнему служат recovery card и подписанное сопряжение.
