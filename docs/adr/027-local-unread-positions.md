# ADR-027: локальные непрочитанные сообщения

Дата: 10 октября 2026 года. Статус: реализовано и принято по PostgreSQL/native CI.

## Контракт и границы

Content.sequence — устойчивый порядковый номер сообщения внутри канала. Create/List/Events возвращают одинаковый номер, идемпотентный повтор не создаёт новый. Channel.latest_message_sequence доступен только при праве read; public preview и visible-only не раскрывают количество сообщений. WatchChannels передаёт изменение этого номера, поэтому неоткрытый канал получает новый счётчик без подписки на его текст. Используются существующие sequence и next_sequence PostgreSQL; новая миграция не нужна.

Счётчик означает число сообщений после локальной позиции чтения этого устройства. Это не серверная квитанция о прочтении другим участником, не синхронизация чтения между устройствами и не счётчик только чужих сообщений. Удаление/редактирование контента и retention потребуют отдельного профиля счётчиков, когда будут реализованы.

## Flutter

Позиции хранятся в LocalChannelPositions отдельно по origin/server ID/principal/channel, без текста или секретов. Позиция не сдвигается назад; неизвестный message ID не применяется. Старое readThrough сохраняется для разделителя и совместимости. При обновлении старые позиции без номера восстанавливаются из загруженной истории; для неоткрытого канала со старой отметкой точный badge появится после открытия, без выдуманного значения.

В навигации показан badge (99+ для больших значений). В чате есть разделитель новых сообщений и переход к первой новой записи. Переход учитывает фактическую видимость lazy-элементов и не отмечает промежуточные кадры навигации прочитанными. Чтение отмечается только в активном чате, текущем маршруте без диалога поверх и окне resumed; просмотренные позиции определяются по полностью видимым сообщениям, либо по концу истории. Скрытая вкладка, фон и отсутствие read не очищают счётчик.

## Проверки

Controller: сохранение/перезапуск, монотонность, разные пользователи, неизвестный ID и отзыв чтения. UI: скрытый чат, фон/resume и длинная история с переходом к новым сообщениям. PostgreSQL: одинаковый номер в ответе, истории и событии, идемпотентный повтор, скрытие watermarks без read и в public preview.

Локальный Docker не используется; PostgreSQL приёмка выполняется в GitHub CI. Физическая камера остаётся отдельным ручным пунктом.
