# ADR-036: первый владелец при запуске без компьютера

Статус: принято, реализация приложения/runtime v0.3.3.

Linux-runtime может создать пространство с нуля командой `space-server start`.
Собственная PostgreSQL и постоянная идентичность сервера сохраняются локально.
Установщик скачивает проверенный комплект; отдельный экспорт с компьютера не нужен.

Первым владельцем становится первый участник, завершивший вход по одноразовой
ссылке из терминала. Не первый случайный HTTP-посетитель. В fragment ссылки
находятся `setup`, `tls` и `server`; секрет не передаётся discovery-запросом,
HTTP URL, редиректом или другим TLS-сертификатам. Приложение отправляет временный
заголовок только через pinned HTTPS; приглашение и setup в одной ссылке запрещены.

Используется существующий ручной ClaimOwner с блокировкой строки PostgreSQL:
один владелец, 15 минут, проверка hash, запрет повторного захвата. Перезапуск до
назначения владельца меняет код. Глобальный `first_login` для интернета не включается.
Bootstrap RPC ограничены allowlist; сервер не открывает обычный вход, пока не
закрыта свободная регистрация. Локальный bootstrap из приложения остаётся прежним.

Владелец назначает несколько администраторов существующим UpdateMember. Роль
не заменяет полномочия устройства: для управления нужен grant `space.manage`.
Обычное устройство может запросить его с подписью своего root после назначения
роли; recovery-only и дочерние устройства не повышаются автоматически.

Приёмка: неизвестный клиент до setup не входит; два ClaimOwner не создают двух
владельцев; неверный pin, повторные/просроченные поля и заголовки отклоняются;
владелец и дополнительный администратор работают после перезапуска. Секрет не
попадает в клиентское хранилище и журналы CI.
