# ADR-030: Переход на ConnectRPC

Статус: полный Connect-мост и перенос основного приложения реализованы; обратная совместимость клиентских транспортов снята по решению пользователя 14 октября. Для установленного домашнего сервера нужен новый опубликованный runtime.
Дата: 11 октября 2026 года. Основание: пользователь выбрал ConnectRPC.

## Решение

Использовать Connect-Go на сервере и Connect-Dart во Flutter с существующими Protobuf-сервисами и Buf. Сохранить бизнес-логику, PostgreSQL, формат идентичности, подписи, grants, токены, ACL, идемпотентность и курсоры. Выбор библиотеки не означает, что транспорт уже заменён.

Connect-Go поддерживает Connect, gRPC и gRPC-Web; обработчики работают через net/http. Connect-Dart поддерживает эти три протокола и заменяемый HTTP-клиент. Эти возможности позволяют организовать постепенный переход с проверкой старого gRPC-клиента. Старые HTTP REST-маршруты grpc-gateway сохраняются до отдельного решения о совместимости; Connect JSON сам по себе не повторяет их URL.

## Порядок внедрения

1. Закрепить версии Connect-Go, генератора и Connect-Dart; проверить совместимость с используемыми Go/Dart и генерацией Protobuf. Не обновлять остальные зависимости без необходимости.
2. Прототип: GetManifest, вход по ключу и защищённая подписка событий из Dart. Проверить бинарный и JSON Connect, работу по HTTPS и отмену подписки.
3. Перенести аутентификацию в HTTP middleware перед декодированием запроса; Connect-interceptors использовать для остальных аспектов. Отдельно подтвердить deadlines, metadata, коды ошибок, ограничения размера, слоты потоков и отзыв grants/ACL для уже открытого потока. Простое подключение новых обработчиков не должно обходить текущие gRPC-interceptors.
4. Проверить самоподписанный сертификат домашнего сервера: доверенный отпечаток, срок действия, имя/IP и отказ при подмене. Не отключать проверку сертификата. Проверить отсутствие повторов авторизованных запросов на неподтверждённом адресе.
5. После сквозных проверок перевести приложение: история, отправка, события и WatchChannels, затем управление, recovery и pairing. Сохранить текущие коды пользовательских ошибок и изоляцию сессий/черновиков разных серверов.
6. CI на трёх ОС: старый gRPC-клиент против нового сервера, Dart/Go Connect, повтор запросов, разрыв и восстановление потока, HTTP JSON, ACL и миграции. Удаление прежнего транспорта — отдельный завершающий срез после приёмки.

Новый домашний runtime требует отдельного выпуска; закреплённый v0.2.2 не заменяется автоматически. Перенос бинарных вложений и медиапотоков не следует из выбора RPC: их ограничения и способ передачи проектируются отдельно.

## Первый срез прототипа, 12 октября 2026 года

Connect-Go/генератор 1.19.2 совместимы с Go 1.24; 1.20 и 1.21 требуют Go 1.25. Protobuf runtime поднят с 1.36.6 до минимально требуемой 1.36.9. Connect-Dart/генератор закреплены на 2.0.0; приложение сохраняет остальные зависимости. Генерируемые Connect-bindings находятся у потребителей.

Четыре маршрута: GetManifest, CreateChallenge, CompleteChallenge, Subscribe. За экспериментальным флагом вызовы передаются в штатный gRPC-сервер; его interceptors, grants, ACL и лимиты остаются авторитетными. Передаётся только Authorization; Grpc-Metadata-* не прокидывается. Размеры входного тела и распакованного сообщения ограничены 16 КиБ. HTTP Host/Origin проверяются; новые media types принимаются только на известных Connect-процедурах. Отмена потока закрывает upstream, запись имеет обновляемый таймаут 20 секунд.

Go-тест проверяет JSON/Protobuf, отказ неверному token и отмену. Dart-сценарий в CI использует loopback HTTP, временные ключи в памяти и штатную проверку серверной подписи transcript: manifest, challenge/login, heartbeat, событие, отмена, отсутствие token и отзыв активного потока. Он не является проверкой домашнего HTTPS/pinning и не переключает рабочие сессии приложения.

Рекомендация об HTTP-аутентификации до декодирования: https://connectrpc.com/docs/go/interceptors/. Для прямых Connect-обработчиков этот этап обязателен; прототип сохраняет авторизацию внутри существующего gRPC-сервера.

Приёмка: [CI сервера 38174641293](https://github.com/space-protocol-project/space-server/actions/runs/38174641293), 6e59209 — успешны PostgreSQL и loopback Connect Dart/Go Protobuf/JSON, события и отзыв, прежний gRPC и нативный vault Windows. [CI установщиков 38174638446](https://github.com/space-protocol-project/space-app/actions/runs/38174638446), 1e0fdef — Windows/macOS/Linux успешно. Локально 111 тестов Flutter, анализ, Windows release и hot restart без ошибок. HTTPS/pinning из Dart остаётся открытым.


## Полный перенос — 14 октября 2026 года

- Сервер обслуживает все 37 RPC через Connect и прежний gRPC-сервис; PostgreSQL, ACL и криптографические форматы общие. Проверка HTTP-авторизации выполняется до декодирования; список публичных процедур совпадает с gRPC.
- Новый discovery объявляет `connect_endpoint: "/"`; основное приложение, управление, recovery и pairing выбирают Connect на том же origin. Без поля или при неизвестном endpoint подключение отклоняется с предложением обновить runtime. gRPC-клиент, bindings и выбор транспорта удалены; pairing тоже использует общий TLS-проверенный Connect-клиент.
- Самоподписанный и системно доверенный сертификаты проверяются по точному SHA-256 и сроку при установлении TLS-сокета, до передачи авторизации. HTTP-перенаправления отключены. HTTP-сжатие согласовывается с возможностями транспорта: автоматически добавляемый системным клиентом gzip удаляется.
- Сохранены пользовательские коды ошибок, сроки unary/stream, таймаут отсутствия кадров, отмена и восстановление подписок. Домашний сценарий проверяет закрытие уже открытого потока при блокировке участника через Connect.
- Инструмент `treesitter_cyclomatic_complexity` (7b216f2), режим inline: новые адаптеры Dart CC ≤ 5 / COG ≤ 4, Connect-мост Go CC ≤ 3 / COG ≤ 2, общая авторизация CC 4 / COG 3. Предшествующие большие функции запуска и сессии не входят в эту оценку. [Подробности и воспроизведение](https://github.com/space-protocol-project/space-app/blob/main/docs/CONNECTRPC.md).

Приёмка: [сервер, PostgreSQL, Flutter и Windows vault](https://github.com/space-protocol-project/space-server/actions/runs/38494346887), повторный прогон после снятия обратной совместимости успешен. [Домашний runtime Windows/macOS/Linux](https://github.com/space-protocol-project/space-server/actions/runs/38494342578) успешно проверил реальный HTTPS Connect, приглашение, активный ACL-поток, перезапуск и обновление между двумя Connect-кандидатами. Локально прошли 228 тестов Flutter, включая восемь сетевых проверок транспорта, анализ, Go tests/vet и сборка Windows; hot reload не выявил исключений Dart.

В Windows debug-прогоне движок Flutter записал ошибки обновления дерева accessibility (`AXTree`); исключений Dart не было. Это отдельная проблема платформенного интерфейса, не подтверждение корректности accessibility. Ручная приёмка на физических системах остаётся открытой.

Публикация нового runtime и закрепление его проверенных архивов в приложении — отдельный оставшийся пункт выпуска. Установленный runtime v0.2.2 не поддерживается новым клиентом; его нужно обновить до Connect-выпуска.


14 октября пользователь снял требование обратной совместимости. Клиент использует только Connect, сервер больше не принимает внешние gRPC-запросы на публичном HTTPS, переключатель `-connect-rpc` удалён. Сквозной тест обновления сохраняет данные между двумя Connect-кандидатами и проверяет восстановление копии, без связи нового клиента с устаревшим сервером. Повторная приёмка этой редакции прошла: серверный CI 38494346887 и домашний runtime 38494342578 успешны; ранний прогон с совместимостью не используется как подтверждение новой редакции.

[Установщики новой редакции](https://github.com/space-protocol-project/space-app/actions/runs/38494332260) успешны на Windows/macOS/Linux, включая установку и перезапуск Windows. Финальная Windows-сборка и hot reload выполнены, исключений Dart нет.
