# ADR-054: профиль участника пространства

Первый срез: имя и аватар, без переопределений по разделам. Профиль относится
к существующему server-local principal, не создаёт новую личность и не меняет
ключи, grant, роли, блокировки, авторство и ID адресатов упоминаний.

`core.member.profile.v1` добавляет MembershipService.GetParticipantProfile,
UpdateParticipantProfile и ListParticipantProfiles. Собственный профиль читается
и изменяется только по текущей действующей сессии; произвольного principal ID
в операции изменения нет. Роль reader также может изменить собственный профиль.
Имена уникальны в пространстве: NFKC-нормализация и Unicode case folding,
транзакционная блокировка на всё пространство.
Одновременный выбор одного имени завершается одним успехом и AlreadyExists. Прежний UpdateProfile и его сообщения удалены из протокола, реализации и клиента.
Клиент не использует прежний API и не подменяет профиль изменением ника.

Имя: до 40 Unicode-символов и 160 UTF-8 байт, без управляющих символов.
Пустое имя означает отображение ID. Аватар: PNG до 8192 байт и 256×256 px,
полная проверка декодером и повторное кодирование без метаданных. SVG, URL,
анимация и внешние ссылки не принимаются. Новый профиль обновляется атомарно
с обязательной ожидаемой ревизией; конфликт не перезаписывает чужую правку.
Аватар можно оставить прежним, заменить или удалить явно.

Пакетное чтение: максимум 50 ID, только внутри доступного read/visible раздела,
при действующей сессии и scope. Возвращаются только незаблокированные участники,
имеющие чтение этого раздела; в MLS — только действующие участники группы.
Нет общего перечисления профилей, имён ролей и статуса блокировки в ответе.
Недоступный профиль пропускается; клиент показывает безопасную заглушку и ID.
Запросы MLS используют состав группы, а не получателей упоминаний или текст.

Клиент хранит аватары в ограниченном кеше текущей сессии и раздела, повторно
получает профиль для синхронизации устройств. Смена сессии отменяет применение
запоздалых результатов. Имя автора показывается по текущему профилю, исторический
текст сообщения и снимок имени в упоминании не переписываются. ID доступен
для проверки личности автора независимо от изменения имени.

Схема 37 добавляет только аватар и ревизию профиля к memberships. Старые имена,
идентичность сервера, содержимое и ACL сохраняются. Для редактирования профиля нужен сервер с указанной capability; fallback отсутствует.
Приложение и сервер с новым контрактом выпускаются совместно. Проверки:
PostgreSQL/Connect, ревизии/конкуренция, scope/отзыв/ban/ACL, изображения,
перезапуск и миграция, несколько устройств, поздние ответы и узкий экран.
Android на устройстве и эмуляторе не запускается.

OpenAPI генерируется с `generate_unbound_methods=true`: RPC имеют явные POST-пути
`/space.v1.MembershipService/GetParticipantProfile`, `UpdateParticipantProfile`
и `ListParticipantProfiles`. Прежний UpdateProfile в описании отсутствует.
