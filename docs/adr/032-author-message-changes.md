# 032. Редактирование и удаление сообщений автором

Дата: 15 октября 2026. Статус: принято. Версии реализации: приложение v0.2.9 и сервер/runtime v0.2.5.

ContentService.UpdateContent принимает channel_id, id, text и expected_revision.
DeleteContent принимает channel_id, id и expected_revision. Оба возвращают
актуальный Content. Его revision начинается с 1, увеличивается при изменениях;
updated_at_unix_ms содержит серверное время изменения, deleted обозначает удаление.
Созданное время и sequence сообщения сохраняются.

Проверяются сессия, членство, блокировка, ACL, доступность и архивность канала,
разрешение chat.write и совпадение author_id с principal_id. Владение пространством
не даёт права редактировать чужие сообщения. Устаревшая версия возвращает Aborted,
удалённое сообщение нельзя восстановить редактированием. Текст — непустой после
trim, до 4096 байт UTF-8. Удаление очищает текст, оставляя служебную запись и курсор.

Для повторов CreateContent сохраняется SHA-256 исходного текста запроса вместо
самого текста: повтор после правки/удаления возвращает актуальное состояние,
а другой текст с прежним ключом отклоняется.

Изменение сообщения и запись события фиксируются одной транзакцией под блокировкой
канала. Порядок событий независим от sequence сообщений. Миграция 12 сохраняет
существующие курсоры event-N и добавляет content_sequence. Новые типы событий:
content.updated и content.deleted. ListEvents/Subscribe возвращают текущее состояние
связанного сообщения, включая служебную запись удаления; удалённый текст не хранится
в отдельном снимке события. Клиент применяет только не более старую revision.
Правки не создают новые сообщения и не повышают счётчик непрочитанных.

Клиент не меняет текст оптимистически. Диалог сохраняет ввод при ошибке; удаление
требует подтверждения. Удалённое сообщение исключается из избранного, локальная
история сохраняет служебную запись. История загружается при каждом подключении,
включая прямой вход без предварительного открытия обзора сохранённых серверов.
Смена идентичности/гранта и подтверждённый отзыв доступа сохраняют прежние правила
очистки локальных данных.

Проверки: PostgreSQL — авторство, конфликт, конкурирующие правки, отзыв записи,
курсор после удаления, сохранение старой истории при миграции; Connect — изменение,
удаление и доставка обоих событий в живой поток; Flutter — события, устаревшие версии,
избранное, повторное подключение, перезапуск и сохранение текста редактора при ошибке.
