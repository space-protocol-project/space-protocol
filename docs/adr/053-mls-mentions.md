# ADR-053: структурированные упоминания внутри MLS

25 октября 2026. Выпущено в приложении v0.7.25+55 с runtime v0.7.19.
Локальная приёмка и обязательный релизный CI успешны; установщики, хеши
и подпись APK проверены. Приложение v0.7.24 использовало прежний формат v1.

## Формат сообщения

Прежний JSON приложения `version=1` сохраняется без дополнительных полей.
Выбранные обращения передаются в `version=2` как массив `mentions` внутри
MLS ciphertext. Каждая запись содержит `principal_id`, `display_name`,
`start` и `length`. Диапазоны измеряются в кодовых единицах UTF-16,
упорядочены, не пересекаются и точно соответствуют `@display_name` в тексте.
Обычный текст с `@` не становится структурированным обращением.

Не более десяти записей; ID ограничены 128 ASCII-байтами и не содержат
управляющих символов. Пустые имена, неверные типы, разрезанная суррогатная
пара и неизвестные поля отвергаются. Снимок имени относится к сообщению,
а личность определяется ID. Упоминания разрешены у текста и ответа с
вложениями; управляющие сообщения и реакции не получают таких полей.

## Совместимость устройств

Поддержка формата объявляется маркером `0xF053` в подписанных MLS
LeafNode capabilities. Это значение из диапазона private use
[реестра IANA](https://www.iana.org/assignments/mls#mls-extension-types).
Групповые required capabilities не меняются: старые устройства могут
присоединяться. Новый формат отправляется только когда все текущие листья,
включая собственный, объявляют поддержку. Иначе выбранное имя отправляется
прежним зашифрованным текстом без ID и диапазонов.

[RFC 9420, раздел 7.2](https://www.rfc-editor.org/rfc/rfc9420.html#section-7.2)
включает capabilities в подписанный LeafNode и требует игнорировать
неизвестные значения этого списка. Поэтому объявление поддержки не требует
ослаблять строгий разбор прикладного JSON у прежних клиентов. Серверный
список устройств или неподписанное заявление о версии не заменяет проверку
поддержки по подтверждённому дереву MLS.

Для существующего собственного листа поддержка обновляется обычным
`self_update` через уже имеющуюся операцию `update`. Обновление не должно
обгонять незавершённую отправку; подтверждение и повтор сохраняют прежнюю
транзакционную схему. Повторное приглашение и смена ключей личности не нужны.
Откат приложения после получения сообщений v2 не заявляется совместимым:
для отката требуется подходящая копия и версия приложения.

## Проверка и хранение

Rust проверяет форму и диапазоны до принятия сообщения; при отправке —
также адресатов по подтверждённому составу группы и поддержку формата.
Неудачный разбор не расходует ratchet основного состояния. Dart повторяет
проверку недоверенных данных при чтении локальной истории и переносе.
Историческое имя сохраняется; подсветка обращения к себе определяется
по principal ID, а не по совпадению текста или имени.

Очередь отправки, защищённая история и зашифрованные архивы сохраняют
выбранные диапазоны. Данные не попадают в открытые SharedPreferences,
PublishMlsRequest, серверные индексы или персональный серверный список.
Сервер продолжает передавать непрозрачный ciphertext; новой миграции БД
для этого среза нет. Криптографические алгоритмы MLS не меняются.

Если адресат исключён до повторной отправки, очередь останавливается.
Явная отмена повторов после смены состава доступна в меню защиты и истории;
неподтверждённые исходящие пакеты при этом сохраняются. Скрыто удалять ID
исключённого адресата или подменять его одноимённым участником нельзя.

## Приёмка

- Новые устройства обмениваются настоящим ciphertext с ID и UTF-16;
  смешанная группа сохраняет чтение v1 прежним движком.
- Обновление существующих листьев включает v2 после подтверждённых commit;
  новый прежний участник снова требует совместимого текстового варианта.
- Проверяются emoji, повторяющиеся имена, перекрытие диапазонов, чужой ID,
  неизвестные поля, управляющие сообщения, очередь, перезапуск и архивы.
- Выбор, черновики, отображение и обращение к себе работают на узком экране;
  смена личности и состава группы отбрасывает запоздалые результаты.
- Пройдены: Flutter 928 / 35 пропусков, чистый анализатор и COG (максимум 14),
  37 Rust-тестов ядра, fmt/clippy/tests моста и OpenMLS ↔ mls-rs.
- Пройдены два сквозных сценария Dart/Connect ↔ Go ↔ PostgreSQL; проверены
  ID после смены root и повторного шифрования при исключении устройства.
- Собраны Windows release и Android debug; CRC APK и 34 ELF для трёх ABI
  проверены. Изолированный Windows-стенд прошёл hot reload без ошибок.
  Android на устройстве и эмуляторе не запускался; релизный CI нового
  среза прошёл на всех целевых платформах. [Подробные результаты](../../../space-app/docs/MLS-MENTIONS.md).
