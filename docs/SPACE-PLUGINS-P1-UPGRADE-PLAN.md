# P1 / E01: план обновления и привязка свидетельств миграции

Статус на 2 ноября 2026 года: контракт и изолированный прототип проверены в GitHub CI на Linux, Windows и macOS. Этот подэтап принят; E01 в целом остаётся открытым. Продолжение [lifecycle](SPACE-PLUGINS-P1-LIFECYCLE.md) и [публичного API реестра](SPACE-PLUGINS-P1-REGISTRY-API.md). Исполнение миграций в PostgreSQL и переключение рабочих пакетов этим блоком не вводятся.

## Закрываемый пробел

Координатор lifecycle уже проверяет `PackageVerified`, `Compatible`, `GrantsApproved`, `BackupReady` и `MigrationReady`. Одних этих признаков недостаточно для интеграции: результат проверки другого пакета, старого поколения или иной резервной копии не должен разрешать текущий переход.

Кандидат `space.upgrade.p1` задаёт неизменяемый план и правила его сопоставления с результатами доверенного ядра. Материалы: [JSON Schema](extensions/p1/upgrade-plan.schema.json), [общий пример](extensions/p1/upgrade-plan.json), [эталон SHA-256](extensions/p1/upgrade-plan.sha256), пакет сервера `experiments/extensions/upgrade`. Схема проверяет форму; Go-прототип дополнительно проверяет связи полей и последовательность миграций.

## Что фиксирует план

| Поле | Значение |
| --- | --- |
| `version` | `space.upgrade.p1` |
| `space`, `installation` | Идентичность пространства и установки; ASCII ID до 64 символов |
| `generation`, `revision` | Поколение managed-оболочки и исходная ревизия lifecycle |
| `data_revision` | Ревизия исходных данных, включая допустимый ноль |
| `source`, `target` | Разные SHA-256 исходного и целевого пакетов |
| `grants` | SHA-256 точного согласованного набора разрешений |
| `checkpoint` | SHA-256 конкретной согласованной резервной копии |
| `schema_from`, `schema_to` | Исходная и целевая версии схемы, 1…65535 |
| `steps` | Упорядоченные ID, входная/выходная версия и SHA-256 каждого шага |

Не более 32 шагов. Каждый повышает схему ровно на один; пропуски, перестановки, повторяющиеся ID и несовпадение конечной версии запрещены. Для обновления только кода разрешён пустой список шагов при одинаковой схеме. Понижение схемы не считается обычным обновлением. Lifecycle-ревизия ограничена сверху значением 2147483644, чтобы оставалось место для начала и завершения; ревизия данных — точным целым JSON до 9007199254740991.

Согласованная копия создаётся до окончательного утверждения плана. Её хеш входит в план, а отдельное свидетельство ядра связывает копию с окончательным digest плана; архив не обязан заранее содержать собственный будущий digest. Замена копии требует нового плана и повторного подтверждения.

## Digest и строгий разбор

Digest вычисляется как SHA-256 от `space.upgrade.p1`, нулевого байта и нормализованного JSON. Поля идут в порядке таблицы выше, поля шага — `id`, `from`, `to`, `digest`; пробелов нет, порядок шагов сохраняется. Все строки ограничены ASCII-профилем, числа целые. Это явно заданный экспериментальный профиль, не общий алгоритм JCS.

Go и независимая Python-проверка сверяются с одним эталоном. Форматирование входного JSON не меняет digest. Разбор ограничен общим пределом P1 16 КиБ и отвергает повторяющиеся ключи, неизвестные/пропущенные поля, `null`, изменение регистра имён полей, нецелые числа и дополнительный JSON после документа. Регистр проверяется явно: стандартный Go-декодер сам допускает сопоставление имён без учёта регистра.

## Свидетельства и переходы

`Binding` — считанные ядром пространство, установка, поколение, исходные пакет/схема и ревизии. `Verification` — результат проверки подписи/доверия, совместимости и разрешений, привязанный к digest плана, целевому пакету и набору разрешений. `Checkpoint` подтверждает точную копию, исходный пакет, схему и ревизию данных. `Migration` подтверждает digest плана, ту же копию, целевые пакет/схему, хеш проверенного результата и успешную проверку результата.

Эти структуры предназначены только для доверенного адаптера Go. Они не являются криптографическими сертификатами или подписанными токенами; их поля нельзя принимать от клиента или WASM. Проверка реальных подписей, содержимого копии, полноты миграции и прав владельца выполняется внешними подсистемами. Этот блок проверяет соответствие свидетельств, а не истинность заявлений недоверенного отправителя.

`Begin` требует текущего разрешения владельца и точного совпадения исходной привязки с планом. После успешной проверки формируется наблюдение `begin_upgrade` для существующего координатора. Координатор отдельно требует `disabled`, ожидаемую ревизию и отсутствие фактически активных вызовов. Изменение плана, пакета, данных, разрешений, копии или поколения инвалидирует ранее полученные свидетельства.

`Finish` повторно проверяет пакет, совместимость, разрешения и копию; исходная привязка остаётся прежней до публикации, а lifecycle-ревизия должна быть на единицу больше. Результат миграции должен соответствовать целевым пакету/схеме и той же копии. Наблюдение `finish_upgrade` доступно только доверенному ядру. Координатор переводит установку из `upgrading` в `disabled`; автоматического включения нет. Повтор начала или завершения со старой ревизией отклоняется.

Проверка и применение наблюдения должны выполняться под общей границей сериализации адаптера. Нельзя сохранить наблюдение с готовыми boolean-полями и применить его позже после изменения пакета или прав. Атомарная публикация кода/данных, запись аудита и восстановление после сбоя требуют постоянного исполнителя; в этом прототипе их нет. Сам `Begin`/`Finish` не меняет реестр и не исполняет SQL.

## Следующая интеграция

Остаётся связать план с постоянным реестром: сохранить digest и этап, подготовить согласованную копию и проверенные артефакты, выполнить миграцию в изоляции с квотами, атомарно опубликовать результат и аудит. Нужны восстановление после перезапуска на каждой границе, отказ при потере подтверждения COMMIT и восстановление прежней копии без автоматического запуска старого бинарника на новой схеме.

Публичный API по-прежнему не принимает `begin_upgrade`, `finish_upgrade` или клиентские свидетельства. Git-установка, доверие издателю E04, архивы пакетов/миграций, рабочий установщик и весь E01 остаются открытыми.
