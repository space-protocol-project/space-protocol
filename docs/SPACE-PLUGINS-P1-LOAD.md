# Ограниченная нагрузочная приёмка P1

Дата: 11 ноября 2026. Нагрузочный подпункт E07 принят: полный CI 43005223189 успешен. Весь P1 этим не закрывается.

## Стенд и предел доказательства

Три независимых задания GitHub Linux CI, каждое с собственной PostgreSQL 17.11. В каждом задании три фазы по 300 секунд: 1, 2 и 8 конкурентных клиентов. Первые 60 секунд каждой фазы исключаются из распределений задержек. Клиенты используют один gRPC-канал и сессию владельца; перед фазой выполняется настоящий challenge/signature вход тем же устройством. Срок жизни сессии не увеличивается.

Ревизии фиксируются до запуска: server `31b626d8078541d941acb6e82aa1aca7cb3cdb98`, app `01558f35c1d704dcad286ca7f500d04343a4d604`, protocol `4df076de4033f37a64d80cb76ea31f4c36c6e2e0`. Приложение здесь не запускается: его SHA связывает кандидат с отдельной [нативной приёмкой форм](SPACE-PLUGINS-P1-FORMS.md). Расписание и набор данных — [закреплённый профиль сервера](https://github.com/space-protocol-project/space-server/blob/31b626d8078541d941acb6e82aa1aca7cb3cdb98/docs/P1-LOAD-PROFILE.md).

Проверяются query, уникальные мутации, повтор с прежним ключом, конфликты payload и ревизии, заранее отменённый запрос, отказ недопустимого эффекта и повтор команды независимого экземпляра. Отдельные проверки отзыва ACL/членства выполняются на собственном канале/экземпляре `revocation` во время каждой фазы. Наполненный до лимита экземпляр отклоняет новую команду, независимый экземпляр продолжает работу. Точные гонки отзыва и отмена уже исполняющегося вызова проверяются отдельными детерминированными тестами ядра.

Перед нагрузкой обязательный тест удерживает настоящую таблицу сессий после вызова расширения: ожидаются DeadlineExceeded без гостевого ответа и успешный свежий запрос после освобождения блокировки. Dispatcher сохраняет отмену/тайм-аут, не раскрывает детали ошибок и не ослабляет проверку прав. В нагрузке DeadlineExceeded разрешён только для query как исчерпание прежнего бюджета; он учитывается отдельно, не как успех. Для команд такой код остаётся ошибкой.

Настоящий WASM работает через ProcessHost с прежними лимитами 256 МиБ на worker, 512 МиБ суммарно и deadline 2 с. Проверяется старый доверенный mutation-binding, разрешающий собственные данные и событие `note_changed`; это не доказательство мутаций через новый полный manifest. Данные, квитанции и outbox не очищаются во время нагрузки.

Число процессов читается из `cgroup.procs` всей выделенной иерархии; это наблюдаемый снимок, а не атомарный счётчик. Общий `host.OSProcesses` на Linux не заполняется и не используется как доказательство. После нагрузки проверяются отсутствие PID и успешное закрытие/удаление групп.

RSS относится ко всему процессу тестового сервера, включая gRPC-клиентов, журнал измерений и инструментацию `-race`. Он не ограничен бюджетом worker. Ожидание пула и количество соединений, ожидающих SQL-блокировок, записываются отдельно; это не распределение длительностей SQL-блокировок. Значения памяти и задержек — профиль прототипа, не SLA и не сравнение со старыми RPC.

## Неуспешные и заменённые попытки

- `42993902053`: исходная сессия истекла на третьей фазе. Исправлено повторным настоящим входом перед фазой; TTL и база сессий не подменяются.
- `42996869228`: стенд ожидал stateless-команду от mutation-регистрации и проверял удаление группы хоста до `Close`. Исправлены ожидания и порядок проверки; обязательные отказы и очистка сохранены.
- `42995906937` и `42999868783` заменены окончательной версией стенда; не засчитываются. В окончательной версии неожиданный ответ останавливает нагрузку, а журнал сохраняется и при ошибке.

- `43000234510`: один runner зафиксировал предусмотренный отказ query владельца при смене ревизии ACL его канала между проверками допуска. Сравнение AccessStamp отклоняет такой ответ. Контроль отзыва перенесён на отдельный канал/экземпляр, чтобы проверять независимость основной нагрузки; PermissionDenied в её допустимые коды не добавлен. Остальные задания остановлены, результаты не приняты.

- `43001599705`: три предварительных прогона успешны; окончательный профиль дополнен прямым подсчётом PID.
- `43002228366`: два задания успешны, третье получило PermissionDenied при двухсекундном тайм-ауте query. Исправлена классификация отмены/тайм-аута авторизации; введён обязательный тест блокировки таблицы сессий. Этот workflow не принят.

Журналы неуспешных попыток хранятся отдельно от принятых результатов. Их нельзя усреднять вместе с успешными измерениями.
