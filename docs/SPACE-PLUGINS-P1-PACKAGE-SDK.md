# P1: подписанный пакет и четыре каркаса расширений

11 ноября 2026 года. Кандидат SDK — `space.sdk.p1.1`, исходная ревизия `space-server` — `4a1995f855b34b2077c8eb50fe940033a0840dcb`. Рабочие функции Чатов, Комнат, Обсуждений и Ленты ещё не перенесены; текущие данные остаются в ядре до P4/P5.

## Подписываемые байты и доверие

`index.json` содержит ровно `format: space.package.index.p1` и `files`: относительное имя → SHA-256 точных байтов файла. Ed25519 подписывает UTF-8 `space.package.index.p1`, один нулевой байт, затем точные байты `index.json`. Проверяющий сервис не пересобирает JSON перед проверкой. Изменение пробелов индекса тоже нарушает подпись. Отпечаток издателя — SHA-256 открытого ключа Ed25519. `index.sig` и `publisher.key` содержат base64 подписи и ключа.

Серверный ZIP содержит manifest, `server.wasm`, LICENSE, только объявленные схемы и три служебных файла индекса. Digest серверного артефакта — SHA-256 ZIP целиком. Клиентский Git-профиль использует тот же домен подписи индекса, но собственный набор файлов и `space.client.bundle.p1`; digest его сохранённого bundle не равен digest ZIP. Эти профили не взаимозаменяемы и не допускают молчаливого преобразования подписанных байтов. `server/client/hybrid` остаются различимыми целями; выполнение неподдержанного профиля запрещено.

Ключ из пакета не создаёт доверия. Проверка получает ожидаемый plugin ID и список разрешённых/отозванных отпечатков из актуальной доверенной конфигурации хозяина. Отзыв имеет приоритет над разрешением. Новый ключ при ротации требует отдельного явного подтверждения хозяином; подпись старым ключом или изменение Git-репозитория сами по себе не подтверждают новый. Старый ключ после отзыва не принимается даже при сохранении в списке разрешённых.

Прототип `GitTrust` клиента закрепляет сочетание локального профиля, репозитория, plugin ID и издателя в системном хранилище; неожиданная смена издателя отклоняется. Автоматическая ротация, публичный список отзыва, интерфейс смены доверия и откат версии доверенного хранилища не реализованы этим чистым проверяющим модулем. Их рабочий жизненный цикл относится к P3. Для P1 допускается только явное снабжение проверяющего процесса текущей доверенной конфигурацией; восстановленный пакет никогда не восстанавливает прежнее доверие автоматически.

## Архив и изоляция

ZIP ограничен 1 МиБ и 70 файлами; WASM — 64 КиБ, остальные файлы — 16 КиБ. Чтение распакованного содержимого ограничено до выделения неограниченной памяти. Абсолютные пути, `..`, ссылки, дубликаты, неизвестные файлы, несовпадение хешей, подписи, plugin ID и неподдержанный manifest отклоняются. Проверка ZIP не извлекает файлы на диск и не выполняет WASM. Валидация ABI и изолированный запуск — отдельный следующий шаг.

SDK сортирует ZIP-записи, использует фиксированные метаданные и Store; одинаковые входы и ключ дают одинаковые байты. Утилита `p1-sdk` принимает внешний seed либо явно указанный публичный тестовый ключ `-fixture`. Тестовый ключ не подходит для доверенной поставки и никогда не добавляется в рабочее хранилище автоматически. Проверка `p1-package-verify` требует внешний открытый ключ и ожидаемый plugin ID.

Исходный [CI SDK](https://github.com/space-protocol-project/space-server/actions/runs/42988914647) успешен: по 237 результатов тестов на Linux/Windows (включая родительские тесты и повторы), одинаковый ZIP между ОС, три исполнения настоящего WASM под Linux ProcessHost. Изолированная отрицательная матрица прошла 60 результатов; сохранённый после завершения transient-unit снимок systemd сбросил значения лимитов и **не является доказательством их действующих значений**. Дополнительная проверка изнутри процесса фиксируется отдельным итоговым CI, прежде чем закрывать E04.
