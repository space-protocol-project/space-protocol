# P1: согласованная копия и восстановление расширений

Продолжение [мутаций](SPACE-PLUGINS-P1-MUTATIONS.md) и [доставки outbox](SPACE-PLUGINS-P1-OUTBOX.md). Используются существующие пути домашнего сервера: физическая резервная копия и переносимый архив. Отдельного экспорта таблиц расширения нет. Рабочий сервер по-прежнему не включает экспериментальный исполнитель и обработчик outbox.

## Состав и точка согласованности

Обязательный набор P1: `extension_p1_meta`, `extension_p1_instances`, `extension_p1_data`, `extension_p1_receipts`, `extension_p1_outbox`. Если доставка была включена, вместе с ним сохраняется `extension_p1_delivery`: consumer, подтверждённый курсор, аренда, последний ACK и число попыток. Копируется вся БД с идентичностью пространства, principal, grants, членством и каналами, а не только пользовательские значения расширения.

Физический `CreateBackup` требует штатно остановленной PostgreSQL и копирует весь каталог данных с проверкой состояния остановки и SHA-256. Это уже включает все таблицы расширений; отдельного списка таблиц для копирования не добавляется. `ExportPortable` тоже требует остановленного сервера, временно запускает только локальную БД и создаёт полный согласованный `pg_dump`. Прежнее исключение содержимого `auth_sessions` сохраняется: после переносимого импорта нужен новый вход тем же зарегистрированным устройством.

Форматы физической копии и переносимого ZIP, основная версия PostgreSQL и схема ядра 46 не меняются. Копия старого пространства без таблиц расширений проходит проверку, а отсутствующие таблицы P1 не создаются. Хеш пакета и привязка instance сохраняются; сами WASM-пакеты и реестр установки пока не реализованы и не добавляются этим изменением в архив.

## Проверка перед публикацией восстановленного каталога

`CheckExtensionP1Backup` проверяет состояние в одной транзакции PostgreSQL. Таблицы блокируются в стабильном порядке. Наличие части обязательного набора, неизвестной таблицы P1 или неподдерживаемой версии запрещает восстановление. Дополнительная таблица delivery необязательна, поскольку её создаёт отдельный конструктор доставки.

Проверяются связи экземпляров с каналами, данных с экземплярами, квитанций с principal; ревизии и позиции outbox; соответствие ACK/аренды существующим событиям. Сохранённые protobuf-квитанции должны быть корректными результатами MUTATION, без replayed, с допустимой уникальной ревизией. В текущем P1 квитанции не удаляются: каждой ревизии экземпляра должна соответствовать одна квитанция. Будущая очистка потребует новой версии этого правила и совместимости копий.

При физическом `RestoreBackup` сначала проверяются исходный manifest и скопированные файлы. Затем во временном каталоге запускается только PostgreSQL, проверяется состояние расширений и отзываются временные аренды. БД останавливается даже при ошибке. После успешной остановки вычисляется новый manifest восстановленной копии, поскольку запуск PostgreSQL и отзыв аренд изменяют её файлы. Исходная копия остаётся неизменной. Только после проверок новый каталог публикуется; существующее назначение никогда не перезаписывается.

При `ImportPortable` dump восстанавливается одной транзакцией в новую БД. После проверки идентичности и версии выполняется та же проверка P1 и отзыв аренд, затем БД останавливается и каталог публикуется. `ExportPortable` выполняет проверку P1 без отзыва аренд источника перед dump. Прямое восстановление сторонними средствами PostgreSQL в обход этих путей требует явно выполнить проверку и отзыв аренд до запуска обработчиков.

Любая ошибка проверки откатывает отзыв аренд и запрещает публикацию назначения. Частичная физическая копия не считается пригодной только на основании наличия файлов: состояние БД проверяется до публикации. Проверка не является универсальным анализатором недоверенного SQL dump и не заменяет доверие к источнику архива.

## Семантика после восстановления

Данные, ревизия экземпляра, квитанции и уже подтверждённый курсор сохраняются. Повтор команды из копии возвращает прежний результат с replayed=true, без вызова гостевого кода. Проверка сессии и ACL при этом остаётся обязательной; переносимый архив не восстанавливает старые access token.

В новой восстановленной БД очищаются `lease_revision`, `lease_ordinal`, `lease_token`, `lease_until` и `last_ack_token`. Число попыток и подтверждённый курсор сохраняются. Поэтому старые token, включая token последнего ACK, не действуют в восстановленной копии. Подтверждённое событие не выдаётся повторно, а незавершённое выдаётся сразу с тем же event ID, новым token и следующим номером попытки. Обычное открытие Store эти поля не сбрасывает: отзыв выполняется только явным путём восстановления.

Новые события теперь получают случайный 256-битный ID, сохраняемый в той же транзакции, что данные и квитанция. Прежде ID вычислялся из installation/instance/revision/ordinal: после восстановления старой копии новая ветвь истории могла повторно использовать ревизию и ID ранее созданного события. Случайный ID устраняет эту коллизию. Уже сохранённые ID не переписываются — восстановление и повторная доставка остаются стабильными.

Восстановление возвращает состояние **на момент копии**. Команды и квитанции, созданные позднее, в ней отсутствуют; защита повторов не может восстановить утраченную историю. Внешние эффекты после момента копии не откатываются. Получатель по-прежнему обязан устойчиво дедуплицировать обработку по event ID; состояние внешнего получателя и правила его восстановления требуют отдельного согласования. Одновременный запуск исходного пространства и его восстановленного клона не является поддерживаемым режимом репликации.

## Приёмочные проверки

Настоящий домашний runtime создаёт командой три события. Первое подтверждается, второе остаётся арендованным, третье — ожидающим. Затем сервер и PostgreSQL останавливаются; создаётся и восстанавливается физическая копия либо переносимый архив. Проверяются:

- сохранение server ID, значений данных, ревизии, единственной квитанции и всех трёх событий;
- новый подписанный вход и повтор команды без исполнения гостя; сохранённый результат совпадает с исходным protobuf;
- отсутствие перенесённой сессии в portable-режиме;
- сохранение подтверждённого курсора, отказ старым token, новый token и следующий номер попытки для прежнего event ID; затем выдача третьего события;
- неизменность исходной физической копии;
- отклонение отсутствующей таблицы или квитанции, повреждённого protobuf, неверных ревизий outbox, неверного курсора и неизвестной таблицы; отказ не меняет аренду;
- отсутствие новых таблиц в старом пространстве; проверка источника не отзывает его аренду;
- отсутствие повторного использования event ID при моделировании отката состояния до команды. Реальное чтение/запись архивов проверяется отдельным home-тестом.

Гостевой план в этих сценариях фиксирован. Реальные WASM/worker проверяются общим P1 workflow отдельно. Сбой питания во время публикации, повреждение диска, online backup, внешние получатели, удаление instance и очистка квитанций остаются отдельными задачами.
