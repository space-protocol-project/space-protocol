# P1: строгий внутренний протокол worker

Продолжение от 30 октября 2026 года к [контрактам P1](SPACE-PLUGINS-P1.md), [Linux ProcessHost](SPACE-PLUGINS-P1-ISOLATION.md) и [Windows ProcessHost](SPACE-PLUGINS-P1-WINDOWS.md). Код находится в экспериментальном модуле `space-server/experiments/extensions`; рабочий сервер его не импортирует.

## Зачем отдельный контракт

До этого worker использовал стандартный Go JSON decoder с запретом неизвестных полей. Такая проверка не запрещала повторные ключи, регистронезависимые совпадения имён и `null` для флагов. Версия сообщения отсутствовала. Кроме того, проверка JSON запроса выполнялась после компиляции WASM. Теперь все проверки входного сообщения выполняются до создания runtime.

Это внутренний обмен доверенной оболочки с одноразовым процессом. Он не заменяет публичный ABI расширений, protobuf API или подписанный manifest. Путь к worker, его окружение, права и ограничения ОС по-прежнему задаёт оболочка.

## Формат запроса

stdin содержит ровно один UTF-8 JSON-объект, за которым допускаются только пробельные символы и EOF. Максимум — 128 КиБ, включая пробелы и base64. При превышении лимита чтение останавливается после контрольного байта. Длительность чтения и исполнения ограничивается внешним ProcessHost; самостоятельный запуск worker без него не обеспечивает процессную изоляцию.

Все пять полей обязательны. Лишние, повторные и иначе написанные имена запрещены; `null` недопустим.

| Поле | Тип и ограничение |
| --- | --- |
| `protocol` | Строка, строго `space.worker.p1` |
| `wasm` | Строка base64; после декодирования 1–65 536 байт; массив чисел не принимается |
| `request` | Строка base64 с UTF-8 JSON, 1–16 384 байт; сохраняются проверки глубины, повторных ключей и чисел |
| `interpreter` | JSON boolean; выбор движка для прототипа |
| `allow_wait` | JSON boolean; доступ только к диагностическому host call `wait` |

Флаги формирует доверенный вызывающий код. `allow_wait` не является пользовательским разрешением или моделью ACL. Неизвестная версия отвергается; старого запасного формата нет. Оболочка и worker должны поставляться совместно. Это не стабилизация ABI v1.

Проверки разделены: ограниченное чтение; синтаксис UTF-8 JSON и уникальность ключей; точный набор и форма полей; декодирование типов; версия; размер WASM; содержимое запроса. Только после них создаётся runtime и начинается компиляция. Публичный `CheckJSON` сохраняет прежний предел 16 КиБ: увеличенный предел доступен только внутреннему разбору сообщения.

## Ответ и ошибки

Успешный stdout содержит прежний JSON результата размером до 16 КиБ. Ошибка входного сообщения возвращается из `Worker` до записи результата; executable завершается с ненулевым кодом. ProcessHost сохраняет существующие ошибки процесса/квоты и не передаёт stderr расширению. Отдельный версионированный конверт ответа и публичный контракт ошибок здесь не вводятся.

## Проверки

- 16 отрицательных сценариев: повтор ключа, другой регистр, неизвестное/отсутствующее поле, `null` и неверный тип флага, неизвестная версия, второе JSON-значение, корневые `null`/массив, неверный UTF-8/base64, массив байтов вместо строки, пустой модуль, повреждённый JSON запроса и превышение общего размера.
- Каждый отрицательный вариант проверяется непосредственно парсером до компиляции и через Worker с отсутствием частичного ответа. Поэтому ошибка компиляции фиктивного модуля не может скрыть принятие повреждённого сообщения.
- Граничные размеры WASM и JSON принимаются; превышение каждого на один байт отклоняется.
- Настоящий echo WASM проходит полный обмен через Worker в compiler и interpreter.
- Общая матрица повторяет тесты, race detector, vet, mod verify и govulncheck на Linux, Windows и macOS. Отдельно повторяются ограничения cgroup Linux и Job Objects Windows.

## Оставшиеся границы

Этот шаг не закрывает macOS ProcessHost, изоляцию файлов/сети и прав, восстановление после смерти supervisor, интеграцию в рабочий сервер, SDK, полный API и доверие издателям. Общий P1 остаётся открытым.
