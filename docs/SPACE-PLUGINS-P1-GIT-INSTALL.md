# P1 — установка клиентского расширения из Git

Срез от 5 ноября 2026 года связывает проверку готового пакета с локальным реестром и экраном SpaceApp на `flutter_bloc`. Это ограниченный прототип установки, а не завершение E04/P3 или выпуск 0.9.0.

## Путь установки

В разделе «Мой доступ и устройства» пользователь открывает установку из Git, разблокирует локальный профиль и задаёт HTTPS URL публичного репозитория GitHub, полный commit либо `refs/heads/...` / `refs/tags/...`, каталог пакета и идентификатор установки.

`GitInstallCubit` получает неизменный кандидат: проверенные байты, манифест, источник, digest и отпечаток издателя. Экран показывает оба commit, запрошенный ref, путь, идентификатор и версию расширения, SHA-256 пакета, отпечаток ключа и требуемые возможности. Для нового ключа нужен отдельный, изначально снятый флажок доверия; для любого пакета — кнопка установки. Подпись удостоверяет владение ключом, но не безопасность кода и не личность автора.

Доверие ограничено локальным профилем устройства, репозиторием и идентификатором расширения. Запись хранится через `PlatformKeyStorage`. Смена ключа отклоняется; автоматического принятия нового издателя нет. Возможности из манифеста не превращаются в разрешения: установка создаёт выключенный экземпляр, а доступ к каталогу выдаётся отдельно через существующий экран согласия.

## Формат готового пакета

Профиль `prebuilt-client-p1` не выполняет сборку из исходников. В каталоге **commit A** лежат ровно шесть файлов:

| Файл | Назначение |
| --- | --- |
| `manifest.json` | Строгий `space.package-profile.p1`, профиль `client` |
| `client.wasm` | Модуль с ограниченной структурной проверкой |
| `LICENSE` | Текст лицензии, включённый в подписанный индекс |
| `index.json` | `space.package.index.p1`, SHA-256 трёх файлов выше |
| `index.sig` | Подпись Ed25519 в base64 |
| `publisher.key` | Открытый ключ Ed25519, 32 байта в base64 |

Подпись индекса покрывает UTF-8 `space.package.index.p1`, нулевой байт и **точные исходные байты** `index.json`. Изменение переводов строк меняет подпись; автор пакета должен закрепить байты в Git. Тестовая фикстура использует `-text` в родительском `.gitattributes`.

В **commit B**, на который разрешается пользовательский ref, в том же каталоге находится `provenance.json`. Оболочка содержит только `payload`, `signature`, `public_key` в base64. Подписанный JSON содержит `format: space.package.origin.p1`, `repository`, `commit: A`, `path`, `digest`, `build_profile: prebuilt-client-p1`. Подпись покрывает UTF-8 `space.package.origin.p1`, нулевой байт и точные байты payload. Ключ обязан совпасть с ключом индекса. Commit A и B раздельны: документ не пытается подписать хеш собственного содержащего его commit. Прямая связь parent не требуется; связь с A задаёт подписанный документ.

Digest вычисляется от UTF-8 JSON без пробелов, с порядком полей `format`, `index`, `signature`, `publisher`, `files`; `format` равен `space.client.bundle.p1`. Значения index/signature/publisher — base64 исходного индекса, подписи и ключа. `files` содержит base64 байтов `manifest.json`, `client.wasm`, `LICENSE` именно в таком порядке. Это формат кандидата P1, а не стабильный SDK.

Манифест допускает только `space.client.p1` / `space_client_p1`, `client.wasm`, известную схему данных, уникальные Windows/Linux/macOS с текущей ОС и пустые contributions. Возможности ограничены существующим контрактом чтения каталогов. Другие ABI, hybrid/server, неподдерживаемые возможности и UI contributions отклоняются. JSON проверяется на лишние и повторяющиеся поля, размер и глубину.

WASM проверяется по заголовку, ограничению размера, границам и порядку секций; непустые imports и start запрещены. **Полной валидации инструкций и исполнения гостя в этом срезе нет.** Хост жизненного цикла и файловый посредник уже работают, но не выполняют устанавливаемый модуль.

## Получение и доверенная запись

Транспорт обращается только к `api.github.com` через Git Database REST API. Он разрешает ref один раз, затем читает объекты по полным SHA-1; каждый blob повторно проверяется как Git-объект. Подписи и SHA-256 связывают фактические байты пакета с источником. Перемещение ветки после проверки не меняет уже показанный кандидат.

Нет запуска Git, shell, hooks, filters, внешних помощников, сборки или распаковки архивов. Ссылки, submodules, LFS pointers, `.gitmodules`, `.gitattributes` внутри выбранного каталога, коллизии имён и неожиданные файлы пакета отклоняются. Родительские каталоги просматриваются без рекурсивной загрузки всего репозитория.

URL не допускает credentials, query и fragment; перенаправления и прокси отключены. DNS ограничен публичными IPv4, соединение закрепляется за проверенным IP, TLS сохраняет штатную проверку CA и имени `api.github.com`. Ограничения: 24 запроса, 8 МиБ на ответ, 24 МиБ суммарно, 4 МиБ на blob, 2048 записей дерева, 20 секунд на запрос и двухминутный срок загрузки. Это намеренно ограничивает глубину пути; ошибки квот не обходятся неограниченными повторами.

Перед записью повторно проверяются локальная сессия, ревизия реестра и снимок доверия. `InstalledExtensionsCubit` последовательно выполняет согласие → запись пакета и защищённой квитанции → транзакцию установки. Хост ещё раз проверяет активность после асинхронной подготовки и перед commit. Закрытие экрана, отмена, истечение двухминутного окна согласия и блокировка профиля инвалидируют кандидат.

Источник хранится в защищённой квитанции принятия: repository, ref, ref_commit B, commit A, path, SHA-1 object format, метод, plugin и fingerprint. Реестр ссылается на digest пакета. После перезапуска владелец сверяет квитанцию, байты, схему и возможности; файл без квитанции не импортируется. Старые квитанции P1 без source поддерживаются. Уже принятый digest нельзя молча связать с другой квитанцией источника.

Согласие, файловая запись и системное хранилище не являются общей транзакцией. Отмена после записи доверия может оставить явно одобренный ключ; отмена после записи пакета — непривязанный файл/квитанцию. Это не создаёт установку и не даёт разрешений. Повторная попытка требует нового кандидата и подтверждения. Автоматическая очистка таких записей, управление доверием и ротация ключей — дальнейшая работа.

Предварительный [CI 42000343114](https://github.com/space-protocol-project/space-app/actions/runs/42000343114) прошёл на Windows/Linux, но остановился на macOS при первом обращении к GitHub до получения пакета. Прежняя диагностика объединяла отказ HTTP и неподдерживаемое кодирование ответа, поэтому точная причина этого ответа не установлена. В транспорт добавлены отдельные диагностические ошибки, а CI получил токен чтения, чтобы исключить зависимость от общего анонимного лимита. Это не ослабляет TLS, фиксацию источника, подписи или согласие. Замечания анализатора исправлены; неуспешные и отменённые прогоны не считаются итоговой приёмкой.

Unit/widget-сценарии проверяют согласие, неизменность кандидата, происхождение и подписи, сохранение после открытия реестра, разделение профилей, смену издателя, конфликт ревизии, блокировку/отмену во время записи, недопустимые URL, частные DNS-адреса и неподдерживаемые пакеты.

Нативный сценарий устанавливает приложение из Inno Setup / `.run` / DMG, получает тестовый пакет через настоящий публичный GitHub API, проверяет новое доверие и явное согласие, пишет в системное хранилище, перезапускает процесс и проверяет source. Затем выполняются выдача разрешения и чтение файла штатным файловым процессом, завершение с отменой активного чтения и отказ при повреждении пакета в третьем процессе. Аутентификация и выбор каталога в этом сценарии заменены фикстурами; их настоящие окна проверялись отдельными предыдущими срезами, не этим тестом.

Нативный CI передаёт штатный `GITHUB_TOKEN` с `contents: read` только тестовому транспорту. Он используется как Authorization исключительно для фиксированного `api.github.com`, не сохраняется в пакете, квитанции или отчётах. Обычный UI не читает токены из среды и делает публичные запросы без авторизации. Это отделяет приёмку от [общего анонимного лимита GitHub на IP](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api); управление credentials для приватных пользовательских источников этим не реализовано.

Пакет теста закреплён на `space-app@a17b181880f745d4b6e08cbc047565418c1087b6`, путь `client/test/fixtures/git-extension`. Генератор `tools/make_git_extension_fixture.py` использует **общедоступный синтетический ключ**, непригодный для настоящих расширений. Ключ не встроен в список доверенных: каждый изолированный CI-профиль начинает без доверия. Персональные данные и рабочие ключи не используются.

## Открытые границы

- Другие Git-хостинги, SSH, приватные репозитории и управляемая передача credentials.
- Сборка из исходников в изоляции, архивные/release-пакеты и стабильный формат SDK.
- Изолированный клиентский WASM-host с полноценной валидацией, исполнением, квотами и ABI; отображение библиотеки «Игры».
- Обновления установленных расширений, миграции, откат, отзыв и ротация ключей, интерфейс управления доверием.
- Android/iOS/Web, полноценный hybrid и UI contributions.
- Длительные нагрузки, независимая экспертиза и оставшиеся критерии E01–E07.

Этот результат не закрывает P1 целиком и не означает доступность функции в опубликованном выпуске приложения.

Основание транспорта: официальные [Git trees](https://docs.github.com/en/rest/git/trees) и [Git blobs](https://docs.github.com/en/rest/git/blobs). Пользовательский [HttpClient.connectionFactory](https://api.flutter.dev/flutter/dart-io/HttpClient/connectionFactory.html) требует явного создания TLS-сокета; в реализации используется `SecureSocket.secure` с именем исходного хоста.

Продолжение: [внутреннее исполнение установленного WASM с API каталогов](SPACE-PLUGINS-P1-CLIENT-WASM.md). Оно отдельно фиксирует границы платформ и проверку отзыва доступа; результаты этого отчёта по установке не подменяют приёмку исполнения.
