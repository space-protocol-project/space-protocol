# P1 — защищённый Linux-запуск клиентского WASM

Продолжение [первого клиентского исполнителя](SPACE-PLUGINS-P1-CLIENT-WASM.md). Подготовлена системная служба для Linux с systemd 254+ и cgroup v2. Срез принят 5 ноября 2026 года по полной матрице GitHub CI. Проверенный Linux-стенд — Ubuntu 24.04; другие дистрибутивы требуют отдельной приёмки.

## Путь исполнения

`SpaceCatalogRuntime` → `InstalledExtensionsCubit` → `ClientWasmBroker` → непривилегированный `space-client-wasm --serve` → `/run/space-client-wasm/control.sock` → системная служба → ProcessHost → worker UID/GID 65534.

Flutter, локальный профиль, Git-установщик и файловый посредник сохраняют обычный UID пользователя. Приложение не вызывает sudo/pkexec, не меняет права своего процесса и не получает запись в cgroup. Вспомогательный процесс соединяется только с фиксированным Unix-сокетом и проверяет корневой UID владельца соединения через SO_PEERCRED. Нет переменной окружения для подмены адреса службы.

Служба запускается systemd из фиксированного root-owned `/usr/libexec/space-client-wasm/space-client-wasm`. Socket activation передаёт единственный listening descriptor; служба проверяет LISTEN_PID/LISTEN_FDS, свой executable и делегированное расположение cgroup. Worker запускается только из этой административно установленной копии. Путь программы, UID, cgroup и параметры квот не поступают от клиента.

## Установка

Поставка Linux содержит `space-client-wasm`, его SHA-256 и каталог `linux-wasm` с двумя unit-файлами и установочным сценарием. Администратор отдельно выполняет:

```sh
sudo bash /path/to/Space/linux-wasm/install-system-service.sh /path/to/Space/space-client-wasm
```

Сценарий проверяет systemd 254+, cgroup v2 и контрольную сумму, копирует executable с владельцем root и правами 0755, устанавливает unit-файлы и включает socket. Контрольная сумма проверяет целостность выбранной поставки; она не заменяет проверку её происхождения администратором. Распаковка `.run` и запуск Flutter не устанавливают службу автоматически. Обновление приложения не заменяет root-owned копию: обновление службы остаётся отдельным административным действием. Автоматическое обновление остаётся открытым. [Двустороннее подтверждение версии транспорта и проверка ручной переустановки](SPACE-PLUGINS-P1-LINUX-PROTOCOL.md) добавлены следующим срезом.

Если службы нет или защищённый запуск недоступен, клиент отклоняет исполнение. Старый привилегированный стенд `SPACE_CLIENT_WASM_CGROUP` сохранён только для проверки ProcessHost; обычный клиент его не использует.

## Границы полномочий

Socket доступен локальным пользователям для ограниченных вычислений. Это не API выдачи прав на каталог. Служба не знает профиль, ключи, установки, root handles или разрешения Flutter; она не открывает пользовательские пути и не принимает команды ОС. Любой запрос с лишними полями отклоняется. Клиент может передать только WASM и ограниченный JSON. Все файловые операции по-прежнему выполняются в приложении с проверкой исходной сессии, экземпляра и разрешения.

Принимаемые приложением пакеты не имеют imports. При прямом вызове службы используется тот же ProcessHost с `allowWait=false`; WASI, файловые и сетевые API не подключаются. Проверка инструкций и компиляция происходят в отдельном worker, а не в root-службе. До запуска приложение повторно проверяет принятие и digest пакета. Прямой клиент Unix-сокета может отправить собственный модуль, но это не даёт ему доверия издателя в приложении или доступа к данным другого пользователя.

systemd задаёт PrivateNetwork, ProtectHome, ProtectSystem=strict, PrivateDevices, PrivateTmp, NoNewPrivileges и RestrictAddressFamilies=AF_UNIX. Корневой supervisor сохраняет только CAP_SETUID, CAP_SETGID и CAP_KILL. Worker имеет UID/GID 65534, пустые дополнительные группы и нулевые effective capabilities. Это усиливает границы процесса; не является доказательством отсутствия уязвимостей ядра или движка и не закрывает E03 целиком.

В systemd 255 при сочетании User=root и seccomp недостаточно включить CAP_SETUID только в CapabilityBoundingSet: служба сохраняет его также через AmbientCapabilities. После смены UID worker ядро очищает permitted/effective/ambient sets; все три проверяются CI. Это соответствует [порядку применения capabilities в systemd](https://github.com/systemd/systemd/blob/v255/src/core/exec-invoke.c). NoNewPrivileges остаётся включённым.

## Общие квоты и завершение

Один ProcessHost принадлежит всей службе и всем её клиентам. Он резервирует бюджет до запуска и освобождает его после reap и удаления cgroup.

| Граница | Лимит |
| --- | --- |
| Вся служба, включая supervisor | 640 МиБ, swap 0, 128 задач, 100% одного CPU |
| Все worker вместе | 512 МиБ, swap 0, 64 задачи, 100% одного CPU |
| Один worker | 256 МиБ, swap 0, 64 задачи, 100% одного CPU |
| Соединения службы | 4 одновременно; лишнее закрывается без ready |
| Соединение | 4 секунды, включая ожидание первого запроса |
| Клиентский транспорт | 5 секунд, вход 128 КиБ, выход 32 КиБ |

Сохраняются пределы первого исполнителя: 64 КиБ модуля, 16 КиБ JSON, до 8 шагов, 100 мс вызова WASM, 2 секунды компиляции/процесса и ограничение памяти гостя. Общие квоты ограничивают вредоносного локального клиента, но пока не обеспечивают справедливое распределение слотов между пользователями.

Отзыв доступа закрывает stdin клиентского процесса. Мост делает half-close Unix-соединения, служба отменяет контекст, ProcessHost завершает cgroup worker. Потеря клиента также закрывает соединение; поздний ответ дополнительно отклоняется арендой исходного разрешения в приложении. KillMode=control-group завершает всё дерево при остановке службы; Restart=on-failure позволяет восстановить службу после аварии. Работа со старым cgroup выполняется через существующую проверяемую очистку ProcessHost.

Для управления деревом используется [делегирование cgroup systemd](https://systemd.io/CGROUP_DELEGATION/): DelegateSubgroup помещает supervisor в отдельный лист, а служба включает memory/pids/cpu только в своём делегированном поддереве.

## Приёмка

Workflow `plugin-p1-client-wasm.yml` проверяет отсутствие службы, устанавливает её отдельным административным шагом на одноразовом runner и далее вызывает WASM под обычным UID. Проверяются реальное выполнение гостя, чтение через файловый посредник, отзыв во время чтения, EOF-отмена, ограничение соединений, отказ произвольной команды, аварийное завершение и повторный запуск службы. Инспекция через root используется только стендом для чтения фактических UID/capabilities, пространств имён и cgroup worker.

Отдельный привилегированный тест ProcessHost использует тестовый executable, который запрашивает и заполняет 512 МиБ. Он должен быть завершён ядром по лимиту worker; проверяются OOMKills, общий peak и освобождение резерва. Эта команда нагрузки не включена в производственный executable.

CPU и pids проверяются по фактическим значениям cgroup действующего worker; отдельная нагрузка до исчерпания pids и измерение CPU throttling этим стендом не выполняются. Бесконечный цикл WASM проверяет ограниченное завершение вызова. Лимит соединений проверяется попыткой открыть пятое соединение при четырёх занятых слотах.

Матрица также сохраняет регрессионные проверки Windows/macOS, анализ Flutter, COG, сборки Inno Setup / `.run` / DMG и три нативных запуска из установленного приложения. Нативный probe проверяет поставку; настоящее исполнение проверяется отдельными Flutter-тестами. Аутентификация и выбор каталога в установочном probe остаются фикстурами. macOS по-прежнему отклоняет исполнение до появления требуемого защищённого хоста.

Предварительные попытки не засчитываются. Временная трассировка системных вызовов удалена из окончательного workflow.

## Открыто

Дистрибутивы без подходящего systemd/cgroup v2, автоматическое обновление службы и поддержка нескольких версий транспорта, справедливые квоты по пользователям, стабильный SDK, UI запуска/библиотеки игр, мобильные платформы и защищённое исполнение macOS. P1 и выпуск 0.9.0 этим срезом не закрываются.

Обновление административно выбранной поставки описано отдельно: [журнал переключения и откат Linux-службы](SPACE-PLUGINS-P1-LINUX-UPDATE.md).
