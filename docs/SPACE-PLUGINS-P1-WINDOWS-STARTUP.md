# P1. Первый запуск Windows и разблокировка профиля

Срез от 5 ноября 2026 года продолжает [приёмку экрана разрешений](SPACE-PLUGINS-P1-CATALOG-GRANT-UI.md). Проверяется первое открытие окна SpaceApp и создание локального профиля без предварительного сворачивания, восстановления или переключения фокуса средствами CI.

## Причина и исправление

`Win32Window::SetChildContent` передавал фокус дочернему окну Flutter ещё до первого показа главного окна. В Flutter 3.47.8 `WindowsLifecycleManager::SetLifecycleState` запоминает состояние даже до подключения слушателя `flutter/lifecycle`. `BeginProcessingLifecycle` включает доставку будущих изменений, но не повторяет сохранённое состояние. Раннее событие фокуса могло оставить Dart без начального `resumed`. Локальная сессия правильно отказывала в разблокировке при неизвестном состоянии.

В Windows runner ранняя передача фокуса разрешена только для уже видимого активного окна. При обычном запуске фокус передаётся из `WM_ACTIVATE` после первого показа. Обработчик также перестал вызывать `SetFocus` для `WA_INACTIVE`. Состояние приложения по-прежнему поступает из событий Flutter. Неизвестное состояние не разрешает вход, возвращение фокуса само по себе не создаёт сессию.

Сопоставление с исходниками SDK — [WindowsLifecycleManager Flutter 3.47.8](https://github.com/flutter/flutter/blob/3.47.8/engine/src/flutter/shell/platform/windows/windows_lifecycle_manager.cc), [подключение слушателя в FlutterWindowsEngine](https://github.com/flutter/flutter/blob/3.47.8/engine/src/flutter/shell/platform/windows/flutter_windows_engine.cc).

## Сценарий GitHub CI

Из `catalog_native_dialog_ci.py` удалена вставка таймеров сворачивания и восстановления Windows. Рабочие исходники runner собираются без изменения начальной активации. Автоматизация нативной кнопки выбора папки сохранена для последующей проверки отзыва доступа.

Стенд `catalog_focus_probe.dart` ждёт реального `resumed` и появления SpaceApp. До первого ввода пароля он проверяет заблокированное состояние Cubit. Записывает начальные события жизненного цикла и отклоняет сценарий с `hidden` или `paused` до первого входа. Через рабочий диалог создаёт пароль в отдельном системном защищённом хранилище CI и получает первую сессию.

Затем выполняет полный прежний сценарий с настоящим системным окном выбора папки, потерей фокуса, отказом неверному паролю, новой сессией, согласием на каталог, чтением контрольного файла и окончательной блокировкой. Windows повторяет сценарий с тремя независимыми временными профилями. macOS проверяет регрессию прежнего сценария. Секреты и пользовательские данные в отчёт не попадают.
