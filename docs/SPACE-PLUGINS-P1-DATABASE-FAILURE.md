# P1: отказ PostgreSQL и неопределённый COMMIT

Продолжение [транзакционных мутаций](SPACE-PLUGINS-P1-MUTATIONS.md) и [аварии сервера/worker](SPACE-PLUGINS-P1-WORKER-CRASH.md). Этот стенд проверяет соединение executor → PostgreSQL и аварийное восстановление самой БД. Гостевой план фиксирован; Store, SQL-транзакции, сессии и gRPC настоящие.

## Точки отказа

| Сценарий | Внесённый отказ | Состояние перед повтором | Повтор команды |
| --- | --- | --- | --- |
| before_commit | Посредник принимает COMMIT от pgx, но закрывает соединение до передачи PostgreSQL | revision/data/receipts/outbox = 0/0/0/0 | План выполняется заново, replayed=false |
| after_commit | PostgreSQL возвращает CommandComplete COMMIT, посредник скрывает подтверждение и разрывает соединение | 1/1/1/1 | Выдаётся сохранённая квитанция, replayed=true, гостя повторно не вызывают |
| database_restart | Во время ожидания SQL-блокировки вставки outbox выделенный контейнер PostgreSQL получает SIGKILL | После восстановления БД — 0/0/0/0 | План выполняется заново |
| committed_restart | После скрытого CommandComplete COMMIT контейнер PostgreSQL получает SIGKILL | После восстановления БД — 1/1/1/1 | Сохранённая квитанция выдаётся без повторного гостевого вызова |

Посредник разбирает границы кадров незашифрованного PostgreSQL-протокола в тестовой сети CI. Отказ включается после гостевого вызова и выбирает соединение, отправившее SQL вставки в outbox. Это отличает COMMIT записи от COMMIT повторной проверки прав внутри dispatcher; подмена не затрагивает предварительное чтение квитанции. До COMMIT перехватывается Simple Query commit; после COMMIT — ответ CommandComplete COMMIT. Производственный драйвер, запросы executor и обработка ошибок не подменяются. Это реальный разрыв соединения сервер → БД, а не потеря ответа между клиентом и сервером.

Первый RPC должен завершиться Internal. SQL-тайм-аут или конфликт (DeadlineExceeded/Aborted) не принимаются за аварию соединения. Сохранённый результат определяется отдельным наблюдателем, который подключается напрямую к БД. Неопределённость существует для вызывающего сервера: при разрыве он не должен делать вывод об откате по одному отсутствию подтверждения.

## Перезапуск PostgreSQL

Аварийные проверки вынесены в отдельную задачу GitHub CI с собственным сервисным контейнером postgres:17.11 и фиксированным портом на отдельной виртуальной машине задачи. Разрушительное действие разрешено только при явном SPACE_P1_DATABASE_CONTAINER: проверяются полный ID контейнера, образ и совпадение опубликованного порта с URL тестовой БД. Остальные задачи workflow используют другой контейнер. В обычном наборе тестов без этого параметра сценарий пропускается.

Контейнер завершается SIGKILL с проверкой кода выхода 137, затем запускается на прежних данных. Стенд ждёт готовности БД и сохраняет журнал PostgreSQL. В сценарии database_restart SQL-барьер подтверждает, что транзакция дошла до записи outbox; после восстановления барьер удаляется. Штатные лимиты команды и SQL не увеличиваются.

## Проверка восстановления

Повтор проходит через прежний executor и его пул соединений с той же сессией, командой и ключом идемпотентности. После аварии БД первый повтор может снова получить Internal: стенд разрешает до девяти клиентских попыток с интервалом 100 мс только для этого кода и записывает фактическое число попыток. Другие ошибки не повторяются. Это проверка восстановления за ограниченное число попыток, а не гарантия успеха первого RPC сразу после готовности БД. Наблюдатель может обновить свой отдельный пул; пул executor вручную не сбрасывается. Проверяются единственные данные, ревизия, квитанция и событие, точное значение записи, содержимое protobuf ответа и неизменный ID события после сохранённого COMMIT. До сохранения гостевой план вызывается ровно дважды, после сохранения — один раз, включая все попытки восстановления. Дополнительные попытки не должны создавать лишних вызовов гостя или записей. После Logout прежняя сессия больше не получает квитанцию.

Тесты не моделируют потерю диска, нарушение гарантий fsync, переключение на реплику, сетевое разделение кластера или длительную смешанную нагрузку. Это Linux/PostgreSQL 17.11 в GitHub CI; новые результаты Windows/macOS и настоящего WASM именно при аварии БД не заявляются. Прежние проверки изолированного WASM остаются отдельной частью workflow. Рабочая регистрация экспериментального API не включается; P1 целиком не закрыт.

Автоматические повторы рабочего клиента этим изменением не добавляются. Internal сам по себе не доказывает отсутствие сохранённого результата; для восстановления используется прежний ключ идемпотентности. Политика клиентских повторов и классификация временных ошибок требуют отдельного контракта перед подключением рабочего транспорта.

## Подтверждённые результаты задачи database-faults

В задаче database-faults прогона 41094677716 успешно выполнены по пять before_commit, after_commit, database_restart и committed_restart: 20 конечных сценариев, 25 результатов вместе с родительскими тестами, без пропусков. Журнал PostgreSQL содержит десять автоматических восстановлений после аварийной остановки.

| Сценарий | Число попыток восстановления в пяти повторениях |
| --- | --- |
| before_commit | 1, 1, 1, 1, 1 |
| after_commit | 1, 1, 1, 1, 1 |
| database_restart | 1, 2, 2, 2, 2 |
| committed_restart | 2, 2, 2, 2, 2 |

Во всех сценариях итог — revision=1, data=1, receipts=1, outbox=1. После сохранённого COMMIT replayed=true и один гостевой вызов; до сохранения replayed=false и ровно два вызова. Отозванная сессия не получает квитанцию.

Предварительные испытания обнаружили ошибки самого стенда. В 41093788479 посредник выбирал COMMIT проверки прав, а динамический порт менялся после запуска контейнера; выбор уточнён по вставке outbox, порт закреплён. В 41094283064 корректные обрывы COMMIT уже проходили, но немедленный повтор после аварии БД мог вернуть Internal. Итоговый стенд проверяет ограниченные клиентские повторы с тем же ключом и фиксирует их число; успешный первый повтор после восстановления не заявляется. До этих прогонов также исправлена конфигурация workflow. Неуспешные предварительные результаты не входят в приёмку.
