# P1. Выдача разрешения на папку из SpaceApp

Срез P1 от 5 ноября 2026 года. Пользователь открывает «Мой доступ и устройства» → «Каталоги расширений», выбирает экземпляр и папку. После возврата из системного окна Space просит снова разблокировать профиль. Перед выдачей доступа экран показывает экземпляр, SHA-256 пакета и абсолютный путь. Кнопка «Включить расширение и разрешить чтение» подтверждает оба действия.

## Привязка к хосту

`SpaceApp` предоставляет дереву `SpaceCatalogRuntime` через `RepositoryProvider`. Владелец уже открытого `LocalLifecycleHost` регистрирует его методом `attach(session, host)` и при отключении вызывает `detach(host)`. Для совместного использования с установщиком объект можно передать в `SpaceApp.catalogRuntime`. Хост и экран используют сессии одного `LocalSessionCubit`. Экран показывает экземпляры текущего профиля в состояниях `enabled` и `disabled` с заявленной возможностью `device.catalog.read` и подключённым посредником выбора папок. У профиля без таких экземпляров отображается пустой список. Регистрация хоста, установка и проверка пакетов относятся к обязанностям владельца среды исполнения.

## Выбор, разблокировка и согласие

1. `CatalogGrantCubit` получает из хоста привязку текущей сессии, экземпляра, установки, пакета и ревизии реестра. До открытия системного окна он явно блокирует старую сессию. Обычная блокировка отзывает ранее выданные разрешения и переводит работающие экземпляры в отключённое состояние.
2. Выбранный корень закрепляется файловым процессом. На этом этапе он принадлежит незавершённому запросу. Таблица активных корней и разрешения реестра меняются только при успешной публикации. После выбора на проверку и согласие отводятся две минуты. Отмена и закрытие экрана освобождают корень.
3. Пользователь нажимает «Разблокировать». Рабочее окно пароля передаёт результат проверки в `LocalSessionCubit`. Для продолжения нужны новый объект сессии, та же область устройства и профиля, тот же локальный автор и тот же подключённый хост. Хост ожидает ровно один переход блокировки после сохранённой ревизии. Дополнительное изменение реестра требует нового выбора.
4. После явного согласия хост повторно проверяет пакет, его схему, запрошенные возможности и штатные подтверждения. Переходы `enable` и `grant` готовятся на одном частном снимке. Одна запись журнала публикует включённое состояние и разрешение. При отказе во второй проверке сохраняется отключённое состояние. Потеря сессии или смена хоста во время ожидания отменяет операцию. Действуют прежние правила выдачи байтов и завершения файлового процесса при отзыве. [Файловый адаптер P1](SPACE-PLUGINS-P1-CLIENT-CATALOG-FILES.md).

## Приёмка в GitHub CI

Workflow `plugin-p1-catalog-focus.yml` выполняет проверки Cubit, маршрута приложения и прежних контрактов, анализ Flutter и контроль сложности. Workflow собирает настольный стенд с рабочим `SpaceApp` для Windows и macOS. Стенд регистрирует синтетический экземпляр «games» с тестовой службой проверки пакета, использует системное защищённое хранилище с отдельным ключом CI, рабочее окно пароля и настоящий файловый процесс. Автоматизация заполняет поля и запускает действия Flutter программно.

Системный выбор выполняет настольный `file_selector`. В CI ему передаётся начальная синтетическая папка. Драйвер Windows управляет кнопкой настоящего `IFileDialog`, драйвер macOS использует XCUITest для кнопки внутри окна `NSOpenPanel`. Средства управления окнами добавляются в сборку стенда. В Windows перед началом сценария выполняется реальное сворачивание и восстановление окна с раздельными проходами цикла сообщений. Это обеспечивает исходное наблюдаемое состояние приложения. В macOS XCUITest переключает фокус на Finder и возвращает его приложению. Приёмка требует наблюдаемых событий Flutter `inactive` и `resumed`, отказа неверному паролю, новой сессии перед согласием и чтения контрольного файла только после согласия. Затем стенд блокирует профиль и ожидает завершения файлового процесса. Настройки временной login Keychain на macOS восстанавливаются после прогона.

## Дальнейшая работа

Рабочий установщик должен подключать хост установленных пакетов к `SpaceCatalogRuntime` и поставлять проверенный файловый процесс вместе с приложением. В плане остаются первичная активация окна Windows без предварительного переключения, вложенные каталоги, инвалидация снимков и внешний WASM ABI.
