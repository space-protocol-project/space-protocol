# P1 / E01: WASM-миграция и атомарная публикация пакета

Статус на 2 ноября 2026 года: подэтап принят в GitHub CI на Ubuntu 24.04 с PostgreSQL 17.11 и настоящим изолированным WASM-worker. Продолжение [постоянного журнала миграции](SPACE-PLUGINS-P1-UPGRADE-RECOVERY.md). Это явно включаемый прототип P1; текущие Чаты, Комнаты, Обсуждения и Лента на него не переключаются. E01 в целом остаётся открытым.

## Проверяемый профиль

Поддерживается первое обновление одной установки с одним instance и исходной схемой 1. План сохраняет неизменяемые digest пакетов, шагов, разрешений и копии. Целевой пакет содержит модуль и регистрацию dispatcher; в P1 его SHA-256 вычисляется по существующему профилю `mutationPackageHash` из модуля, manifest и отсортированных событий. SHA-256 каждого шага относится непосредственно к байтам WASM. Формат архива внешнего пакета этим профилем не определяется.

`PrepareWASMUpgrade` под проверкой сессии/ACL и блокировками БД сохраняет план, целевую регистрацию и модули миграций. Исходный документ собирается из настоящего `extension_p1_data`, а не принимается от клиента. Проверяются выключенное состояние, отсутствие активных вызовов, текущие пакет/поколение/ревизии, канал и доверенные свидетельства ядра. Артефакты сохраняются в `extension_p1_upgrade_artifacts` вместе с журналом; подготовленный результат остаётся отдельно от рабочих данных.

Текущий конструктор управляемой службы при открытии читает опубликованную регистрацию из БД. Он допускает конфигурацию с прежним либо целевым digest, но запрещает произвольную замену установки, instance или канала. Проверка привязок в транзакции открытия исключает применение регистрации, устаревшей во время чтения.

## Контракт данных и WASM-хост

[Схема](extensions/p1/migration-data.schema.json) и [общий пример](extensions/p1/migration-data.json) описывают документ `space.migration.data.p1`:

```json
{"version":"space.migration.data.p1","schema":1,"values":{"note":{"value":1}}}
```

Разрешены только `version`, `schema`, `values`. Версия схемы — целое 1…65535, не более 32 ключей вида `[a-z][a-z0-9_-]{0,63}`. Весь документ ограничен 16 КиБ и общими правилами JSON P1: UTF-8, ограничение вложенности, отсутствие дублирующихся ключей и хвостового документа. JSON Schema описывает форму; сервер дополнительно проверяет байтовые ограничения и точное совпадение входной/выходной версии с шагом плана. Пустой набор данных разрешён.

`ResumeWASMUpgrade` принимает именно `ProcessHost`, а не произвольную реализацию `Runtime`. Перед каждым шагом доверенный адаптер заново предоставляет свидетельства, затем сервер проверяет текущую сессию, ACL, поколение, ревизии и ожидаемый курсор. Модуль считывается из сохранённых артефактов и сверяется с digest шага. Гость получает только документ; он не выбирает таблицы, установку, SQL, сетевые адреса или пути файлов.

Используется существующий экспериментальный ABI `space_alloc` / `space_handle` / `space_free`. Компиляция и исполнение происходят в отдельном worker с системной изоляцией. Вызов не получает разрешения на диагностический `wait`, WASI, файловую систему или сеть. Действуют текущие квоты P1: модуль до 64 КиБ, linear memory до 4 страниц, общий бюджет хоста 512 МиБ, до двух workers по 256 МиБ, deadline гостя 100 мс и предел процесса 2 с. Операция ядра ограничена пятью секундами. Это существующие экспериментальные пределы, не будущий SLA SDK.

После успешного выполнения проверяются формат результата и целевая схема. Результат, курсор и запись шага фиксируются одной транзакцией; запись получает признак `wasm`, который устанавливает только закрытый путь изолированного исполнения. Старый доверенный Go-преобразователь остаётся для прежних опытов восстановления, но его результат не допускается к публикации.

## Атомарная публикация

`PublishUpgrade` — метод доверенного Go-ядра, новых RPC нет. Он требует актуальную сессию владельца, `space.manage`, управление каналом и свежие свидетельства пакета/копии. Перед записью проверяются полный курсор, все WASM-шаги, digest артефактов, схема результата и неизменность исходных данных относительно сохранённого снимка. Готовность результата не включает установку автоматически.

Один COMMIT выполняет следующие изменения:

1. Заменяет ключи и значения рабочего `extension_p1_data` результатом миграции.
2. Переключает `package_hash` instance и общий `binding_hash` установки на целевой пакет.
3. Добавляет событие `publish_upgrade` в постоянный аудит lifecycle и увеличивает его ревизию на единицу, сохраняя `disabled`.
4. Меняет поколение установки, чтобы прежняя оболочка больше не могла запускать старый пакет или фиксировать команды.
5. Меняет `history_id` команд пространства, чтобы прежние клиентские контексты и окна повторов не переносились на новый пакет автоматически.
6. Сохраняет признак публикации и SHA-256 результата в журнале миграции.

Квитанции команд, outbox и курсор доставки сохраняются. Миграция не выдаёт себя за новую прикладную команду и не создаёт квитанцию: ревизия данных остаётся прежней, история команд меняется отдельно. Следующая команда нового пакета продолжает счётчик ревизий. В сквозном тесте исходный пакет создаёт запись и событие, миграция меняет запись и добавляет ключ, а новый пакет выполняет следующую команду с сохранением прежних квитанций и outbox.

Старая оболочка закрывается после успешного либо неопределённого COMMIT. Новое открытие восстанавливает опубликованный пакет из БД и оставляет установку выключенной; включение требует отдельного авторизованного действия. Повтор `PublishUpgrade` с тем же digest после открытия новой оболочки проверяет опубликованное состояние и не создаёт второе событие аудита.

## Сбои и восстановление

| Сбой | Результат |
| --- | --- |
| WASM trap, цикл, некорректный JSON, неверная схема, попытка превышения памяти | Шаг не фиксируется; рабочие пакет и данные остаются исходными, квота worker освобождается |
| Подмена модуля или целевого пакета | Подготовка отклоняется по digest |
| Изменение исходных данных, отзыв доверия, недостаточные права | Публикация отклоняется |
| Конкурирующие публикации | Одна фиксация и одно событие аудита; устаревшая оболочка отсекается |
| Соединение оборвано до доставки COMMIT | Изменения пакета, данных и аудита откатываются вместе; после открытия можно повторить публикацию |
| COMMIT выполнен, ответ потерян | Новая оболочка видит опубликованный результат и не повторяет миграцию или аудит |
| Процесс завершён перед публикацией готовой миграции | Сохраняется готовый журнал и исходный пакет |
| Процесс завершён после публикации | Восстанавливаются новый пакет и новые данные; старое поколение не допускается |

Проверка резервных копий учитывает артефакты и опубликованное состояние, сопоставляет пакет, привязки, курсор, результат и журнал. Если после миграции ещё не было новых команд, рабочие данные дополнительно сравниваются с результатом публикации. После новых команд проверяется дальнейшая ревизия и обычная согласованность квитанций; исходный результат миграции сохраняется как история, а не навязывается новым данным.

## Оставшиеся границы E01

Это первый ограниченный профиль публикации P1: одна установка/instance, исходная схема 1, данные до 16 КиБ. Повторное обновление той же установки требует отдельной реализации истории планов и версий схем; текущий завершённый журнал не удаляется и не перезаписывается. Не вводятся произвольные SQL-миграции, установка из Git, проверка издателей E04, новые публичные RPC или автоматический фоновый установщик. Проверку подписей и содержимого согласованной копии по-прежнему выполняет доверенный адаптер ядра.

Отдельная приёмка этого подключения на Windows/macOS, перенос новых артефактов через ZIP и аварийное завершение самого PostgreSQL здесь не подтверждаются. Прототип не меняет рабочую схему текущих Чатов/Комнат/Обсуждений/Ленты и не является выпуском 0.9.0. E01 и P1 в целом остаются открытыми.
