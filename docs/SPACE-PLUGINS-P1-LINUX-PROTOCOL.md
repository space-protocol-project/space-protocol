# P1 — совместимость приложения и Linux-службы WASM

Продолжение [защищённого Linux-запуска](SPACE-PLUGINS-P1-LINUX-BROKER.md). Добавлено обязательное двустороннее подтверждение версии транспорта до передачи модуля. Принято 5 ноября 2026 года полной матрицей GitHub CI.

## Контракт

Служба и приложение используют фиксированный Unix-сокет, проверку root через SO_PEERCRED и прежние квоты. До привычного `ready` служба отправляет ровно такой канонический кадр:

```json
{"protocol":"space.client.wasm.linux.p1","version":1}
```

Кадр заканчивается LF. Клиент сверяет его и возвращает точно такой же кадр. Мост начинает читать stdin только после сверки приветствия и отправки подтверждения. Служба выдаёт `{"ready":true}` после проверки подтверждения; Flutter по-прежнему ждёт `ready` перед отправкой WASM. Обмен версиями не передаётся во Flutter: прежний контракт `ClientWasmProcess` сохранён.

Одна точная версия поддерживается намеренно: диапазоны, понижение версии и автоматический переход к неверсионированному транспорту отсутствуют. Лишние или повторные поля, другая версия, незавершённый и слишком длинный кадр отклоняются. Буфер кадра ограничен 512 байтами, действуют прежние deadlines соединения. Буферизованные байты после подтверждения не теряются: запрос читает тот же reader.

Версия относится к внутреннему транспорту приложения и службы. Она не заменяет версию WASM ABI, схему данных, версию установленного расширения, проверку издателя или идентичность локальной сессии. Совместимая версия транспорта не доказывает свежесть исполняемого файла; подпись/аттестация поставки и автоматическое обновление службы этим протоколом не вводятся.

## Переход с предыдущего прототипа

Предыдущая служба сразу отправляла `ready` и не имеет версии транспорта. Новый мост отклоняет её до передачи WASM. Прежний клиент не может передать запрос новой службе без подтверждения протокола; прежний Flutter также не принимает новое приветствие вместо `ready`.

Служба общая для локальных пользователей. При смене протокола нужно согласовать обновление их приложений; одновременная поддержка старого и нового транспорта пока отсутствует.

После обновления приложения администратор должен повторно установить службу из соответствующей поставки:

```sh
sudo bash /path/to/Space/linux-wasm/install-system-service.sh /path/to/Space/space-client-wasm
```

Flutter сам не вызывает sudo/pkexec. Установщик проверяет контрольную сумму до остановки службы; неверная поставка сохраняет работающий процесс. Совместимая повторная установка закрывает старые соединения, заменяет root-owned executable и unit-файлы, включает socket activation. Следующий запрос создаёт новый процесс службы. Локальный реестр, пакеты расширений и профиль не являются данными этой службы и не мигрируют данным сценарием.

Этот срез проверял ручную переустановку. Следующий срез добавляет [журнал обновления, проверку WASM и откат при сбое](SPACE-PLUGINS-P1-LINUX-UPDATE.md). Автоматическое получение новой службы, интерфейс диагностики несовместимости и поддержка нескольких версий транспорта ещё открыты.

## Проверки

- Go проверяет старый кадр, будущую версию, дополнительные/повторные поля, превышение длины, обрыв и пустой кадр; успешный двусторонний обмен, побайтовую доставку и сохранность буферизованного запроса.
- В Linux CI временная root-фикстура заменяет только endpoint остановленной службы. Новый непривилегированный мост получает старое, будущее, слишком длинное и оборванное приветствие. Он завершается с ошибкой, не выдаёт `ready`, фикстура не получает байтов WASM. Этот процесс не входит в поставку и ничего не исполняет.
- Настоящая новая служба отклоняет неверсионированный запрос и подтверждение будущей версии. После восстановления настоящей службы выполняется реальный WASM.
- Неверная контрольная сумма обновления не меняет MainPID и не ломает следующий вызов. Совместимая повторная установка закрывает старое соединение, меняет MainPID и сохраняет возможность выполнения. Проверяются root-владелец и права 0755 без setuid у установленного executable.
- Сохраняются проверенные сценарии изоляции, квот, OOM, отзыва доступа, перезапуска, мост из поставки, установочные пакеты и регрессия Windows/macOS. Настоящее macOS-исполнение остаётся закрытым.

Предыдущая служба моделируется её неверсионированным приветствием; настоящий старый executable не устанавливается. Проверка замены процесса использует повторную установку одной совместимой версии. Это не приёмка миграции между произвольными выпусками службы и не проверка автоматического отката.

При повторной приёмке исправлено окно гонки в нативном тестовом стенде macOS: файл готовности мог появиться до завершения записи PID. Теперь PID записывается с `flush` во временный файл, затем файл атомарно переименовывается. Проверка совпадения PID сохранена; при несовпадении журнал содержит ожидаемое и фактическое значение. Это изменение тестового стенда, а не механизма сессий приложения.
