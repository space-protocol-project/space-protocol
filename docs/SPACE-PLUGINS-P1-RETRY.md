# P1 / E02: кандидат правил ошибок и повторов

Статус: экспериментальный профиль space.retry.p1, первый ограниченный блок E01/E02. Это общий контракт решений для Go и Dart, не новый protobuf API и не подключённый автоматический повтор рабочего клиента. [Критерии E01–E07](SPACE-PLUGINS-P1-EXIT.md) остаются открытыми.

## Неопределённый результат

[Аварийные проверки PostgreSQL](SPACE-PLUGINS-P1-DATABASE-FAILURE.md) показали: Internal может означать как отсутствие записи, так и сохранённый COMMIT с потерянным подтверждением. После восстановления старому пулу иногда требовались две клиентские попытки. Клиент не должен создавать новый ключ только из-за ошибки или отсутствия ответа.

Политика возвращает action, unknown и delay_ms. unknown — сохраняемая неопределённость результата текущей серии попыток. После неоднозначного отказа она не снимается последующим PermissionDenied, истечением сессии, исчерпанием бюджета или отменой. Только проверенный успешный ответ на ту же команду подтверждает результат. Значение false при первом однозначном отказе не доказывает отсутствие результата старой серии с тем же ключом.

| Наблюдение доверенного транспорта | Решение |
| --- | --- |
| Проверенный OK на ту же команду | confirmed, unknown=false, включая ответ после локальной отмены: отмена не откатывает уже подтверждённую запись |
| Unknown, Internal, Unavailable, DeadlineExceeded, потеря транспорта TransportLost | unknown=true; ограниченный повтор неизменного запроса, только если выполнены условия ниже |
| DataLoss | stop, unknown=true; повреждение данных не доказывает откат, автоматического повтора нет |
| Canceled или локальная отмена | stop; Canceled считается неоднозначным; текущая неопределённость сохраняется, автоматического возобновления нет |
| Unauthenticated | reauthenticate; это действие оболочки, не автоматический вход и не отправка команды; предыдущая неопределённость сохраняется |
| InvalidArgument, NotFound, AlreadyExists, PermissionDenied, ResourceExhausted, FailedPrecondition, Aborted, OutOfRange, Unimplemented | stop; предыдущая неопределённость сохраняется; конфликт ревизии не исправляется автоматически новой ревизией или ключом |
| Неизвестный код, некорректные локальные параметры или изменившаяся привязка запроса | stop, unknown=true |

Коды gRPC передаются политике нормализованными именами; TransportLost — локальное наблюдение транспорта. Строка message и прежний экспериментальный retryable из UI error-схемы не управляют повтором. Политика не разбирает сообщения SQL, не раскрывает внутренние ошибки и не меняет серверное отображение ошибок.

## Неизменный запрос и бюджеты

Политика применяется только к MUTATION с непустым ключом, которую доверенный транспорт предварительно проверил. SameRequest означает совпадение неизменяемого снимка: сервер/пространство, установка/экземпляр, principal, команда, effect, ключ, expected_state_revision и точные байты payload. Изменение пользователя, назначения, данных, ревизии или ключа останавливает серию. Новый токен того же principal допустим только после явного восстановления сессии и повторной проверки привязки; он не выдаёт новых прав на старую квитанцию.

Не более четырёх попыток, включая первую. После ошибок попыток 1/2/3 задержки равны 250/500/1000 мс; после четвёртой повтор запрещён. Общий бюджет — 30 секунд по монотонным часам; перед повтором резервируются задержка и полные 5 секунд следующего RPC. Серверные бюджеты SQL, WASM и команды не увеличиваются. Это детерминированный профиль прототипа, не фоновая очередь и не политика повторов всего Space.

Дополнительно требуется известное доверенному клиенту оставшееся окно повторной выдачи квитанции. Оно должно вмещать задержку и пять секунд RPC. При неизвестном или истёкшем окне — stop с сохранением неопределённости; клиент не пробует тот же эффект под новым ключом. RPC сверки теперь содержит поля окна, но сервер возвращает false/0: доверенное окно ещё не реализовано. Интеграция должна дополнить жизненный цикл квитанции, а не подставить 30 суток или бесконечность по умолчанию. Целевой срок хранения из спецификации не является доказательством оставшегося времени конкретной квитанции после восстановления копии.

Истечение бюджета прекращает автоматические попытки, но не объявляет откат. Для ручного восстановления нужны прежний снимок команды, проверка сессии/прав и согласованный способ сверки состояния. Отмена между ожиданием и отправкой проверяется повторно будущим исполнителем; данная чистая функция не управляет таймерами или сетью.

## Реализация и проверяемые границы

В space-server добавлена отдельно используемая DecideRetry, в space-app — чистая decideExtensionRetry. Обе возвращают решение по доверенному наблюдению; они не регистрируются в рабочем RPC, не отправляют запросы, не сохраняют ключи и не вычисляют SameRequest. Последние обязанности принадлежат будущему клиентскому исполнителю в Bloc/Cubit.

Канонические [40 сценариев](extensions/p1/retry.json) и их [схема](extensions/p1/retry.schema.json) проверяют все коды, сохранение неопределённости, отмену, смену запроса, неизвестное окно, четыре попытки, точные границы бюджета/окна и ошибочные параметры. Файлы Go/Dart сравниваются с канонической копией на явно закреплённой ревизии space-protocol в CI. Дополнительный последовательный тест проверяет потерю транспорта → отказ доступа; Go также проверяет последующее разрешение неопределённости успешным ответом.

Это проверка общего алгоритма принятия решения. Она не доказывает фактическую неизменность сетевых байтов, устойчивость очереди к перезапуску клиента, соблюдение таймеров транспортом или отмену настоящего RPC. Сквозной прототип исполнителя с этими гарантиями остаётся обязательной частью E02.

## Следующий блок E01/E02

- Добавить в API проверяемые метаданные окна квитанции и способ сверки неопределённой команды без раскрытия данных после отзыва прав; определить поведение tombstone после удаления полного ответа.
- Реализовать клиентский исполнитель, который замораживает запрос/привязку, хранит ключ, применяет решения политики и проверяет отмену/смену пользователя перед каждой отправкой.
- Проверить его на настоящем RPC с потерей ответа и неопределённым COMMIT, истечением окна и восстановлением сессии; не подменять эту приёмку таблицами решений.
- Завершить остальные контракты E01/E02: manifest, реестр, contributions/lifecycle, доставка, дедупликация и правила хранения/очистки. Настоящий документ их не закрывает.
