# Карта перехода четырёх функций Space на расширения

Статическая инвентаризация P0 от 29 октября 2026 года. Основание — [спецификация](SPACE-PLUGINS.md), текущие исходники трёх репозиториев и существующие отчёты выпусков. [Воспроизводимый каталог](SPACE-PLUGINS-P0-INVENTORY.md) содержит все 116 RPC контрактов, все 46 SQL-миграций, создаваемые/изменяемые таблицы и индексы, а также файлы реализации и проверок с постоянными ссылками на commit.

Исходные ревизии: приложение `35b0a9e73666f9d91d650a5b23e75da1441539bf`, сервер `78303322c4d99475fafcc6c03cca84aa58462764`, протокол `ba4f7336add2db3d6b379ea3d8ad2c1df8515713`. Незакоммиченные изменения voice bindings приложения и `connect_assets.go` сервера не включены в снимок и не изменялись. Обновление каталога: `python tools/inventory_plugins.py` из space-protocol.

## Готовность к началу

Начинать P0 и проектирование P1 можно. Документация системы и Git-установки уже есть; runtime, SDK, реестр и рендерер расширений ещё не реализованы. Завершение документации не означает готовность публичной установки или переноса рабочих данных.

По текущему TODO опубликованы приложение 0.8.1 и runtime 0.8.0 со схемой 46. Исправление аварийного восстановления macOS находится в main и ещё не выпущено; отдельная проверка завершения Android-процесса во время переноса остаётся открытой. Независимая экспертиза и физическая приёмка исключены из обязательного объёма 0.8.0 решением пользователя, но не считаются выполненными. Публикация и CI здесь повторно не проверялись. Эти границы не блокируют инвентаризацию, но сохраняются перед переносом данных и заявлением готовности 0.9.0.

В этой работе зафиксированы состав переноса, правила сохранения ID и исходные сценарии. Измерения p95/памяти, прогон миграций и выполнение сценариев не проводились. P0 остаётся открытым в части измеренного исходного уровня; карту можно использовать для начала P1.

## Отдельные репозитории официальных расширений

По указанию пользователя каждую из четырёх функций переносим в отдельный репозиторий организации проекта. Предлагаемые имена ниже являются планом, существование репозиториев не заявляется.

| Репозиторий | ID пакета | Прикладная ответственность |
| --- | --- | --- |
| `space-extension-chat` | `space.chat` | Обычная переписка, действия над сообщениями, страницы и обзор чата |
| `space-extension-rooms` | `space.rooms` | Сущности комнат, политика входа и вместимости, страницы и обзор |
| `space-extension-discussions` | `space.discussions` | Темы/ответы, чтение, закрепление, модерация и жалобы |
| `space-extension-feed` | `space.feed` | Публикации/комментарии, репосты, персональная хронология и её UI |

Каждый репозиторий содержит manifest, исходники WASM, схемы команд/данных, декларации UI и обзора, локализации, миграции, тесты, лицензию, историю изменений и CI упаковки. Пакет выпускается независимо от клиента/runtime и закрепляет поддерживаемые версии host/ABI/UI. Для установки из Git CI сохраняет готовый подписанный пакет в отдельной ветке/каталоге; commit, digest и происхождение фиксируются. Исходники не компилируются скриптами на рабочем сервере.

Создание репозиториев входит в P1 после определения минимальной структуры SDK; наполнение реальной логикой идёт в P4/P5. В P2 существующий Go/Dart-код остаётся в текущих репозиториях за встроенными адаптерами. Переименование каталога или копирование кода в новый репозиторий само по себе не считается переносом функции.

Общие контракты принадлежат space-protocol; runtime и host services — space-server; оболочка, доверенные компоненты, ключи и устройства — space-app. Общий SDK версионируется один раз, не копируется в четыре репозитория. Решение о его отдельном репозитории принимается в P1. Официальные расширения не получают скрытых API по префиксу `space.*`.

## Обнаруженные расхождения между целью и текущей реализацией

| Факт в исходниках | Последствие для перехода |
| --- | --- |
| `channels.view_type` — одна строка; `scanChannel` в `channels.go` строит один `View{Id: kind, Type: kind}` | `repeated View` в protobuf не означает реализованную многовидовую БД; первый backfill создаёт ровно один instance для существующего channel/view |
| `events.go` соединяет журнал `events` с `contents`; события `content.created/updated/deleted` публикуются при изменениях чата | Нельзя объявить этот журнал универсальным replay расширений; нужен отдельный контракт и совместимый мост |
| `forum.dart` и `feed.dart` используют опрос с интервалом 10 секунд | Нельзя считать realtime-события тем/публикаций уже готовыми; P2 сохраняет polling, P3 добавляет общий журнал |
| `ChatHistory.favorites` — локальный набор; community favorites хранятся на сервере | Унификация не должна случайно публиковать личное избранное чата или лишать форум межустройственной синхронизации |
| В ForumService/FeedService нет RPC произвольного редактирования текста автором | Редактирование нельзя записывать в список уже выпущенных функций этих двух разделов; модерация и revision не равны редактированию |
| `ForumState` имеет ручное копирование; FeedState использует Freezed | При новом адаптере привести повторяющееся состояние к принятому подходу, не делать массовый рефакторинг в P0 |
| Активные комнаты хранятся в `internal/voice/rooms.go`, а не таблице участников комнат | Не мигрировать живые SDP/session/audio slots как постоянные данные пакета |
| Общие поиск, экспорт, assets и персональная лента обращаются к конкретным таблицам | Перенос «только forum.go/feed.go» сломает другие функции; нужны провайдеры и единый источник записи |

Исходники перечислены с точными путями и ревизиями в каталоге; ниже пути сервера относятся к space-server, клиента — к space-app. Группы `prefix_*` обозначают семейства файлов, раскрытые в каталоге, а не предложение переносить все файлы целиком.

История ограничена 14 днями и 4 МиБ в текущем коде; избранное влияет на очистку. Outbox имеет пределы 100 записей и 1 МиБ, а его область включает grant. Эти числа — исходное поведение, не квоты будущего WASM. Нельзя переносом сменить principal/grant либо повторно отправить уже принятую mutation.

Для MLS сохраняются `mls_group_id`, маршруты устройств, envelopes, sequence/epoch и клиентское защищённое состояние. Серверный пакет не получает открытый текст, ключи и локальный поиск. Текущий глобальный серверный поиск и пользовательский экспорт не включают MLS. Архивирование истории и восстановление рабочего ratchet проверяются раздельно.

Минимальная регрессия: отправка и повтор после обрыва; очередь с вложением и изменением сообщения; ответы/реакции/удаление; возврат истории по страницам; локальное избранное и черновик после рестарта; отзыв доступа в активной подписке; MLS на двух устройствах и после восстановления. Тестовые опоры: серверные `content_*`, `mls_*`, `chat_mentions*`, клиентские `chat*`, `outbox*`, `mls*`, `history*` из каталога.

Сохранить лимит 2–32, значение 8 по умолчанию, audio_slot 0–31, mute/deafen и действующие проверки старых клиентов. Heartbeat клиента по умолчанию 3 секунды; signaling timeout 15 секунд и connection timeout 45 секунд — исходные настройки, которые нельзя незаметно заменить бюджетом обычного WASM-вызова в 2 секунды. Управление комнатой вызывает медиаслужбу, а не держит WASM-вызов на всё время разговора.

Выключение пакета и обновление должны иметь явную политику новых входов и текущих разговоров. Данные участников активной комнаты нельзя восстанавливать как действительные билеты после рестарта. Регрессия: два клиента, восстановление сети, TURN, лимит, освобождение slot, отключение участника при отзыве прав, PTT и перенос настроек. Серверные `internal/voice/*_test.go`, `postgres/voice*_test.go`, клиентские `voice*` и платформенные стенды проверяют разные уровни; транспортные тесты не заменяют акустическую приёмку.

Обязательны отдельные разрешения чтения/записи/управления и скрытие личности заявителя от модератора. Сохранить ключи идемпотентности автора в канале, уникальность sequence и связи вложений с темой/ответом. Персональные read state, mentions, favorites и реакции нельзя объединить с публичным объектом темы.

Список тем учитывает закрепление; ответы имеют собственную последовательность. Переход к ответу через поиск/уведомление/обзор должен сохранить эту координату. Счётчик жалоб в обзоре требует права модерации. Существующий polling темы сохраняется до внедрения нового журнала событий. Устойчивое хранение черновика форума между перезапусками не заявляется как подтверждённый аналог SavedDrafts чата; новые требования к нему выделяются отдельно.

Регрессия: создание/повтор, ответы и страницы, pin/close/read, вложения, реакции/избранное, mentions, модерация и приватность жалоб, поиск и прямой переход после скрытия родителя. Опоры: `postgres/forum*_test.go`, `community_*_test.go`, клиентские `forum*`, `community*`, снимки и стенды в документации. Авторское редактирование текста не входит в подтверждённый RPC-паритет.

Репост связан с оригиналом в том же канале; ответ на комментарий связан с тем же post и предшествующим sequence. Разрешение загрузки вложения учитывает эти права.

Личные подписки имеют собственные версии и проверку текущей видимости источников. Отписка и скрытие автора/оригинала не должны оставлять доступные старые карточки из общего кеша. Состояние незавершённой отправки и request key из FeedController сохраняется при переключении UI; долгоживущая дисковая очередь как у ChatOutbox для ленты не подтверждена и не включается в паритет автоматически.

Регрессия: публикация/повтор, комментарии и ответы, репост/цитирование, раздельные publish/comment, read, жалобы/модерация, подписки/персональная лента, удаление доступа к оригиналу, экспорт. Опоры: `postgres/feed*_test.go`, `participant_follows*_test.go`, `community*`, `user_export_test.go`, клиентские `feed*` и `participant_follow*` из каталога.

В `assets` существуют отдельные связи content_id, mls_sequence, forum_thread_id, forum_reply_id, feed_post_id, feed_comment_id и ограничение единственного владельца. Это явная точка будущей схемы ссылок на объекты расширений; удалять внешние ключи до работающего эквивалента целостности нельзя.

SQL-каталог включает все CREATE/ALTER/DROP и индексы миграций 001–046. Помимо названий таблиц при переносе обязательны CHECK, UNIQUE, FK, каскады и collation курсоров. Первичные/уникальные ограничения внутри CREATE TABLE видны в полном SQL по ссылкам; таблица индексов не заменяет их. Новые схемы и номера миграций здесь не назначаются.

## События и фоновые операции

| Механизм | Исходное поведение | Действие при переносе |
| --- | --- | --- |
| Chat events | `store.go` создаёт content.created; `content_changes.go` — updated/deleted; ListEvents читает текущее содержимое по JOIN | Не обещать неизменяемый снимок payload старого события; сохранить cursor/sequence и новый журнал определить отдельно |
| Subscribe | `subscribe.go` использует polling 500 мс, ограниченные stream slots | Общая служба replay, повторная проверка ACL, обратное давление |
| WatchChannels | `channel_watch.go`, polling 500 мс | Реестр разделов должен выдавать совместимый поток изменений |
| Forum/Feed refresh | UI timer 10 секунд и обновление после действия | На P2 оставить поведение; перенос таймеров/подписок в общий lifecycle и Cubit — отдельная работа |
| Voice | Heartbeat/recovery клиента, media timers сервера | Не переносить в универсальный scheduler плагинов без медийных гарантий |
| Push | Регистрация, poll, batch/ack в `push_http.go`, отдельная очередь | Это не готовый универсальный outbox; определить атомарность событий и уведомлений нового API |
| Очистка | `root_retention.go`, `retention_devices.go`, миграционные удаления, asset lifetime | Сохранять порядок ссылок/отзыва, назначение каждой очистки; не выдавать root retention за retention содержимого |
| Резервные копии | `internal/home/scheduled_backups.go`, `scheduled_archives.go`, backup policy | Добавить сохранение пакетов, mapping и схем к общему snapshot |
| Клиент | ChatHistory.prune, последовательные SavedDrafts, outbox retry и locks, personal notification delivery | Сохранять scope и отменять старые задачи при смене principal/instance |

Готового общего планировщика jobs, event bus для всех четырёх функций и транзакционного plugin outbox в текущем коде не установлено. Они остаются задачами P3. Прототипы не должны подменять очереди чата или работающий голос.

## Идентификаторы и план первого backfill

1. Ядро создаёт installation официального пакета для каждого существующего типа, встреченного в channels. Пустое новое пространство может не иметь ни одного пакета; текущая миграция 001 создаёт `general`, поэтому новый режим пустого пространства требует отдельного изменения bootstrap.
2. На существующей схеме `view.id = view.type = channels.view_type`. Для каждого channel создаётся одна запись mapping `(space_id, channel_id, legacy_view_id) → instance_id`; UNIQUE этой тройки делает повтор безопасным. Type chat с MLS не меняет группу и не становится незашифрованным каналом.
3. instance_id выделяется один раз и сохраняется в БД. Название канала, положение, адрес сервера и версия пакета на него не влияют. Старые ID содержимого не заменяются.
4. Полная новая ссылка включает space identity, instance, kind, object ID и координату ответа. Legacy lookup разрешает channel/type/ID в тот же объект; ACL проверяется после разрешения ссылки и перед выдачей содержимого.
5. Данные личного чтения, избранного, mentions и курсоров сохраняют principal/device/grant scope. Нельзя заменить его одним instance_id. Для клиентских ключей переход читается из versioned mapping, с checkpoint и возможностью повторного запуска.
6. P2 вводит только registry/mapping и adapters. Таблицы предметных данных и writer остаются прежними. Перенос физического хранения и переключение единственного writer принадлежат P4/P5, после проверки восстановленной копии.

Ни один из четырёх новых репозиториев не получает историю пользователей или рабочие базы. В них переносятся исходники, схемы, fixtures без личных данных, UI, миграции и контрактные тесты. Сохранение Git-истории кода и лицензий планируется при фактическом выделении; уничтожение старых исходников не является частью P0.

Состав стенда для исходных измерений: зафиксированные SHA, одинаковые ОС/CPU/RAM/PostgreSQL, три повторных прогона после прогрева, наборы 1 000 и 10 000 объектов на раздел, отдельный principal с ограниченными правами. Измерять p50/p95 запросов истории, темы, поста, поиска и обзора, время write+видимость, память клиента/runtime, число SQL-запросов и размер backup. Для голоса — отдельные задержка подключения, потери/переподключение, сеть/TURN и реальный звук; его нельзя оценить только p95 обычного RPC.

Fixtures включают пустой/архивный раздел, tombstones/hidden, большие вложения на действующей границе, одновременно активные экземпляры, повтор request ID и отзыв ACL. Отчёт должен содержать точные параметры и сырые результаты, а не только итог «пройдено». Цель не более 20% ухудшения p95 из спецификации проверяется на одном и том же стенде. Эти измерения и B01–B10 ещё не выполнены в рамках P0; запускать через GitHub CI согласно действующему порядку проекта.
