# P1 / E02: клиентский журнал и неопределённый COMMIT PostgreSQL

Статус на 1 ноября 2026 года: совместная приёмка Linux/PostgreSQL завершена успешно в GitHub CI. Продолжение [нативного восстановления Linux](SPACE-PLUGINS-P1-COMMAND-RECOVERY.md) и [отказов PostgreSQL](SPACE-PLUGINS-P1-DATABASE-FAILURE.md). Этот блок проверяет их совместное поведение; весь E02/P1 остаётся открытым.

## Что проверяется

Настоящий Flutter Linux сохраняет неизменный protobuf-снимок команды в `PlatformKeyStorage` через Secret Service. Запрос проходит Connect-мост, настоящий gRPC, сессию/ACL и исполнитель транзакционных мутаций PostgreSQL. Как в прежнем аварийном стенде, гостевой обработчик заменён детерминированным планом со счётчиком; изоляция WASM этим прогоном не проверяется заново.

Тестовый посредник между исполнителем и PostgreSQL выбирает транзакцию по вставке outbox. Он обрывает соединение в одной из двух точек:

| Точка отказа | Доказательство посредника | Ожидаемое состояние после восстановления |
| --- | --- | --- |
| До передачи COMMIT PostgreSQL | `COMMIT not forwarded` | revision/data/receipts/outbox = 0/0/0/0; сверка UNKNOWN, клиент сохраняет неопределённость |
| После ответа PostgreSQL о COMMIT | `CommandComplete COMMIT withheld` | 1/1/1/1; сверка CONFIRMED, единственное событие сохраняет свой ID |

Сервер в обоих случаях обязан получить `Internal`; тайм-аут, конфликт или обычный успешный ответ не принимаются за неопределённый COMMIT. Connect-мост удерживает этот результат до остановки клиента. Таким образом, клиент аварийно завершается до получения ответа и до начала автоматического повтора. Доставка `Internal` работающему клиенту проверяется отдельной политикой повторов; здесь не утверждается её нативная приёмка при аварии БД.

Контроллер подтверждает SIGKILL группы клиента вместе с Secret Service, затем завершает SIGKILL выделенный контейнер PostgreSQL и запускает его на прежних данных. Используется прежняя проверка полного ID, образа и порта контейнера; требуется явный `SPACE_P1_DATABASE_CONTAINER`. Код выхода 137 и готовность после восстановления обязательны. Это последовательные аварии в одном сценарии, не утверждение об одновременном физическом отказе машины.

## Холодная сверка

Каждый запуск создаёт новый процесс Flutter и отдельную D-Bus-сессию/Secret Service с прежним зашифрованным профилем. Независимое чтение через `secret-tool` и проверка файла GNOME Keyring остаются обязательными. Исходный SHA-256 снимка сравнивается после восстановления; исходная команда и запрос сверки должны быть protobuf-эквивалентны. Снимок не содержит токена сессии.

Исполнитель и пул соединений сервера сохраняются; вручную пересоздаётся только независимый пул наблюдателя, который проверяет состояние БД. После аварии PostgreSQL старое соединение исполнителя может дать `Internal`. Контроллер допускает до четырёх холодных запусков, каждый выполняет одну сверку. Новый запуск разрешён только при `Internal`, `stop` и сохранённой неопределённости; иные ошибки завершают тест отказом. Успешная сверка UNKNOWN прекращает проверку сразу и не разрешает повтор Execute. Это ограниченная логика стенда, а не новая политика автоматических повторов рабочего приложения.

Во всех вариантах требуется:

- ровно один запрос контекста, один Execute и один вызов гостевого обработчика за весь сценарий;
- `attempts=0` в восстановленном клиенте: он только сверяет, не отправляет команду заново;
- неизменный снимок до/после аварий, сохранённая запись журнала при UNKNOWN и CONFIRMED;
- отсутствие частичных данных, лишних квитанций или событий; исходный ID события после сохранённого COMMIT не меняется;
- при UNKNOWN — `stop`/`unknown=true`, при CONFIRMED — `confirmed`/`unknown=false`.

Прежние три сценария аварии клиентского процесса и проверки повторного входа/ACL запускаются вместе с новыми. Новая проверка использует сохранённую действующую сессию владельца; она не заменяет прежние сценарии отзыва прав и повторного входа.

## Результаты

[GitHub CI 41308188237](https://github.com/space-protocol-project/space-app/actions/runs/41308188237) завершён с `conclusion=success`; задания `recovery` и `complexity / cognitive` успешны.

- Ревизия приложения: `59ab3c35b6266a67e0717ef91d22ca9796e3500a`; сервер: `5e6115a375ff3b86db128a86403ac2d21fc8d238`. Последующий коммит документации не меняет проверенные исходники.
- Три повторения каждого из пяти конечных сценариев: 15 успешных сценариев, 21 результат вместе с родительскими тестами; ошибок и пропусков нет. Шесть сценариев проверяют сочетание клиента и PostgreSQL, девять повторяют прежние точки аварии клиента.
- Подтверждены 15 SIGKILL групп клиента и 6 SIGKILL контейнера PostgreSQL с кодом 137. Журнал БД содержит шесть автоматических восстановлений после аварии.
- 48 запусков Flutter, 33 завершённых холодных чтения системного журнала. Все шесть новых сценариев получили успешную сверку с первого холодного запуска; дополнительные запуски из допустимого предела четырёх не потребовались.
- До COMMIT во всех трёх повторениях — UNKNOWN и 0/0/0/0; после COMMIT — CONFIRMED и 1/1/1/1. В каждом новом сценарии ровно один Execute, запрос контекста и вызов гостевого обработчика.
- `go test -race`, `go vet ./internal/postgres`, `go mod verify`, `flutter analyze` и 55 профильных тестов прошли. Максимальная COG приложения — 14; рабочий Dart в этом изменении не редактировался.
- [Сводка и исходные журналы](p1-results/2026-11-01-client-database/summary.json), метаданные CI и журнал PostgreSQL сохранены с [SHA-256](p1-results/2026-11-01-client-database/SHA256SUMS). Локальные сборки, тесты и устройства не использовались.

## Границы

Рабочий код приложения, сервера, схема БД и лимиты команд не меняются. Новый Go-стенд находится в `space-app/tools/p1_command_database_test.go` и только в CI копируется в тестовый пакет PostgreSQL закреплённой ревизии сервера.

Не проверяются потеря питания/диска, отказ внутри незавершённой записи системного журнала, реплики и сетевое разделение кластера, авария процесса сервера одновременно с клиентом/БД, остальные платформы клиента, пользовательский интерфейс восстановления и настоящий WASM именно при этой комбинации отказов. Эти результаты не закрывают остальные критерии [E01–E07](SPACE-PLUGINS-P1-EXIT.md).
