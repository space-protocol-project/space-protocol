# P1: контракты и первые прототипы расширений

Статус на 29 октября 2026: начат P1 для 0.9.0. Подготовлены экспериментальные схемы, изолированный WASM-хост и ограниченный Flutter-рендерер. Это проверка основы архитектуры, не завершение P1 и не публичная установка расширений. [Основная спецификация](SPACE-PLUGINS.md), [план](../TODO.md), [закрытый P0](SPACE-PLUGINS-P0-RESULTS.md).

Продолжение от 30 октября: [изоляция компилятора и общие квоты памяти Linux](SPACE-PLUGINS-P1-ISOLATION.md), затем [Job Objects на Windows](SPACE-PLUGINS-P1-WINDOWS.md). Добавлен [строгий внутренний протокол worker](SPACE-PLUGINS-P1-WORKER.md). Реализовано [восстановление Linux после аварии supervisor](SPACE-PLUGINS-P1-RECOVERY.md). Следующий шаг — [жизненный цикл экспериментальной Linux-службы](SPACE-PLUGINS-P1-SERVICE.md). Ниже сохранена исходная проверка ABI от 29 октября; новый ProcessHost запускает этот код только внутри отдельного worker.

## 1. Результат проверки контрактов

Сохраняем разделение Package / Installation / Instance. Установка пакета не создаёт полномочия пользователя, а команда расширения не обходит ACL ядра. Идентичность, MLS, ключи, WebRTC/TURN, резервные копии и проверка доступа остаются в ядре. Чаты, Комнаты, Обсуждения и Лента позднее переносятся в четыре самостоятельных репозитория; этот прототип их не заменяет.

| Контракт | Проверяемая часть P1 | Что ещё необходимо |
| --- | --- | --- |
| Пакет | Закрытая схема экспериментального manifest, версии, безопасный фиксированный entrypoint | Полный manifest, contributions, подпись, доверие издателю, архив, Git resolver |
| ABI | Три экспорта, память, указатели, владение, тайм-аут, запрет WASI | Согласовать окончательный v1 с SDK и прикладными host calls |
| Запрос | Схема kind/name/payload/context; principal/device/space/instance и ревизия доступа выделены из payload | Реальный dispatcher формирует context из сессии и повторно проверяет ACL; схема не авторизует запрос |
| Ошибки | Закрытая схема code/message_key/retryable | Отображение всех ошибок runtime в стабильные коды и трассировка без утечки данных |
| UI | Версия, три компонента, переводы, команды, fallback, ресурсные бюджеты | Формы, привязки query/state, contributions «Обзора», остальные компоненты и тесты совместимости |
| События / lifecycle | Сохраняются требования основной спецификации | Схемы событий, идемпотентность, доставка, транзакции и обновление/откат ещё не реализованы |
| Внешний API | Сохраняются существующие RPC | Новые protobuf-сервисы реестра/commands/queries/contributions/lifecycle и генерация Go/Dart/OpenAPI ещё не добавлены |

Эксперимент имеет отдельные идентификаторы `space.plugin.p1`, `space_plugin_p1`, `space.ui.p1`. Они не объявляются стабильным `v1`; совместимость с будущим SDK не обещается. Нельзя устанавливать образец manifest как готовый пакет: это положительная фикстура схемы, без исполняемого пакета и подписи.

Машинные контракты находятся в [extensions/p1](extensions/p1): `manifest.schema.json`, `request.schema.json`, `error.schema.json`, `ui.schema.json` и положительные JSON-примеры. JSON Schema — Draft 2020-12. Неизвестные поля закрытых объектов запрещены. Значения `storage.own` / `events.own` в manifest проверяют только форму декларации; действующих разрешений хост не выдаёт.

Поля 64-битных счётчиков и времени передаются десятичными строками. Текущая схема проверяет форму и длину, но ещё не диапазон uint64 и актуальность deadline; это обязательная задача dispatcher. Лимиты глубины JSON, общего числа узлов, уникальности ID, наличия переводов и разрешённости команд дополнительно проверяются кодом. Одной проверки JSON Schema недостаточно.

## 2. Серверный эксперимент

Исходники: `space-server/experiments/extensions`, отдельный Go module, не импортируемый рабочим сервером. Закреплён [wazero v1.12.0](https://github.com/wazero/wazero/releases/tag/v1.12.0). Проверяются compiler и interpreter. Нативные библиотеки WASM не нужны; это не проверка подписанной упаковки приложения на macOS.

### ABI и владение памятью

- Модуль экспортирует память `memory`, `space_alloc(i32) -> i32`, `space_free(i32, i32)` и `space_handle(i32, i32) -> i64`.
- Вход — UTF-8 JSON; хост вызывает alloc, проверяет границы и копирует вход в память гостя. Гость владеет выделенной областью до free либо уничтожения instance.
- Результат handle: старшие 32 бита — указатель, младшие — длина. Область результата должна быть непустой, находиться в памяти и не пересекаться со входом. Для проверки пересечения используется расширенная арифметика.
- Хост копирует результат в собственную память и проверяет JSON, затем вызывает free сначала для результата, затем для входа. Указатель в память гостя наружу не передаётся.
- При trap, тайм-ауте, неверном JSON/указателе либо ошибке free вызов не выдаёт результат; instance уничтожается. Очистка ошибочного instance не зависит от успешного выполнения guest free.
- На каждый вызов создаётся новый instance; изменяемые globals и линейная память не переходят в следующий вызов. Компиляция кешируется по SHA-256 исходного WASM.

WASI не подключён, импортированная память запрещена. Единственный разрешённый импорт — диагностический `space_host_p1.wait(i32) -> i32`. Он не даёт доступа к файлам, сети или данным Space. Разрешение передаётся доверенным Go-кодом, а не JSON. Core start исполняется без этого разрешения; запрет автоматического `_start` не устраняет Core start, поэтому его также ограничивает deadline. Прикладной `space_host_call` пока отсутствует.

### Экспериментальные бюджеты

| Ресурс | Предел |
| --- | --- |
| WASM-бинарник | 64 КиБ |
| JSON входа и ответа | 16 КиБ каждый |
| Линейная память instance | 4 страницы × 64 КиБ = 256 КиБ |
| Одновременные вызовы на Host | 2; третий получает отказ без очереди |
| Суммарный максимум линейной памяти активных instance | 512 КиБ |
| Кеш компиляций | 16 различных digest; следующий отклоняется |
| Вызов, включая Core start / alloc / handle / free | Deadline 100 мс или более ранняя отмена вызывающего кода |
| JSON | Строгий UTF-8, глубина до 8, без дубликатов ключей, хвоста, NaN, Infinity и переполнения float64 |

Это стартовые параметры стенда, не производственные квоты. Стенд проверяет завершение прерванного вызова менее чем за 2 секунды с учётом планировщика CI; он не доказывает жёсткий real-time предел 100 мс.

**Границы исходного ABI-прототипа:** 512 КиБ — только линейная память, не RSS Go-процесса. Его локальный кеш ограничен числом модулей. В продолжении P1 добавлен [ProcessHost для Linux](SPACE-PLUGINS-P1-ISOLATION.md): компиляция и выполнение вынесены в ограниченный процесс; общего кеша между вызовами нет. Сам localHost не является безопасной границей процесса. Отмена Go host calls требует их собственного сотрудничества: тестовый wait поддерживает context, произвольный блокирующий callback автоматически безопасным не становится. Проверка JSON в Go синтаксическая; request/error schema и формирование доверенного context ещё не включены в Call. До закрытия этих пунктов нельзя подключать недоверенные пользовательские пакеты к рабочему серверу.

## 3. Flutter-прототип

Исходники: `space-app/client/lib/src/extensions_p1` и `client/lib/ui/extensions_p1.dart`; тесты — `client/test/extensions_p1_test.dart`. Рендерер не зарегистрирован в навигации приложения и не обращается к рабочему API.

- Компоненты: `section.v1`, `text.v1`, `button.v1`. Отображается обычный текст; загрузка Dart/HTML/JavaScript, WebView, произвольные URL и системные команды не поддерживаются.
- Документ имеет версию `space.ui.p1`. У каждого узла уникальный ID. Лимиты: до 64 узлов, до 32 элементов в списке, глубина узлов до 4; одновременно действует более строгий для некоторых деревьев предел глубины всего JSON 8.
- Идентификаторы: `[a-z][a-z0-9_.-]{0,63}`. Тексты: 1–512 Unicode code points, до 64 переводов на язык. Языки прототипа en/ru; en обязателен и служит fallback.
- Неизвестный компонент допускается только с `required: false` и валидным fallback. Обязательный неподдерживаемый компонент, лишнее поле, отсутствующий текст и незарегистрированная команда отклоняют документ целиком.
- Список допустимых команд и обработчики приходят из доверенного клиента. Cubit блокирует повторное действие до окончания первого, скрывает подробности исключений и не обновляет закрытое состояние. Это защита поведения UI, не авторизация сервера.
- Название источника расширения и общий текст ошибки задаёт оболочка. Проверяются семантика кнопки, клавиатура, русский перевод, английский fallback и отсутствие overflow при ширине 320 и масштабе текста 3×.

Общий пример `ui.json` скопирован в тестовый каталог приложения. CI сравнивает его побайтно с закреплённым полным SHA протокола `d324ce5618bcd7458e8bfac557dade15e715378f`. Это проверка согласованности фикстуры, не сквозная установка пакета и не соединение Flutter с WASM по сети.

Промежуточные неуспехи: [некорректная custom section фикстуры](https://github.com/space-protocol-project/space-server/actions/runs/40947230541), [оформление условий Dart](https://github.com/space-protocol-project/space-app/actions/runs/40948148633), [сокращённый SHA checkout](https://github.com/space-protocol-project/space-app/actions/runs/40948761796), [слишком позднее освобождение SemanticsHandle в тесте](https://github.com/space-protocol-project/space-app/actions/runs/40948907800). Исправлены и повторно проверены; они не считаются приёмкой. Лишние автоматические сборки установщиков и полного неизменённого сервера от промежуточных коммитов остановлены; приёмка прототипов основана на трёх целевых workflows выше.

## 5. Следующая часть P1

1. Завершить платформенную изоляцию: Linux ProcessHost описан в [продолжении P1](SPACE-PLUGINS-P1-ISOLATION.md); добавлен [Windows ProcessHost](SPACE-PLUGINS-P1-WINDOWS.md); остаются macOS, packaging macOS и интеграция launcher в жизненный цикл сервера. Кеш между запросами пока отключён.
2. Определить SDK и создать четыре репозитория расширений с CI, лицензиями, сборкой и проверяемым пакетом для Git-установки; не переносить бизнес-логику раньше P4/P5.
3. Спроектировать protobuf API и совместимую генерацию: реестр и экземпляры, команды, queries, contributions, lifecycle. Добавить доверенный dispatcher с ACL, контекстом сессии и идемпотентностью.
4. Дополнить схемы событий/команд/результатов и полный manifest, связать их с ABI и тестами Go/Dart; зафиксировать окончательный v1 после SDK-проверки.
5. Реализовать и проверить trust/signature/key rotation/archive policy до публичной установки из Git.
6. Расширить декларативный UI под contributions и необходимые формы, проверить ошибки, доступность и совместимость версий на целевых платформах.

P2 начинается с совместимых внутренних адаптеров, без миграции пользовательских данных. Критерии 0.9.0 остаются P1–P3 и внешний пакет «Опросы»; наличие этих прототипов само по себе выпуск не закрывает.
