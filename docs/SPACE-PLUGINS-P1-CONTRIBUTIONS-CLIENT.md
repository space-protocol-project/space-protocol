# P1: список contributions и открытие элемента в клиенте

11 ноября 2026 года. Клиентский прототип использует [общий реестр и protobuf API](SPACE-PLUGINS-P1-CONTRIBUTIONS.md): получает элементы одного экземпляра и открывает выбранный query через существующий декларативный рендерер. Прикладное состояние находится в `ContributionsCubit` на flutter_bloc, повторяющиеся поля состояния генерируются Freezed. Рабочая навигация SpaceApp не подключается этим изменением.

## Поведение и границы доверия

`ConnectContributionsTransport` использует сгенерированный `ExtensionP1ServiceClient`, `RpcCall` с отменой и сроком пять секунд. Доверенная оболочка задаёт экземпляр, текущие заголовки сессии и допустимые имена stateless-команд. Метаданные элемента не дают права исполнения команд. Query всегда передаёт имя из проверенного списка и пустой payload `{}`; произвольные параметры запросов и маршруты не добавлены.

`ContributionRegistry` проверяет предел 32 элементов, 32-байтовый digest, уникальность и формат ID/query, известный вид, обязательный английский fallback и границы переводов. Результат неизменяем; сортировка идёт по ID. Заголовок выбирается по точной локали, основному языку, затем английскому. Digest сохраняется как идентичность регистрации, не используется как разрешение или заменитель текущего допуска.

Экран показывает локализованное название и вид «Обзор»/«Раздел». Нажатие вызывает `QueryExtension`, проверяет `ui_api=space.ui.p1` и документ перед отображением через `ExtensionPanel`. Есть загрузка, отсутствие элементов, общий отказ и кнопка повторения. Возврат и обновление заново получают список с сервера; старый кеш не выдаётся при ошибке. Для команд сохраняется явный `effect=NONE`; новые мутации здесь не вводятся.

Каждая загрузка или смена элемента отменяет предыдущие запросы и меняет локальное поколение. Поздние ответы и ошибки прежнего поколения не заменяют новый документ. `invalidate()` очищает список/документ и отменяет запросы при сообщении оболочки о смене или завершении сессии; `close()` не допускает поздних обновлений закрытого Cubit. Ошибка чтения, версии UI или команды очищает ранее доступные сведения. Тексты транспортных ошибок не выводятся пользователю.

Отзыв на сервере обнаруживается следующим запросом; отдельной подписки на изменения ACL этот прототип не вводит. Уже отрисованный документ не исчезает мгновенно без запроса или вызова `invalidate()` владельцем. Рабочее подключение владельца к событиям сессии, агрегация разных установок, маршрутизация и кеширование на пользователя относятся к интеграции P2.

## Проверки

Клиентский профиль GitHub CI выполняет анализ Flutter, повторную генерацию Freezed со сверкой Git, тесты на Linux/Windows и общий контроль COG. Новые тесты охватывают строгую проверку метаданных, неизменяемость, локализацию, неизвестный элемент, ошибку и повтор, пустой список, открытие/возврат, ответ не по порядку, invalidate/close/back во время чтения. Транспортные тесты используют настоящие HTTP-запросы с protobuf: проверяют заголовок сессии, instance/query, эффект команды, отказ неизвестного имени, версию UI и отмену ожидания.

Нативный Linux-профиль использует отдельный тест `TestContributionsNativeClientFixture` в space-server: настоящие сессии/ACL, PostgreSQL, прямой Connect-обработчик с барьером отправки и WASM-worker под cgroup. Flutter работает без повышения прав. Временные учётные данные находятся в приватном каталоге стенда и не публикуются в артефактах. Управляющие файлы стенда меняют ACL или завершают тестовую сессию; это не API рабочего сервера.

Нативный сценарий открывает элемент Обзора и раздел, возвращается к списку, повторяет после hot restart, отдельно проверяет hot reload. После получения списка право чтения отзывается до открытия: документ не выдаётся. После восстановления ACL повтор снова получает список и документ. Завершение сессии затем блокирует возврат к списку. После остановки проверяются отсутствие новых данных/квитанций/outbox и освобождение cgroup.

Windows в этом срезе получает анализ, тесты состояний/виджетов и HTTP/Connect; новый нативный сценарий с PostgreSQL/WASM на Windows ещё не принят. Предыдущая приёмка нативных форм Windows не заменяет этот сценарий. Проверка macOS по решению пользователя остаётся отложенной и не засчитывается как успешная.

## Результат и продолжение

Ревизии исполняемого кода: app `c0e93a94a020bb56f9b4825f8aa530c21bf20d3e`, server `f12558aecaa8901685cb44a1f7b6b77a2b7ad6fd`. Protobuf API не менялся; использован контракт предыдущего [среза реестра](SPACE-PLUGINS-P1-CONTRIBUTIONS.md). В сервере изменён только изолированный тестовый стенд, производственные обработчики не переписаны.

Полный [CI 43025109531](https://github.com/space-protocol-project/space-app/actions/runs/43025109531) успешен: клиентские задания Linux и Windows, нативный Linux и контроль сложности. На каждой ОС выполнен анализ, сверка генерации и 31 тест без пропусков. Нативное задание подтвердило шесть контрольных отметок — два вида элемента до/после перезапуска, hot reload, hot restart, отзыв ACL перед открытием, восстановление/повтор и выход перед чтением списка. Серверный тест завершился PASS, cgroup удалена.

[Общий CI сервера 43024900481](https://github.com/space-protocol-project/space-server/actions/runs/43024900481) на окончательной ревизии стенда также полностью успешен: проверки Go, полная Flutter-регрессия, сквозной вход/события/отзыв и нативное хранилище Windows. Последнее относится к существующему сценарию хранилища и не подменяет нативную приёмку нового экрана contributions на Windows.

Первый запуск 43024750333 не принят: клиентскому Linux-заданию не хватало системных X11-заголовков для нативной зависимости Flutter. Они добавлены, запущен новый полный профиль; проверки не отключались. Старый запуск отменён как заменённый. Дополнительно устранена гонка запуска стенда: файл подключения публикуется переименованием после полной записи, чтобы клиент не увидел частичный JSON.

Локально анализ прошёл без замечаний, 31 целевой и регрессионный тест успешен; COG — 419 файлов, 3995 функций, максимум 14, превышений нет. Отчёт сложности GitHub CI подтверждает максимум **9** для нового рукописного кода contributions; функции Cubit — не выше 4. Локальные результаты вспомогательные и не заменяют нативную приёмку GitHub CI.
