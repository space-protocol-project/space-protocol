# P1: список contributions и открытие элемента в клиенте

11 ноября 2026 года. Клиентский прототип использует [общий реестр и protobuf API](SPACE-PLUGINS-P1-CONTRIBUTIONS.md): получает элементы одного экземпляра и открывает выбранный query через существующий декларативный рендерер. Прикладное состояние находится в `ContributionsCubit` на flutter_bloc, повторяющиеся поля состояния генерируются Freezed. Рабочая навигация SpaceApp не подключается этим изменением.

## Поведение и границы доверия

`ConnectContributionsTransport` использует сгенерированный `ExtensionP1ServiceClient`, `RpcCall` с отменой и сроком пять секунд. Доверенная оболочка задаёт экземпляр, текущие заголовки сессии и допустимые имена stateless-команд. Метаданные элемента не дают права исполнения команд. Query всегда передаёт имя из проверенного списка и пустой payload `{}`; произвольные параметры запросов и маршруты не добавлены.

`ContributionRegistry` проверяет предел 32 элементов, 32-байтовый digest, уникальность и формат ID/query, известный вид, обязательный английский fallback и границы переводов. Результат неизменяем; сортировка идёт по ID. Заголовок выбирается по точной локали, основному языку, затем английскому. Digest сохраняется как идентичность регистрации, не используется как разрешение или заменитель текущего допуска.

Экран показывает локализованное название и вид «Обзор»/«Раздел». Нажатие вызывает `QueryExtension`, проверяет `ui_api=space.ui.p1` и документ перед отображением через `ExtensionPanel`. Есть загрузка, отсутствие элементов, общий отказ и кнопка повторения. Возврат и обновление заново получают список с сервера; старый кеш не выдаётся при ошибке. Для команд сохраняется явный `effect=NONE`; новые мутации здесь не вводятся.

Каждая загрузка или смена элемента отменяет предыдущие запросы и меняет локальное поколение. Поздние ответы и ошибки прежнего поколения не заменяют новый документ. `invalidate()` очищает список/документ и отменяет запросы при сообщении оболочки о смене или завершении сессии; `close()` не допускает поздних обновлений закрытого Cubit. Ошибка чтения, версии UI или команды очищает ранее доступные сведения. Тексты транспортных ошибок не выводятся пользователю.

Отзыв на сервере обнаруживается следующим запросом; отдельной подписки на изменения ACL этот прототип не вводит. Уже отрисованный документ не исчезает мгновенно без запроса или вызова `invalidate()` владельцем. Рабочее подключение владельца к событиям сессии, агрегация разных установок, маршрутизация и кеширование на пользователя относятся к интеграции P2.

## Проверки

Клиентский профиль GitHub CI выполняет анализ Flutter, повторную генерацию Freezed со сверкой Git, тесты на Linux/Windows и общий контроль COG. Новые тесты охватывают строгую проверку метаданных, неизменяемость, локализацию, неизвестный элемент, ошибку и повтор, пустой список, открытие/возврат, ответ не по порядку, invalidate/close/back во время чтения. Транспортные тесты используют настоящие HTTP-запросы с protobuf: проверяют заголовок сессии, instance/query, эффект команды, отказ неизвестного имени, версию UI и отмену ожидания.

Нативный Linux-профиль использует отдельный тест `TestContributionsNativeClientFixture` в space-server: настоящие сессии/ACL, PostgreSQL, прямой Connect-обработчик с барьером отправки и WASM-worker под cgroup. Flutter работает без повышения прав. Временные учётные данные находятся в приватном каталоге стенда и не публикуются в артефактах. Управляющие файлы стенда меняют ACL или завершают тестовую сессию; это не API рабочего сервера.

Нативный сценарий открывает элемент Обзора и раздел, возвращается к списку, повторяет после hot restart, отдельно проверяет hot reload. После получения списка право чтения отзывается до открытия: документ не выдаётся. После восстановления ACL повтор снова получает список и документ. Завершение сессии затем блокирует возврат к списку. После остановки проверяются отсутствие новых данных/квитанций/outbox и освобождение cgroup.

Первоначальный срез проверял Windows только анализом и тестами состояний/виджетов и HTTP/Connect. Последующее нативное подтверждение Windows приведено ниже; прежняя приёмка форм не использована вместо нового сценария. Проверка macOS по решению пользователя остаётся отложенной и не засчитывается как успешная.

## Нативная приёмка Windows — 11 ноября

Полный [CI 43037855946](https://github.com/space-protocol-project/space-app/actions/runs/43037855946) успешен на app `82b5ee495db879e3a67d761d176765d723653e3f`. Закреплён прежний server `f12558aecaa8901685cb44a1f7b6b77a2b7ad6fd`; Dart, Cubit, protobuf и производственные обработчики не менялись. В workflow теперь пять заданий: нативные Windows/Linux, клиентские тесты Windows/Linux и COG.

Windows запускает настоящие PostgreSQL 17.11, сессии и ACL ядра, прямой Connect и отдельный WASM-worker через ProcessHost/Job Objects. Служба PostgreSQL не устанавливается: создаётся новый кластер CI на случайном loopback-порту с SCRAM-паролем. После завершения требуется успешная остановка и подтверждение отсутствия работающего сервера через pg_ctl. Тестовая схема удаляется штатным завершением Go-стенда; рабочие данные пользователя не используются.

На обеих ОС подтверждены шесть отметок: Обзор и раздел до/после hot restart, hot reload, отказ открытия после отзыва ACL, восстановление доступа с повтором, отказ списка после выхода. Это один холодный запуск Flutter и горячий перезапуск, не два независимых холодных процесса. Go-стенд с race завершился PASS и проверил отсутствие новых данных, квитанций и outbox. Ресурсный каталог worker удалён; на Linux также удалена cgroup. Клиентские задания вновь выполнили анализ, сверку Freezed и по 31 тесту без пропусков; профиль COG не ослаблялся.

Первый запуск 43033022348 не принят и заменён: initdb на Windows не смог прочитать файл пароля в закрытом каталоге с токеном ядра. initdb получает ограниченный Windows-токен до чтения пароля, что подтверждается [исходником PostgreSQL 17.11](https://raw.githubusercontent.com/postgres/postgres/REL_17_11/src/bin/initdb/initdb.c). Исправлен только bootstrap стенда: отдельный одноразовый файл наследует ACL рабочей папки CI и удаляется сразу после initdb, включая отказ. Права каталога с токеном сессии не расширяются, SCRAM не заменён на trust. Параметр файла описан в [документации initdb](https://www.postgresql.org/docs/17/app-initdb.html).

Повторный запуск 43034030970 выявил истечение сессии до первого списка: нативная сборка Windows заняла более 10 минут, а сессии ядра действуют 10 минут. Сборка перенесена перед созданием стенда и выдачей сессии на обеих ОС; срок действия сессий и проверки ACL не ослаблены. Тот же прогон задержался при загрузке Linux-пакетов с azure.archive.ubuntu.com; добавлены ограниченное время загрузки, отказ при неполном обновлении индекса и резервное HTTPS-зеркало mirrors.edge.kernel.org. Подписи пакетов проверяются штатными ключами Ubuntu, проверка TLS не отключается. Промежуточный 43036598281 отменён в пользу следующего запуска. В 43037132127 нативный Windows уже прошёл, но задания Linux завершились сетевой ошибкой подготовки; ни один из этих запусков не считается полной приёмкой.

Бинарный архив PostgreSQL загружается с закреплённого HTTPS-адреса EDB, используемого сборкой runtime проекта; проверяется версия, сохраняются URL и SHA-256 полученных байтов. Этот digest — свидетельство загруженного файла, не независимая подпись издателя. Пароль базы, токен ядра, каталог данных и ZIP не публикуются. [Сырые результаты](p1-results/2026-11-11-contributions-windows/) и [SHA-256](p1-results/2026-11-11-contributions-windows/SHA256SUMS) сохраняют доказательства отдельно от исходной Linux-приёмки.

Подпункт нативного чтения contributions и открытия элементов Windows закрыт. Это не новая приёмка LPAC, сетевого запрета, дисковой границы или рабочего broker: Windows-хост здесь использует ресурсный Job-профиль. Оставшиеся E01/E03/E06/E07 сверяются по общей матрице. macOS по решению пользователя отложен; P1 и релиз 0.9.0 не объявляются завершёнными.
