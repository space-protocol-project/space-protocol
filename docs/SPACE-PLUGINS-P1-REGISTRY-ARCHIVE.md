# P1 / E01: архивное восстановление реестра и аудита

Статус на 1 ноября 2026 года: архивный цикл реестра v2 прошёл GitHub CI на трёх ОС. Продолжение [реестра установок](SPACE-PLUGINS-P1-REGISTRY.md) и [постоянного аудита](SPACE-PLUGINS-P1-LIFECYCLE-AUDIT.md).

## Проверяемый путь

Стенд использует собранный домашний runtime и настоящую PostgreSQL. Managed-сервис вызывается из тестового процесса через адаптеры ядра; публичный административный RPC этим прогоном не вводится. Пространство получает идентичность, устройство, сессию и владельца через существующие операции ядра. Managed-сервис создаёт пять установок, выполняет переходы владельца и ядра, сохраняет команду, квитанцию и три события outbox. Затем соединения и PostgreSQL закрываются.

Проверяются оба существующих формата:

- Физическая копия остановленной базы: `CreateBackup` → `RestoreBackup` в новый каталог → запуск PostgreSQL.
- Переносимый ZIP: `ExportPortable` с `pg_dump` → `ImportPortable` с `pg_restore` в новый каталог → запуск PostgreSQL.

Для каждого формата выполняются варианты с полной квитанцией и с удалённым по сроку хранения телом квитанции. Форматы архива и рабочий код резервного копирования этим блоком не изменены. Лимит полного набора домашних тестов в сборщике увеличен с 5 до 10 минут для расширенной матрицы; целевой архивный прогон ограничен 20 минутами. Гостевой план детерминирован, а модуль задаётся доверенной тестовой привязкой; это проверка хранилища и архивного пути, не упаковки настоящего WASM-пакета.

## Что должно сохраниться

| Установка | Состояние в архиве | Ревизия lifecycle |
| --- | --- | ---: |
| install | enabled | 2 |
| disabled | disabled | 1 |
| disabling | disabling | 3 |
| quarantined | quarantined | 2 |
| removed | removed | 2 |

Реестр сравнивается целиком, включая отпечатки привязок, за исключением поколения текущей оболочки. Аудит сравнивается целиком: авторы, идентификаторы, действия, состояния, ревизии, исторические поколения и время должны совпасть. Сравнение выполняется до создания managed-сервиса и после него: открытие не должно добавлять начальные снимки или переписывать историю.

У всех пяти установок поколение архивной копии должно смениться ещё до создания новой оболочки. Запрос управления со старым поколением отклоняется. Выключенная, выключаемая, удалённая и карантинная установки не вызывают гостя. Доверенное ядро завершает ранее начатое выключение: `disabling` ревизии 3 становится `disabled` ревизии 4 и получает одну новую системную запись аудита с новым поколением.

Прежние проверки данных выполняются в том же цикле: идентичность сервера сохраняется; переносимый архив не переносит сессии; после нового входа меняется `history_id`; старая команда не исполняется повторно. Полная квитанция сверяется с исходной, удалённое тело не восстанавливается. Сохраняются данные, ревизия, три события outbox и подтверждённый курсор. Старые аренда и ACK отклоняются; ожидающее событие получает новый токен и следующую попытку. После восстановления вызовов гостя нет.

## Отрицательные сценарии

Для каждого формата подготавливаются две семантически повреждённые копии:

1. Полностью отсутствует таблица аудита при версии реестра v2.
2. У установки `disabling` удалена промежуточная запись ревизии 2, но сохранены начальная и последняя записи.

В физической копии пересчитывается манифест файлов. Для ZIP создаётся настоящий PostgreSQL dump повреждённой базы и пересчитывается SHA-256 в манифесте. Проверка структуры и контрольных сумм проходит; отказ обязан исходить от проверки согласованности реестра/аудита, а не от повреждённого ZIP или неверного хеша.

Восстановление должно завершиться отказом до публикации назначения. Родительский каталог назначения остаётся пустым: нет опубликованной базы, временного каталога или оставленных секретов. Исходная копия остаётся неизменной и проходит проверку контрольных сумм. Повреждения создаются только в изолированных тестовых каталогах.

## GitHub CI и границы

Матрица `plugin-p1-backup.yml`: Ubuntu 22.04, Windows 2025, macOS 15. На каждой ОС строится runtime и выполняются домашние тесты; затем восемь конечных архивных сценариев повторяются трижды с `-race`. Workflow требует все восемь сценариев по три раза и запрещает ошибки/пропуски целевого прогона. Сохранены прежние проверки расширений без managed-реестра, восстановления старой копии и переноса пространства.

Исходное задание macOS 14 отменено инфраструктурой до запуска шагов: образ попал в [плановое отключение перед завершением поддержки](https://github.com/actions/runner-images/issues/13518). Матрица переведена на macOS 15; остальные версии ОС и код сценариев не менялись.

Предварительные прогоны выявили две ошибки нового стенда: повторное назначение уже созданного владельца и повторную обработку ожидаемой ошибки старой сессии в managed-ветке после ZIP-переноса. Обе исправлены в тестах без изменения проверок доступа или восстановления. Неуспешные и отменённые прогоны не используются как приёмка.
