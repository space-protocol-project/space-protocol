# Управление сервером из приложения Space

Владелец, администратор и участники используют одно Flutter-приложение. HTML /space, web-оболочка и возможность включить прежнюю панель удалены. Сервер предоставляет discovery, gRPC и независимый HTTP API.

## Подключение и владение

Запустите сервер по server/README.md и подключитесь в приложении. Проверьте server ID и отпечаток до подтверждения доверия. По умолчанию первый успешный вход на новом сервере назначает владельца. При выбранном ручном bootstrap получите одноразовый setup-код через space-server -setup-code, откройте управление в приложении, явно разрешите этому устройству управление, затем предъявите код.

Для управления нужны роль owner/admin и подписанное разрешение space.manage. Устройство без этого разрешения предлагает отдельное подтверждение выдачи. Подпись выполняется сохранённым root либо исходной корневой JSON/PNG-карточкой. Recovery-карточка не может расширить свои права. Новое разрешение сохраняется и проверяется в vault до отзыва прежнего.

## Настройки и доступ

В «Управлении пространством» доступны названия, доступность чатов, регистрация, каналы, порядок, архив и публичный предпросмотр. ACL содержит правила ролей и индивидуальные правила участников. При конфликте revision загрузите актуальное состояние и повторите изменения; черновик не применяется автоматически.

Владелец изменяет роли и блокирует участников. Приглашения задают роль member/reader, срок и число использований. Секретный код виден только после создания; скопируйте его или ссылку. Ссылку origin#invite=… вставляют в поле адреса приложения. Отзыв ссылки закрывает новые вступления; уже вступившего человека блокируют отдельно.

Список устройств показывает сроки, scopes, recovery и связь с родительским разрешением. Отзыв текущего устройства отключает приложение. Отзыв другой записи требует root-подписи или исходной карточки; отзыв recovery закрывает также дочерние устройства.

## Восстановление

На странице идентичности доступны экспорт и импорт JSON/PNG-карточки, QR-камера, подтверждение сопряжения, ротация root и возобновление сохранённой ротации. Коды сопряжения сверяют независимо на обоих устройствах. Ротация сохраняет principal, но отзывает прежние устройства и карточки: сохраните новую карточку.

Физическую камеру и сквозные PostgreSQL-сценарии нужно проверить перед выпуском. Локальный Docker в текущей работе не запускается. [Описание основного приложения](APPLICATION-GUIDE.md), [решение](adr/025-unified-administration.md).
