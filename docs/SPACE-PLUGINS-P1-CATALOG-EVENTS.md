# P1: ответы, события и отмена операций каталога

Кандидат от 3 ноября 2026 года, продолжение [локальных разрешений](SPACE-PLUGINS-P1-CLIENT-LOCAL.md). Это схемы и чистая модель порядка выдачи. Файловый адаптер, системные подписки и параллельное исполнение клиента здесь не реализованы.

## Вызовы и привязка

[Обёртка вызова](extensions/p1/client-catalog-call.schema.json) добавляет случайный `request_id` к прежнему запросу `space.client.catalog.p1`, не меняя его формат. [Команда отмены](extensions/p1/client-catalog-cancel.schema.json) содержит этот ID и полную привязку: устройство, локальный профиль, установка, экземпляр, digest пакета, поколение, grant/ревизия и корень. Хост сверяет их с собственным контекстом; чужой ID или привязка не отменяют операцию.

Идентификатор вызова не переиспользуется в одном поколении. Повтор передачи идентичного запроса может вернуть только ранее сохранённый результат этой операции после повторной проверки доступа; изменённый запрос с тем же ID отклоняется. Хранение ответов ограничивается бюджетом хоста; после удаления записи повтор даёт отказ и требует нового ID, а не скрытого повторного чтения. Реализация этого кеша ещё предстоит.

## Ответы и события

[Схема событий](extensions/p1/client-catalog-event.schema.json) — строгое объединение четырёх вариантов с общей привязкой, `request_id` и монотонным `sequence`, начинающимся с 1. Неизвестные поля и вложенные данные другого варианта запрещены.

| Вид | Содержимое | Правила |
| --- | --- | --- |
| `page` | snapshot, записи, next_cursor, more | Одна страница, не больше min(limit, 128) записей |
| `chunk` | snapshot, offset, data_base64, eof | Одна порция, не больше min(limit, 65536) декодированных байт |
| `invalidated` | directory_changed либо overflow | Продолжение снимка невозможно; после события только terminal/StaleHandle |
| `terminal` | Только код завершения | Ровно одно завершение; никаких имён, дескрипторов или байтов |

Один вызов выдаёт не более одного `page` или `chunk`, затем `terminal`. `Completed` допустим после ответа с данными, включая пустую последнюю страницу или пустое чтение с `eof=true`. Ошибка, отмена или отзыв могут завершить вызов без данных. После terminal запрещены любые последующие события, включая повтор terminal. Получатель отклоняет пропуск номера, повтор, чужой request_id, snapshot и поколение. При потере порядка он закрывает операцию и начинает новую после проверки доступа; автоматического воспроизведения потока нет.

Запись страницы содержит непрозрачный handle, отображаемое имя и тип `file` / `directory`. Имена ограничены 255 символами, не содержат разделителей и управляющих символов; `.` и `..` отклоняются семантической проверкой. Имена отображаются как текст, не интерпретируются как путь, HTML или команда. Handle внутри страницы уникален. Абсолютные пути и специальные файлы не выдаются.

Base64 проверяется не только регулярным выражением: требуется корректное каноническое кодирование и допустимая длина декодированных данных. Смещение ответа совпадает с запросом; сумма смещения и числа байт не превышает 2^53−1. Пустая порция без EOF запрещена. Следующая порция — новый запрос с новым ID и смещением, увеличенным на число полученных байт. Snapshot привязан к открытой версии файла; если адаптер не может подтвердить её неизменность, он завершает чтение как StaleHandle, а не смешивает версии файла.

## Пагинация и изменения каталога

`more=true` требует непустой страницы и непустого `next_cursor`. При `more=false` курсор пуст. Пустой каталог — пустая страница с `more=false`. Следующая страница запрашивается отдельным вызовом `list`; её предел может быть меньше прежнего, но не больше 128.

Курсор — случайный непрозрачный ключ закрытой таблицы хоста. Запись связывает его с полной привязкой разрешения, handle каталога, snapshot, позицией и сроком действия. Подмена, истечение срока, смена корня/каталога/поколения/ревизии grant и отзыв доступа запрещают продолжение. Порядок внутри снимка стабилен; страницы не пропускают и не повторяют позиции. Повтор того же курсора до истечения срока возвращает ту же страницу только при действующем доступе. Алгоритм снимка и кеш страниц ещё предстоит реализовать.

Хост выбирает либо ограниченный неизменяемый снимок, либо проверяемую версию перечисления. Изменение каталога или переполнение наблюдателя, из-за которого порядок нельзя подтвердить, инвалидирует снимок и его курсоры. До выдачи страницы активный вызов получает `invalidated`, затем `terminal/StaleHandle`; новый обход начинается с пустого курсора. Если страница уже выдана, её вызов может завершиться, но продолжение по инвалидированному курсору запрещено. Это события операции, а не долговременная подписка на изменения всего устройства. Отдельный watch API, поток имён изменённых файлов и автоматическое восстановление подписки в этот срез не входят.

## Отмена и отзыв во время чтения

Отмена идемпотентна: повтор для той же операции не создаёт второе завершение. После завершения она ничего не меняет. Отмена для чужой привязки отклоняется. До подтверждённой передачи terminal хост отменяет I/O, освобождает буферы и отбрасывает невыданный результат.

Проверка действующего разрешения и передача каждого результата сериализуются с отзывом. Если отзыв выиграл эту границу, данные не выдаются, даже когда чтение ОС уже завершено; допустим только `terminal/AccessRevoked`. Позднее повторное разрешение не оживляет операцию. При конкуренции отмены и отзыва до завершения приоритет имеет AccessRevoked. Смена профиля, пакета, поколения или ревизии grant действует аналогично отзыву для старого вызова.

Если страница/порция уже передана до отмены или отзыва, передачу нельзя отменить задним числом. Завершение всё равно имеет Cancelled/AccessRevoked вместо Completed; индекс и UI после отзыва удаляют зависимые результаты и игнорируют старое поколение. Terminal не содержит ранее прочитанных данных. Управляющий канал должен иметь резерв для завершения при заполненной очереди данных; при разрыве канала операция считается незавершённой и закрывается при переподключении, а не успешной. Реальная гарантия отмены зависшего системного I/O требует платформенной проверки.

## Проверка и границы

`tools/catalog_stream_model.py` моделирует допуск уже проверенного схемой события, последовательность, терминальные состояния и привязку курсора. Факты актуального доступа и снимка поступают от доверенного хоста, не от гостя. Модель не создаёт snapshot, не читает файлов, не кеширует страницы и не доказывает реальную сериализацию потоков ОС.

`tools/check_catalog_streams.py` проверяет строгие варианты схем, пределы страниц/порций, base64, имена, порядок, чужие привязки, курсоры, отмену до выдачи, отзыв после уже переданной страницы и отзыв во время чтения. Прежние проверки профилей и локальных разрешений сохраняются. Полный E01 остаётся открытым.
