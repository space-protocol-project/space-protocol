# P1: изменения прав и истечение доступа перед commit

Продолжение [транзакционного исполнителя](SPACE-PLUGINS-P1-MUTATIONS.md). Этот срез расширяет конкурентные проверки существующих блокировок и проверки срока доступа. Рабочий сервер по-прежнему не включает экспериментальный исполнитель; установка пакетов и клиентский транспорт не подключаются.

## Проверяемые границы

| Изменение | До транзакции записи | Во время защищённой записи |
| --- | --- | --- |
| ACL канала запрещает запись | Команда отклоняется, состояние остаётся пустым | Изменение ACL ждёт строку канала; после commit повтор команды запрещён |
| Участник блокируется | Команда отклоняется, состояние остаётся пустым | Изменение членства ждёт строку участника; после commit повтор запрещён |
| Владелец заменён другим участником | Прежний владелец теряет исключение owner и не записывает данные | Изменение owner_id ждёт настройки; после commit прежний владелец не получает квитанцию |
| Отозван родительский grant после завершённого полного сопряжения | Дочерняя сессия теряет доступ, записи нет | Отзыв ждёт grant, затем отзывает дочернюю сессию; повтор не проходит аутентификацию |

ACL и членство меняются через настоящие RPC ядра. Отдельного публичного RPC передачи владельца нет: тест изменяет owner_id и ревизию настроек через SQL, проверяя границу блокировки и вычисления роли. Это не приёмка пользовательского сценария передачи пространства.

Родительское устройство действительно проходит полный подписанный pairing и ClaimPairing, получает device.manage и делегирует дочернее устройство. Отзыв родителя подписывается корневым ключом и проходит через AuthService. Этот сценарий дополняет ранее проверенные recovery-parent, незавершённое pairing дочернего устройства и root rotation; он не заменяет их.

До commit изменения выполняются во время гостевого вызова. Проверяется факт успешного изменения прав, отказ команды и нулевые revision/data/receipts/outbox. Для второго порядка SQL-барьер удерживает вставку outbox внутри транзакции; через pg_stat_activity подтверждается, что изменение полномочий действительно ждёт блокировку. После снятия барьера остаются ровно одна ревизия, запись, квитанция и событие; отозванный повтор не вызывает гостя.

## Истечение срока без конкурентной записи

Проверяются четыре независимых срока: auth session, текущий grant, родительский grant и одобренное, но ещё не завершённое pairing дочернего устройства.

Во время гостевого вызова срок выбранной записи устанавливается на 500 мс вперёд по clock_timestamp() PostgreSQL. Команда проходит повторную проверку и входит в транзакцию записи ещё при действующем доступе. SQL-барьер удерживает вставку outbox; тест ждёт фактического истечения срока по часам БД, затем снимает барьер. Проверка непосредственно перед commit должна отказать, откатив данные, квитанцию, событие и ревизию.

Это проверяет различие между now() (время начала транзакции) и текущим временем, а не просто заранее просроченный токен. Настройка короткого срока выполняется SQL в тестовой БД; публичные правила выдачи сроков не меняются. Сохраняются прежние lock_timeout, statement_timeout, бюджет команды и лимиты WASM. Ожидание укладывается в существующий лимит блокировки.

## Границы приёмки

Гостевой план в новых сценариях фиксирован; транзакции, сессии, подписанные запросы и RPC ядра настоящие. Прежние тесты изолированного WASM остаются в общем P1 workflow. Повторные прогоны этих управляемых гонок не являются нагрузочным benchmark, доказательством отсутствия всех deadlock или проверкой произвольного порядка нескольких одновременных административных операций.

Совместная авария сервера/worker проверена в [следующем срезе](SPACE-PLUGINS-P1-WORKER-CRASH.md). Отказы БД и неопределённый COMMIT описаны в [следующем отчёте](SPACE-PLUGINS-P1-DATABASE-FAILURE.md). Остаются длительная смешанная нагрузка, контракт ошибок и повторов клиента, рабочая доставка получателям с ACL, lifecycle и очистка. P1 целиком не закрыт.
