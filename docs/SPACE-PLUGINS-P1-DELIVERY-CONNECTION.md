# P1: общее окно HTTP/2 и несколько медленных получателей

6 ноября 2026 года. Продолжение [окна отдельного потока](SPACE-PLUGINS-P1-DELIVERY-FLOW.md) для прямого `ExtensionP1ManagedService.NewDeliveryHandler`.

## Общее окно соединения

Настоящее TLS-соединение согласует h2; окно каждого потока увеличено до 1 MiB. Служебный ответ тестового стенда передаёт ровно 65535 байт, расходуя исходное общее окно соединения. Клиент читает кадры, но не отправляет WINDOW_UPDATE для соединения. Этот служебный путь не является API расширения: он только создаёт воспроизводимое состояние транспорта, не меняя лимиты ответов и рабочую логику обработчика расширений.

Два следующих настоящих запроса расширения получают заголовки, но не могут получить тело при исчерпанном общем окне. Третье, отдельное TLS-соединение должно вернуть полный документ. Счётчик обработчиков подтверждает, что обе медленные отправки в этот момент ещё активны: завершение быстрого запроса после их тайм-аутов не считается доказательством независимости.

Отзыв ACL запускается через API ядра и наблюдается в pg_stat_activity как ожидающий SQL-блокировку. Обе задержанные отправки должны завершиться RST_STREAM по штатному сроку записи без тела и успешного END_STREAM; отзыв после этого завершается. WINDOW_UPDATE общего окна позволяет отправить следующий запрос по тому же соединению и получить NotFound по новым правам. GOAWAY запрещён проверкой: завершение всего соединения не подменяет очистку отдельных потоков.

## Два независимых медленных клиента

Два отдельных TLS-соединения задают нулевые окна потоков и удерживают по одному ответу. Третье соединение получает полный документ, пока оба первых обработчика активны. Отзыв ACL ждёт SQL-блокировки; после обоих тайм-аутов он завершается. На каждом из прежних соединений новый поток с увеличенным окном получает NotFound по обновлённому ACL.

Runtime новых сценариев управляемый тестовый; PostgreSQL, авторизация, сериализация, SQL-блокировки, TLS и HTTP/2 настоящие. Обёртка HTTP только считает активные обработчики и не задерживает запись, не заменяет writer и не вводит ошибки.

## Приёмка

Оба новых теста обязательны по пять раз с race detector и повторяются в изолированной выборке. Пропуски и ошибки Delivery-выборки запрещены. Прежние проверки окна потока, TLS, отмены, COMMIT, квитанций, WASM и аварий PostgreSQL сохраняются.

[Полный GitHub CI 42220403285](https://github.com/space-protocol-project/space-server/actions/runs/42220403285) успешен для `4b862282c106ad453b69963ec55e6466a856bf39`: **2/2 задания**, core и database-faults. Оба новых теста прошли по пять раз с race detector и по одному разу в изолированной выборке. Delivery — 211 записей pass без skip/fail; изолированный этап — 278 pass без skip/fail. Общие test/race — по 820 pass и 83 ожидаемых skip специальных стендов; worker-crash — 21 pass, аварии PostgreSQL — 26 pass. Числа включают родительские тесты и итоги пакетов, а не только независимые сценарии.

Прошли vet, mod verify и govulncheck. Полный workflow успешен с первой попытки. Проблем рабочей логики в проверенных случаях не обнаружено, исправления не потребовались. Локальные Windows test/vet подтвердили компиляцию и анализ, но без тестовой БД не являются приёмкой сетевых сценариев. Group/Publish/Versions сохраняют отдельные стенды и здесь не переаттестуются.

[Исходные журналы и метаданные](p1-results/2026-11-06-delivery-connection/) сохранены без изменения байтов; [SHA256SUMS](p1-results/2026-11-06-delivery-connection/SHA256SUMS) фиксирует их целостность.

## Границы

Два одновременных медленных клиента — функциональная проверка, не массовая нагрузка и не доказательство глобальной квоты. Заполнение TCP-буферов ОС при остановке чтения сокета, большое число соединений, исчерпание пула БД, глобальное ограничение памяти/числа отправок и внешние прокси остаются открытыми. Клиент стенда продолжает читать служебные кадры; ограничивается выдача HTTP/2-кредитов, а не скорость TCP.

Прямой обработчик ещё не подключён автоматически к рабочему серверу; прежний gRPC-мост и нативный LPAC-транспорт также остаются открытыми. P1/E03 целиком не закрыты.
