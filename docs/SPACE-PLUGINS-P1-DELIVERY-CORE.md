# P1: снимок допуска к возврату результата из ядра

6 ноября 2026 года. Продолжение [локальных поколений и снимка вызова](SPACE-PLUGINS-P1-WINDOWS-IPC.md). Это интеграция в экспериментальную `ExtensionP1ManagedService`, не включение расширений в рабочий сервер.

## Контракт

До запуска вызова оболочка получает из PostgreSQL единый снимок: Principal настоящей сессии, AccessStamp существующей проверки ACL, installation, generation, revision и вид доступа (read/write). Состояние установки должно быть enabled, поколение — совпадать с владельцем управляющей оболочки. Чтение использует существующую `extensionP1PrincipalTx` и FOR SHARE строки установки в той же транзакции. Никаких новых таблиц, собственных паролей или альтернативной политики ACL не вводится.

Снимок хранится только в контексте доверенного вызова. После QueryExtension, ExecuteExtensionCommand и GetExtensionMutationContext выполняется повторная авторизация и чтение реестра. Principal, установка, поколение, ревизия и тип доступа должны совпасть. При отказе возвращается ошибка без объекта результата. Отсутствующий снимок и подмена instance отклоняются.

Ревизия обязательна: совпадение состояния enabled и поколения не означает, что разрешение оставалось неизменным. Изменённая ревизия установки или AccessStamp после отзыва и восстановления ACL отсекает прежний вызов. Новый вызов получает свежий снимок. Состояние disabled или чужое поколение запрещает запуск гостя ещё на входе.

## Транзакции и границы

Транзакция снимка завершается до WASM; блокировки не удерживаются во время вычисления. Проверка результата также завершается до возврата RPC. Это барьер допуска к возврату, а не атомарная отправка сетевых байтов: отзыв после последней проверки всё ещё может пересечь сериализацию/доставку RPC. Связь с транспортным барьером deliveryGrant требует отдельного адаптера.

Команды сохраняют прежнюю проверку авторизации и lifecycle перед COMMIT. Новая проверка результата её не заменяет. Если ExecuteExtensionCommand успешно завершён, но снимок перед возвратом изменился, оболочка возвращает Unavailable/delivery_not_confirmed без документа. PermissionDenied/FailedPrecondition здесь недопустимы: текущая политика повторов считает их определённым отказом. Unavailable сохраняет неопределённость; без доверенного окна повторов действие — stop, затем сверка квитанции после восстановления доступа. Возможен только прежний защищённый повтор того же запроса в доверенном окне, не новая команда. Reconcile сохраняет прежнюю отдельную авторизацию и доступность при выключенной установке.

Постоянное поколение установки, локальное поколение разрешения транспорта и AccessStamp сессии — разные величины. Они не объединены в один переносимый токен. Схема хранения не меняется, проверяются существующие значения реестра. Полная интеграция клиентского локального профиля, транспорта LPAC и перезапуска остаётся открытой.

Backend мутаций сохраняет свой существующий снимок до WASM и сравнение перед COMMIT. Снимок внешней управляемой оболочки добавлен для допуска и возврата; передача именно этого снимка в COMMIT-барьер отдельным контрактом ещё не реализована. Общая функция авторизации не означает общий объект снимка на всех границах.

## Проверки

- Настоящий RPC использует управляемый тестовый Runtime; в его callback тест изменяет постоянную ревизию, состояние или поколение установки. Готовый результат не возвращается. Новый вызов с новой ревизией проходит; disabled/чужое поколение не вызывают Runtime. Новые инъекции не выполняют WASM: настоящий изолированный WASM проверяется прежними регрессионными сценариями этого workflow.
- Настоящая сессия участника получает снимок через begin. Logout делает его недействительным.
- ACL запрещается и затем возвращается к прежним разрешениям через API ядра. Старый снимок отвергается, новый проходит.
- Отложенный trigger тестовой БД меняет ревизию установки при COMMIT. Команда сохраняет эффект, квитанцию и outbox ровно один раз, но ответ блокируется с Unavailable. DecideRetry сохраняет unknown, Reconcile подтверждает квитанцию без повторного вызова тестового Runtime. Это инъекция границы COMMIT, не новый публичный API.
- Полный workflow ядра повторяет существующие проверки авторизации, lifecycle, COMMIT, квитанций, outbox, архивов, аварий worker и PostgreSQL, включая настоящий изолированный WASM.

Изменения строк реестра в первом тесте — намеренная имитация записи другим владельцем/процессом, а не новый публичный API изменения установки. Тест ACL использует публичный API. Итоговая приёмка приведена ниже. Начальный прогон 42190753393 отменён после добавления отдельных проверок сессии и восстановления ACL.

[Диагностический прогон 42190902579](https://github.com/space-protocol-project/space-server/actions/runs/42190902579) подтвердил три сценария реестра и аварии PostgreSQL, но выявил несогласованность кодов ошибок: общий helper denied() возвращал Unauthenticated также для изменившегося снимка ACL. Проверка изменившегося/отсутствующего снимка теперь явно возвращает PermissionDenied; отозванная сессия сохраняет Unauthenticated. Первый прогон не считается приёмкой. Новые тесты перенесены в начало workflow, повторяются пять раз с race detector и проверкой отсутствия skip/fail.

P1/E03 остаются открытыми. Следующая граница — согласование постоянного снимка с фактической отправкой ответа. Порядок «COMMIT выполнен, доставка запрещена» проверяется этим срезом через квитанцию.

В [42192319937](https://github.com/space-protocol-project/space-server/actions/runs/42192319937) код прошёл новые тесты, полные test/race, vet/mod verify/govulncheck и нативные сценарии, но workflow завершился ошибкой проверки отсутствия пропусков. Старый общий селектор изолированного этапа захватил группы Group/Publish/Versions, добавленные после настройки этого workflow; им требуются другие WASM-образцы. Область этапа явно ограничена остальными TestExtensionP1: перечисленные три группы принимаются в отдельных plugin-p1-groups.yml, plugin-p1-publish.yml и plugin-p1-versions.yml. Запрет пропусков для выбранных тестов сохранён, добавлено обязательное присутствие новых Delivery-тестов. Группы миграций/версий этим отчётом не переаттестуются. Второй прогон не является итоговой приёмкой.

Прогон 42195345436 отменён после добавления проверки неоднозначного исхода команды после COMMIT. Он не считается приёмкой.

## Итоговая приёмка

[Полный workflow 42195656806](https://github.com/space-protocol-project/space-server/actions/runs/42195656806) успешен для `b5ad90e94ba9872a4df99d863a332e8dfff51a82`: **2/2 задания**, core и database-faults. Новые шесть сценариев выполнены по пять раз под race detector, без skip/fail. RegistrySnapshot, AuthoritySnapshot и CommittedCommand также прошли в общих test/race и изолированном этапе.

Общие test и race дали по 786 записей pass и 83 ожидаемых skip для стендов, которым требуются специальные fixtures/окружение. Изолированная выборка — 244 записи pass без skip/fail; worker-crash — 21 pass, аварии PostgreSQL — 26 pass. Числа включают родительские тесты и итоговые записи пакетов, не являются числом независимых сценариев. Также прошли vet, mod verify, govulncheck, проверки сессий/ACL, блокировок COMMIT, lifecycle, квитанций и outbox.

Тест CommittedCommand подтвердил Unavailable при запрещённом возврате, unknown в политике повторов и подтверждённую квитанцию через Reconcile: данные/квитанция/outbox сохранились в одном экземпляре, Runtime вызван один раз. Итоговый workflow выполнен целиком, без повторного запуска отдельных упавших заданий.

[Исходные журналы и диагностика](p1-results/2026-11-06-delivery-core/) сохранены с [SHA256SUMS](p1-results/2026-11-06-delivery-core/SHA256SUMS). Это приёмка допуска к возврату RPC и обработки неопределённого исхода команды; транспортная атомарность и единый снимок на всех границах остаются открытыми. Релиз не выпускается.
