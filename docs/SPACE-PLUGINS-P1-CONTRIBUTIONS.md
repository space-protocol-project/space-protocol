# P1: реестр элементов Обзора и разделов расширений

11 ноября 2026 года. Реализован общий реестр объявленных элементов (`contributions`) для экземпляра расширения и экспериментальный API его чтения. Источник — проверенный manifest регистрации; перечисление не запускает WASM. Это часть E01/E06, а не завершение P1 или подключение навигации рабочего приложения.

## Контракт и совместимость

В `docs/extensions/p1/manifest.schema.json` добавлено необязательное поле `contributions`: до 32 элементов с точными полями `id`, `kind`, `title`, `query`. `kind` принимает `overview` или `section`. ID уникален в manifest; query обязан ссылаться на объявленный запрос, а не команду. ID и query ограничены 64 ASCII-символами. Заголовок содержит 1–8 локалей, обязательный английский fallback, до 120 Unicode-символов на перевод; пустые строки и управляющие символы запрещены. Неизвестные поля, неверный регистр ключа, null, повторяющиеся ID и отсутствующие схемы отвергаются. Сохраняется общий предел manifest 16 КиБ.

Отсутствие поля сохраняет прежний неявный элемент `overview`, если такой запрос объявлен. Явный `[]` означает отсутствие элементов и сохраняется при сериализации; `null` недопустим. Прежние 12 обязательных полей не изменены. Старый строгий host может отклонить новое необязательное поле: это экспериментальный кандидат P1, не обещание совместимости стабильного v1.

Общий пример — `docs/extensions/p1/manifest-contributions.json`; его точные копии в Go manifest и SDK сверяются CI. Он объявляет два элемента: `summary` в Обзоре и `details` как раздел, запросы с такими же именами и команду `refresh`. Произвольные объявленные имена больше не ограничены парой `overview`/`acknowledge`. Этот исходный manifest v1 остаётся stateless, `data_schema=1`, без permissions. Последующий [manifest v2](SPACE-PLUGINS-P1-MANIFEST-V2.md) связывает явно объявленные мутации и capabilities со схемами результатов и событий.

## API

`ExtensionP1Service.ListExtensionContributions` принимает обязательный `instance_id` и необязательный фильтр `kind` (все / Обзор / раздел). Возвращает список с ID, видом, переводами заголовка и именем query, отсортированный по ID, а также 32-байтовый `registry_sha256`. Предел 32 делает пагинацию ненужной в этом прототипе. Пустой instance не означает перечисление всех установок.

Digest идентифицирует неизменяемую регистрацию, включая manifest, схемы и WASM; одинаков для разных фильтров. Это не подпись издателя, не разрешение доступа, не квитанция и не замена повторной авторизации. Возвращаемые карты переводов не разделяются с внутренним состоянием: изменение результата вызывающим кодом не меняет следующий ответ. Исходная регистрация также копируется при создании dispatcher.

Данные элемента читаются существующим `QueryExtension` по объявленному query. Метаданные не принимают HTML, URL или произвольные компоненты. `section` здесь объявляет самостоятельный раздел; `section.v1` остаётся контейнером декларативного документа. Объединение элементов разных установок, выбор страницы и маршруты рабочего приложения относятся к P2.

Добавлены Go/gRPC/Connect, Dart/Connect и OpenAPI-контракты. Генерация выполнена GitHub CI, без ручной правки выходных файлов. Реестр выводится из неизменяемой регистрации; отдельной новой таблицы PostgreSQL не вводится. Состояние установки, поколения и привязки продолжают принадлежать существующему постоянному реестру lifecycle. Новый архивный цикл в этом шаге не заявляется.

## Сессии, ACL и доставка

Чтение требует настоящей сессии и права чтения канала. Dispatcher проверяет допуск до и после подготовки списка; управляемая оболочка дополнительно проверяет жизненный цикл и снимок доставки. Выключенная установка недоступна. Читатель может получить элементы и выполнить query, но не получает права на `refresh` только из-за наличия кнопки в документе.

Прямой Connect-обработчик включает новый RPC в существующий барьер фактической отправки. Смена ACL, завершение сессии или ревизии реестра после подготовки ответа блокирует выдачу старого тела. Проверены HTTP/1, TLS HTTP/1 и TLS HTTP/2. Forwarder прежнего gRPC-моста добавлен для полноты контракта; атомарность его сетевой отправки этим стендом не доказана.

Проверены истечение сессии, отзыв устройства, смена epoch, push-only сессия, недостаточные scopes и блокировка участника. Отказ не возвращает метаданные и не запускает WASM. Скрытый канал даёт NotFound, недействительная сессия — Unauthenticated, ограничения scopes/членства — PermissionDenied; выключение или смена регистрации — FailedPrecondition. Неизвестный экземпляр сохраняет существующий отказ управляемой оболочки Unauthenticated, неверный enum — InvalidArgument.

SDK-пример реально исполняется отдельным WASM-worker: оба запроса возвращают ограниченный декларативный документ, команда владельца использует явный `effect=NONE`. Проверено отсутствие новых данных, квитанций, outbox и ревизий от такой команды. Пример возвращает постоянный документ и не реализует прикладную логику Чатов или других расширений.
