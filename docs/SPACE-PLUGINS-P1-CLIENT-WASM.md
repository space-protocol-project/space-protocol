# P1 — исполнение установленных клиентских WASM и API каталогов

Продолжение [установщика из Git](SPACE-PLUGINS-P1-GIT-INSTALL.md). Добавлен внутренний путь `SpaceCatalogRuntime.invoke(session, instance, root)` → владелец установок → посредник разрешений → отдельный supervisor → защищённый ProcessHost. Ограниченный срез принят 5 ноября 2026 года по полной матрице GitHub CI; границы платформ приведены ниже.

## Граница платформ

| Платформа | Исполнение |
| --- | --- |
| Windows | Штатный ProcessHost: назначение Job до запуска worker, лимиты памяти и CPU, закрытие дерева процессов |
| Linux, обычное приложение | Отказ до передачи WASM: рабочего привилегированного launcher для приложения ещё нет |
| Linux, отдельный привилегированный CI-стенд | Существующий ProcessHost с cgroup v2 и worker под UID/GID 65534 |
| macOS | Отказ до передачи WASM: общий гарантированный бюджет существующего VM-прототипа остаётся открытым |

Отдельный обычный процесс или Dart isolate не подменяют защищённый ProcessHost. Нет автоматического sudo, запуска без квот или перехода к выполнению в процессе Flutter. Успех отрицательного сценария Linux/macOS означает корректный отказ, а не готовность исполнения на этих настольных платформах.

Повторно используется модуль `space-server/experiments/extensions`, закреплённый на `b9d2c05eb8b0f22424100bcc85bf94b0123e617d`. Его версии wazero 1.12.0 и x/sys 0.44.0 сохранены вместе с проверенной реализацией изоляции; обновление этого основания не совмещается с клиентской интеграцией. Go-модуль и контрольные суммы закрепляются в `native/space_client_wasm`.

## Исполнение и доверие

`InstalledExtensionsCubit` регистрирует исполнитель в `SpaceCatalogRuntime`, владеет единственным активным заданием и при остановке отменяет и дожидается его завершения. Гость не выбирает сессию, установку, экземпляр или корень. Все четыре привязки задаёт доверенный вызывающий компонент приложения.

До загрузки пакета проверяются непрозрачная локальная сессия, включённое состояние экземпляра и активное разрешение `device.catalog.read` на выбранный корень. Затем повторно читаются защищённая квитанция и точные байты принятого пакета, сверяются SHA-256, схема и возможности манифеста. Файл повторного чтения также сверяется с digest, чтобы замена между чтениями не подменила исполняемые байты.

Для исполнения допускается только контейнер `space.client.bundle.p1`, клиентский манифест с поддерживаемым ABI и модуль не больше 64 КиБ. Это более узкий предел исполнения P1, чем предел хранения Git-установщика. Предварительная структурная проверка запрещает start и imports; полноценная проверка WASM-инструкций происходит внутри защищённого worker, а не во Flutter или supervisor.

`space-client-wasm` собирается вместе с приложением и проверяется по контрольной сумме перед запуском. Windows/Linux используют исполняемый файл и sidecar в каталоге приложения; macOS — код в `Contents/MacOS`, checksum в `Contents/Resources`. Это доверенный компонент поставки, не исполняемый файл из Git-пакета.

## Кандидат клиентского ABI

Внутри `space_client_p1` используется обмен шагами через JSON. Экспорты заимствуют проверенную форму `space_alloc(i32)->i32`, `space_free(i32,i32)` и `space_handle(i32,i32)->i64`; память экспортируется как `memory`. Результат упакован как pointer в старших 32 битах и length в младших. Вызовы каталога не являются WASI или прямыми нативными imports.

Каждый шаг создаёт новый worker и новый экземпляр WASM. Первое сообщение ядра — `{"event":"start"}`. Гость возвращает одно из точных сообщений:

```json
{"op":"list","limit":1,"cursor":null,"state":null}
```

Ответ ядра содержит `event: list`, прежний `state`, `entries` из пар `name`/`handle` и `next`. Запрос следующей страницы передаёт `next` как `cursor`.

```json
{"op":"read","handle":"opaque-handle","offset":0,"limit":64,"state":null}
```

Ответ содержит `event: read`, прежний `state`, `bytes` в base64 и `eof`. Файловый посредник проверяет непрозрачный handle; произвольный путь вместо handle не открывает файл.

```json
{"op":"done","value":{"example":"bounded JSON result"}}
```

`done` завершает задание. Неизвестная операция, лишние или повторные поля и превышение размеров отклоняются. Гость не может добавить `root`, `instance`, путь ОС или команду запуска. `state` — ограниченное продолжение, а не сохранённая память или локальная база данных. Это кандидат P1, не стабильный SDK.

## Разрешения и отмена

Внешняя аренда чтения удерживает исходную сессию, экземпляр, корень и поколение на всё задание. Каждый файловый запрос проходит также через штатные `listCatalog` / `readCatalog` и собственную аренду. Проверка повторяется после асинхронной загрузки, после ответа WASM, после ответа файлового процесса и перед выдачей результата.

Отзыв, выключение, карантин, блокировка или закрытие хоста закрывают каталог и уведомляют worker об отмене. Закрытие stdin отменяет контекст supervisor; ProcessHost завершает worker и очищает ресурсы. На ошибке/тайм-ауте доверенный клиент также завершает supervisor. Успешный старый ответ не становится разрешённым после повторной выдачи доступа: исходная аренда уже отменена.

Для клиента резервируется один слот. Новый вызов во время активного задания отклоняется; слот освобождается после остановки процесса. Миграции сохраняют прежнее правило отказа при активных чтениях; revoke/disable разрешены и отменяют работу. Задание не имеет полномочия выдавать или возобновлять разрешения.

Ограничения: до 8 шагов, 16 КиБ JSON, 32 записи страницы, 4096 байт порции файла; через 10 секунд задание отменяется и поздний результат запрещён. Освобождение файлового посредника может дополнительно ждать его собственного ограниченного запроса. ProcessHost ограничивает worker 256 МиБ, группу 512 МиБ, память WASM четырьмя страницами; вызов WASM имеет 100 мс, компиляция и процесс — 2 секунды. Включён интерпретатор. Ограничения ресурсов процесса не являются доказательством защиты от произвольной уязвимости самого WASM-движка; остальные критерии E03 остаются обязательными.

## Приёмка CI

Workflow `plugin-p1-client-wasm.yml` собирает переносимые синтетические модули из `testdata/catalog.c`: перечисление и чтение через ядро, бесконечный цикл и trap. Настоящие ключи пользователя и данные устройства не используются.

Целевые Flutter-тесты проходят настоящий Git-установщик с подписанным тестовым пакетом и подменённым Git-транспортом, постоянный реестр, сессии и согласие на каталог. Проверяются отказ до запуска без разрешения, чужие экземпляры/корни, отмена позднего результата, отзыв во время чтения, запрет лишних полномочий, квоты и повторная проверка пакета. На Windows отдельный сценарий соединяет настоящий WASM worker с настоящим файловым процессом. Linux/macOS проверяют отказ неподдерживаемой настольной конфигурации. Отдельная Go-проверка Linux запускает защищённый worker в cgroup под управлением root только на одноразовом runner.

Сборки Inno Setup / `.run` / DMG проверяют поставку обоих процессов, контрольные суммы и регрессию установки/повторного открытия/повреждения пакета. Нативная аутентификация и chooser в этом сценарии остаются фикстурами предыдущего стенда. Реальный GitHub-транспорт принят предыдущим срезом; этот CI не заменяет его проверку.

Рабочий Linux launcher без повышения прав самого Flutter, защищённый macOS-хост, мобильные платформы, стабильный SDK и ABI, хранение состояния гостя, UI запуска и отображение библиотеки игр, производительность многократной компиляции и полная приёмка E01–E07 ещё открыты. Этот срез предоставляет внутренний исполнитель приложения; сам по себе он не добавляет готовый пользовательский раздел «Игры» и не завершает P1 или 0.9.0.
