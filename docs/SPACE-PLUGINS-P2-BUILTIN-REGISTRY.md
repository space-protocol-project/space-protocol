# P2: встроенный реестр установок и адаптеры

Продолжение: [команды и рабочий RPC](SPACE-PLUGINS-P2-BUILTIN-COMMANDS.md). Ниже сохранена приёмка первого среза; её ограничения по отсутствию команд и RPC устранены последующим срезом.

11 ноября 2026 года. Первый серверный срез P2: постоянные метаданные четырёх встроенных установок, экземпляры каналов и внутренние адаптеры чтения. **Полный GitHub CI успешен**, оба задания завершены на закреплённой ревизии. macOS E03/E06 остаются отложенными; релиз не выпускается.

## Граница реализации

Миграции PostgreSQL 46 → 47 → 48 добавляют `builtin_extension_installations` и `builtin_extension_instances`, затем согласование служебной смены view. Это отдельный профиль совместимости `legacy.p2`, а не внешний WASM-пакет, подписанный manifest или публичная установка. Данные четырёх функций не переносятся. Таблицы экспериментов `extension_p1_*` не становятся рабочим реестром автоматически.

| Установка | Пакет | Прежний view | Внутренний адаптер |
| --- | --- | --- | --- |
| `builtin:chat` | `space.chat` | `chat` | `Store.List` для открытого чата; `Store.ListMlsEnvelopes` для MLS |
| `builtin:voice_room` | `space.rooms` | `voice_room` | `VoiceService.GetVoiceRoom` — состояние комнаты |
| `builtin:forum` | `space.discussions` | `forum` | `Store.ListForumThreads` — первые 20 тем |
| `builtin:feed` | `space.feed` | `feed` | `Store.ListFeedPosts` — первые 20 публикаций |

Каждая база пространства получает четыре встроенные установки. Одна установка имеет несколько экземпляров. Их идентификатор — `builtin:<channel_id>:<view_id>`; область уникальности — база конкретного пространства. Название, позиция, архивность и ACL читаются из текущего Channel, а не копируются в независимое состояние. В существующей SQL-модели один view на канал; новый реестр хранит явную пару `(channel_id, view_id)` и не объявляет поддержку нескольких физических коллекций внутри прежнего канала.

Ограничения БД связывают установку с точным типом view, экземпляр — с парой channel/view. Подмена `chat` на `feed` через ссылку на другую установку запрещена. При миграции заполняются экземпляры уже существующих каналов. Триггер добавляет экземпляр при вставке нового канала в той же транзакции: откат создания откатывает и метаданные. Внешний ключ удаляет экземпляр вместе с каналом. Переименование и архивирование не меняют ID; старые запреты повторного использования удалённого channel ID сохраняются.

Это метаданные совместимости, не второй путь записи сообщений, тем или публикаций. Прежние RPC остаются единственными пользовательскими путями записи на этом шаге. Метаданные являются частью базы PostgreSQL; новая версия схемы не обещает запуск старого runtime поверх обновлённой базы.

При прежней служебной смене типа view триггер заменяет старую привязку новой в той же транзакции. Ссылка на пару channel/view проверяется при COMMIT; несогласованная пара не публикуется. При rollback остаётся старый экземпляр, при успешном изменении старый ID не разрешается. Пользовательское содержимое не удаляется. Это не новый публичный API смены типа и не разрешение на перенос данных между функциями.

## Допуск и чтение

`Store.BuiltinSections` возвращает неархивные разделы с текущим разрешением ACL на чтение канала. `Store.BuiltinSection` разрешает ID заново перед открытием. Обе операции требуют настоящий авторизованный context: токен, совпадение principal, действующий grant/session и членство. Анонимный служебный обход старых методов здесь запрещён. Проверки сессии и членства удерживаются в транзакции вместе с чтением каталога; текущий ACL проверяется существующим ядром. Дополнительные условия операции, например участие конкретного устройства в MLS, проверяет прежний сервис при открытии: наличие раздела в списке не заменяет этот допуск.

`internal/builtin.Registry` содержит закрытый набор четырёх адаптеров. `Open` не принимает произвольный channel или имя обработчика: канал берётся из разрешённого экземпляра. Адаптер вызывает прежний сервис, который повторно проверяет свои права. Отозванный доступ между перечислением и следующим открытием не сохраняется в кеше. Сбой службы комнат возвращает `Unavailable`, не подменяется пустой комнатой. Ключи MLS, медиатранспорт и права произвольного WASM гостю не передаются.

Результаты — типизированные внутренние protobuf-ответы существующих сервисов. Это ещё не новый сетевой API, JSON-контракт внешнего SDK или декларативная страница. Барьер фактической сетевой отправки и согласованный общий снимок раздела/содержимого не объявляются реализованными этим внутренним вызовом; рабочий транспорт — следующий блок P2. Между разрешением раздела и чтением содержимого действуют две транзакции, а прежний сервис заново проверяет допуск.

## Проверки

Workflow `plugin-p2-registry.yml`: PostgreSQL 17.11 на Ubuntu 24.04, отдельная тестовая база/схемы, Go из `go.mod`, целевые тесты с `-race` в пяти повторениях и отдельная полная обычная/race-регрессия ядра, `go vet`, `go mod verify`, `govulncheck`.

| Проверка | Что подтверждает |
| --- | --- |
| `TestBuiltinRegistryAdapters` | Четыре настоящих адаптера, сообщения/темы/публикации, protobuf-паритет чтения, состояние комнаты; стабильные ID после повторного открытия Store |
| `TestBuiltinRegistryAuthority` | Настоящий вход, скрытие ACL после первого чтения, отсутствие скрытого раздела в списке, неверный view, отсутствие сессии и отзыв grant |
| `TestBuiltinRegistryVisibility` | Два экземпляра одной установки, архивирование, отказ доступа с сессией другой базы, запрет несовместимого типа установки |
| `TestBuiltinRegistryTransaction` | Метаданные видны внутри создающей транзакции, полностью исчезают после rollback; удаление канала удаляет экземпляр |
| `TestBuiltinRegistryUpgrade/46`, `/47` | Миграция обеих прежних схем в 48, сохранение идентичности и существующего контрольного снимка пользовательских таблиц, полный backfill каналов и четыре установки |
| `TestBuiltinRegistryViewChange` | Смена view, согласованная замена привязки, COMMIT/rollback и сохранность прежней публикации |
| `TestBuiltinRegistryMLS` | Прежний MLS-сервис, равенство protobuf-ответов с конвертами, Welcome только адресату, отказ зарегистрированному устройству вне группы |

Первый запуск [43074300104](https://github.com/space-protocol-project/space-server/actions/runs/43074300104) не принят: целевые тесты прошли, полная регрессия обнаружила несовместимость с `TestParticipantFollowsReaderMLSAndChangedCursor`. Его служебное изменение feed → MLS chat блокировалось новым внешним ключом. Исправление внесено миграцией 48 без изменения уже отправленной миграции 47. Промежуточный `43075393164` отменён после добавления проверки обновления версии 47; он не используется как приёмка.

Следующий промежуточный `43075576974` отменён после добавления обязательного MLS-пути чтения; он также не является итоговой приёмкой. При сверке исходников обнаружено, что прежний `Store.List` правильно запрещает чтение MLS как открытого текста. Адаптер теперь выбирает `ListMlsEnvelopes` по доверенным метаданным канала; существующие проверки членства и фильтрация Welcome не обходятся. Криптографическая обработка MLS и клиентское хранение ключей не менялись.

Итоговый workflow: [43076023954](https://github.com/space-protocol-project/space-server/actions/runs/43076023954), сервер `44cdfc2cb142a733710b324b30c791b598589b00`. Проверяемые файлы: `internal/builtin/registry.go`, `internal/postgres/builtin_extensions.go`, `builtin_extensions_test.go`, `builtin_view_changes_test.go`, `builtin_mls_test.go`, миграции `047_builtin_extensions.sql` и `048_builtin_view_changes.sql`, список миграций `store.go`. Клиентский Dart и protobuf не менялись.

Повторное открытие Store не называется аварийным завершением ОС или полным архивным восстановлением. Новый ZIP/физический round-trip реестра и выпускная межплатформенная матрица не проверяются этим целевым набором. Голосовая проверка читает настоящую службу, но не устанавливает новый WebRTC-звонок. Локальные тесты без PostgreSQL подтверждают сборку; приёмка опирается на GitHub CI.

Существующий ZIP-импорт (`internal/home/portable.go`) требует точного совпадения версии схемы. Поэтому успешное обновление открываемой базы 46/47 → 48 не доказывает прямой импорт ZIP прежней версии в новый runtime. Совместимость старых архивов, полный round-trip новых метаданных и возврат на прежний runtime остаются отдельными обязательствами до завершения паритета P2; этот срез их не закрывает.

## Следующие блоки

- Перевести клиентскую навигацию и Обзор на contributions, независимые ошибки и кеш пользователя, сохранив старый overview API.
- Подключить рабочий RPC и транспорт к внутренним адаптерам; добавить команды и пагинацию с прежними ограничениями и ключами повторов. Новый Registry пока не регистрируется как публичный сетевой сервис.
- Проверить один путь записи старого RPC и нового dispatcher, матрицу старых/новых клиентов и серверов и полный поведенческий паритет.
- Проверить резервное копирование новых метаданных и переход архивов прежних схем; не считать обычное повторное открытие базы архивной приёмкой.
- Публичные пакеты/установщик и полный lifecycle — P3; перенос пользовательских данных и функций в четыре внешних репозитория — P4/P5.

Общий пункт подключения всех возможностей четырёх функций остаётся открытым до команд, транспорта и паритета. Этот срез закрывает постоянный серверный реестр и внутреннее чтение, не весь P2. Отложенные macOS E03/E06 сохраняются отдельно; выпуск 0.9.0 не выполняется.
