# P1 / E01: межплатформенный перенос ZIP с реестром и аудитом

Статус на 1 ноября 2026 года: межплатформенный перенос прошёл GitHub CI во всех шести направлениях. Этот блок продолжает [архивное восстановление на каждой ОС](SPACE-PLUGINS-P1-REGISTRY-ARCHIVE.md); полный E01 остаётся открытым.

## Как проверяется перенос

Три независимых задания `plugin-p1-transfer.yml` собирают домашний runtime на Ubuntu 22.04, Windows 2025 и macOS 15. Каждое создаёт настоящее временное пространство PostgreSQL с владельцем, устройством и сессией. После сохранения пяти установок, десяти записей аудита, одной команды и трёх событий outbox сервер останавливается и создаёт ZIP через `ExportPortable` / `pg_dump`.

Каждая исходная ОС создаёт два архива: с полной квитанцией и с удалённым по сроку хранения телом квитанции. Удаление тела сохраняет ключ команды. В отдельные задания восстановления передаются готовые ZIP; каждое задание импортирует архивы двух других ОС через `ImportPortable` / `pg_restore` в новую базу. Все четыре варианта на принимающей ОС повторяются три раза с `-race`.

Таким образом проверяются шесть направлений: Linux → Windows, Linux → macOS, Windows → Linux, Windows → macOS, macOS → Linux, macOS → Windows. Выполнены 36 конечных сценариев восстановления. Тест запрещает использовать архив собственной ОС или другой ревизии сервера. SHA-256 ZIP сверяется с источником до и после каждого импорта; журналы связывают источник, назначение, архитектуру, вариант и контрольную сумму.

Runtime передаётся только между заданиями одной ОС в TAR с проверкой контрольной суммы и путей. Между разными ОС переносятся данные ZIP, а не физические файлы PostgreSQL или исполняемые файлы. Одноразовые ключи и токены тестового пространства создаются внутри CI; они нужны для повторного входа и проверки отзыва прежней сессии. Передача этих тестовых данных согласована пользователем, срок хранения временных артефактов — один день. В постоянные материалы отчёта входят только результаты проверок и сведения о запусках.

## Проверяемые инварианты

- Реестр v2 сохраняет пять состояний и ревизий: `enabled/2`, `disabled/1`, `disabling/3`, `quarantined/2`, `removed/2`. Полный снимок сравнивается с исходным, за исключением отозванного поколения оболочки.
- Все десять записей аудита сохраняются целиком, включая автора, время и историческое поколение. Сравнение выполняется до и после открытия managed-сервиса; новый начальный снимок не добавляется. Время приводится к UTC только при чтении тестового снимка.
- Поколения всех установок меняются. Старое управляющее поколение отклоняется; четыре неактивные установки не допускают гостевые вызовы. Ядро завершает `disabling → disabled`, добавляя ровно одну новую системную запись аудита.
- Идентичность пространства сохраняется. Исходная сессия не переносится; устройство входит заново через обычный механизм ядра.
- `history_id` меняется; старая команда отклоняется без запуска гостя. Сверка полной квитанции возвращает исходный результат, а удалённое тело не восстанавливается.
- Данные, ревизия, три события и подтверждённый курсор outbox сохраняются. Старые ACK отклоняются; неподтверждённое событие получает новый токен и следующую попытку, после его подтверждения доступно третье событие.
- Исходный ZIP остаётся неизменным. После импорта гостевой код не вызывается.

## Обнаруженная несовместимость и исправление

Первый прогон [41326394070](https://github.com/space-protocol-project/space-server/actions/runs/41326394070), сервер `9817777c221c21583774ae17eeb1ee2973cfa081`, выявил ошибку рабочего экспорта: PostgreSQL Windows создавал внутренний дамп со сжатием gzip, а runtime Linux/macOS собирается без zlib. `pg_restore` отклонял Windows-архивы с сообщением `this build does not support compression with gzip`. Проверки архива на одной ОС эту несовместимость не обнаруживали.

В `preparePortableDump` добавлен `--compress=none`, предусмотренный [документацией PostgreSQL 17](https://www.postgresql.org/docs/17/app-pgdump.html). Внешний ZIP по-прежнему сжимается средствами Go. Формат манифеста, проверки доступа, согласованности и контрольных сумм не изменены. Лимит 2 ГиБ сохраняется и применяется к внутреннему несжатому дампу; оценка ёмкости больших пространств этим прогоном не выполняется.

Исправление касается новых архивов. Старый Windows-архив со сжатым дампом нужно восстановить на runtime с поддержкой gzip и экспортировать заново; автоматическое преобразование не добавлено.

## Границы проверки

Проверяется перенос реестра v2 между указанными образами ОС с версией PostgreSQL из текущего сборщика runtime. Это не проверка обновления между основными версиями PostgreSQL или архивной миграции реестра v1.

Managed-сервис вызывается через адаптеры ядра из тестового процесса. Гостевой план детерминирован; бинарные WASM-пакеты не устанавливаются из архива. Настоящий WASM и изоляция проверяются отдельным набором регрессии. Публичный API управления, Git-установка, обновление/откат пакетов и миграций, перенос клиентских MLS-данных и ручная приёмка интерфейса этим блоком не закрываются.

Следующее дополнение: [публичный API реестра и журнала аудита P1](SPACE-PLUGINS-P1-REGISTRY-API.md). Границы архивного прогона выше сохранены; API проверяется отдельным сетевым набором.
