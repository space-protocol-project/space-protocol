# P1 / E01: несколько экземпляров и согласованное обновление

Статус на 2 ноября 2026 года: подэтап принят в GitHub CI. Этот отчёт продолжает [историю версий](SPACE-PLUGINS-P1-VERSION-HISTORY.md). Полный E01 остаётся открытым.

## Модель установки

Установка задаёт общий пакет, разрешения, состояние жизненного цикла и поколение. В ней может быть несколько экземпляров: каждый имеет собственный идентификатор, канал ядра, данные, ревизию, квитанции команд и outbox. Каналы могут различаться. Отключение, карантин и обновление относятся ко всей установке; активные вызовы учитываются общим координатором.

Групповой профиль P1 принимает от двух до восьми экземпляров. Их полный состав задаётся при создании управляемого сервиса; изменение состава существующей установки не входит в этот срез. Прежний профиль обновления одного экземпляра сохраняется. Смешивать разные пакеты или разные исходные/целевые схемы внутри группы запрещено.

Пример: два экземпляра Чатов используют одинаковый пакет, но разные каналы. У первого есть сообщения и ревизия 17, у второго нет данных и ревизия 0. Общий план фиксирует обе ревизии. Успешная миграция первого ещё не меняет ни его рабочие данные, ни пакет: публикация возможна после готовности обоих.

## Контракт доверенного ядра

Публичный protobuf API обновлений пока не подключён. Экспериментальный Go API сервера:

| Метод | Назначение |
| --- | --- |
| `ExtensionP1GroupDigest` | Проверяет и вычисляет digest полного упорядоченного состава плана |
| `PrepareGroupUpgrade` | Под одной блокировкой сохраняет все планы, пакеты, модули и исходные снимки |
| `ReadGroupUpgrade` | Возвращает общий digest, курсоры экземпляров, готовность и признак публикации |
| `AdvanceGroupUpgrade` | Исполняет один шаг указанного экземпляра в изолированном `ProcessHost` |
| `PublishGroupUpgrade` | Атомарно публикует всю группу |
| `ListUpgradeVersions` | Возвращает общую историю установки с прежней пагинацией, без данных и модулей |

Каждый элемент `ExtensionP1GroupMember` содержит `Instance`, прежний `upgrade.Plan`, целевую регистрацию и модули шагов. Идентификаторы должны идти в строгом лексикографическом порядке без повторов. Состав и каналы сверяются с постоянным реестром: нельзя прислать подмножество установки или заменить экземпляр.

У всех планов совпадают пространство, установка, поколение, ревизия жизненного цикла, исходный и целевой пакеты, версии схем, digest разрешений и копии. `DataRevision` и снимки данных принадлежат отдельным экземплярам. Каждый модуль связан с digest соответствующего шага.

Digest группы — SHA-256 от `space.upgrade.group.p1`, нулевого байта и сериализованного Go JSON массива пар `Instance` / `Plan`. Это внутренний профиль прототипа, не новый публичный формат protobuf. `ExtensionP1GroupEvidence` связывает этот digest с прежними свидетельствами проверки пакета и резервной копии для каждого экземпляра. Реальную проверку подписей издателя и содержимого копии выполняет доверенный адаптер; один флаг `Complete` не заменяет проверку архива.

Подготовка, шаг, чтение, публикация и история используют настоящую сессию ядра, права владельца и проверку управления **всеми** каналами установки. Смена поколения, отзыв сессии и ACL сохраняют прежние границы транзакций. Гость не получает SQL, токен или право выбрать другую установку.

## Постоянный журнал и публикация

`extension_p1_meta.group_version=1` обозначает групповой формат. `extension_p1_group_jobs` хранит текущий неизменяемый состав, исходные документы, артефакты, результаты и курсоры. Каждый завершённый шаг содержит digest входа и модуля, выход, автора и поколение. Результат шага и его курсор фиксируются вместе; повтор после неопределённого COMMIT сначала читает журнал.

Рабочие данные не меняются во время подготовки. Публикация повторно проверяет весь состав, свидетельства и неизменность исходных данных. В одной транзакции она:

1. Заменяет данные и пакеты всех экземпляров.
2. Пересчитывает привязку установки по полному составу.
3. Записывает одно событие `publish_upgrade` и увеличивает ревизию установки один раз.
4. Меняет поколение установки и историю команд пространства.
5. Добавляет одну запись общей истории и отмечает план опубликованным.

Ошибка на любом экземпляре откатывает всю публикацию. Старая оболочка закрывается; после открытия новой установка остаётся выключенной. Повтор опубликованного digest не создаёт второй версии или события аудита. Ревизии данных, прежние квитанции и outbox сохраняются; старая команда не становится командой нового пакета.

`extension_p1_group_versions` хранит полные записи всех экземпляров и артефакты каждого опубликованного перехода. Следующий план может заменить только опубликованную рабочую запись. Цепочка проверяет непрерывность номеров, пакетов, схем, состава и каналов, монотонность ревизий и соответствие аудиту. Новая оболочка загружает последний опубликованный пакет каждого экземпляра, даже если уже существует следующий незавершённый план.

Открытие сервиса и проверка резервной копии отклоняют повреждённый digest, разрыв истории, потерю обязательных таблиц, расхождение рабочего журнала с историей и подмену пакета экземпляра. Восстановление меняет поколение и историю команд, сохраняя зафиксированные курсоры миграции.

## Границы и дальнейшая работа

Это прототип P1 для фиксированного состава одной установки, а не обновление нескольких независимых установок одной транзакцией. Добавление/удаление экземпляров существующей установки, автоматический откат, произвольный SQL, загрузка из Git и проверка издателей не добавлены.

Сохраняются пределы документа 16 КиБ / 32 ключа и квоты WASM. Запись группы ограничена 40 000 000 байт; предел не заменяет общий бюджет хранения истории. Полная проверка истории растёт с её длиной: производственный SLA не измерен.

Проверка резервных копий понимает новые таблицы. Отдельная [приёмка групповых архивов от 11 ноября](SPACE-PLUGINS-P1-GROUP-ARCHIVE.md) завершена: физические копии и ZIP на трёх ОС, шесть направлений переноса, четыре состояния, отказ повреждений и возобновление WASM на Linux. Прежние результаты [архивного подэтапа](SPACE-PLUGINS-P1-VERSION-ARCHIVE.md) по-прежнему относятся к одному экземпляру. Завершение процесса PostgreSQL исходным набором нескольких экземпляров не моделируется.

E01 ещё требует бюджета истории и правил очистки. Подключение управления обновлениями и экземплярами к приложению относится к P2/P3. Рабочие Чаты, Комнаты, Обсуждения и Лента продолжают использовать текущую архитектуру; этот срез не означает готовность 0.9.0.
