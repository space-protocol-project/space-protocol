# P1: доставка и подтверждение outbox

Продолжение [транзакционных мутаций](SPACE-PLUGINS-P1-MUTATIONS.md). Реализован отдельно включаемый внутренний прототип; рабочий сервер его не запускает. Это доставка доверенному обработчику ядра, а не клиентская подписка, публичный RPC или вызов WASM. Прототип проверен в GitHub CI и перенесён в main; P1 целиком не закрыт.

## Контракт

`NewExtensionP1Outbox(ctx, installation, instance, consumer)` принимает только доверенную привязку ядра к существующему экземпляру. Поддерживается ровно один неизменяемый consumer на экземпляр. Повторное открытие с тем же consumer сохраняет курсор, аренду и последнее подтверждение; другой consumer получает отказ. Несколько процессов одного consumer могут конкурировать за события. Fan-out нескольким независимым обработчикам пока не реализован.

`Claim` выдаёт самое раннее неподтверждённое событие в порядке `(revision, ordinal)`. Результат содержит installation, instance, стабильный event ID, тип, исходный JSON payload, ревизию, позицию, случайный 256-битный token аренды, срок и номер попытки. Пока аренда действует, новые Claim возвращают пустой результат. Следующее событие не обгоняет неподтверждённое; неисправный обработчик поэтому может остановить очередь своего экземпляра.

Аренда длится 30 секунд по `clock_timestamp()` PostgreSQL. После её истечения выдаётся то же событие с новым token и увеличенным номером попытки. Предыдущий token уже не может подтвердить событие. Номер попытки сбрасывается после успешного ACK; автоматического удаления события или пропуска после заданного числа ошибок нет.

`Ack` принимает token только текущей неистёкшей аренды в привязке installation/instance/consumer. Проверка времени выполняется отдельным SQL statement после получения блокировки строки: ожидание блокировки не продлевает аренду. ACK атомарно переносит курсор, сохраняет последний подтверждённый token и очищает аренду. Повтор последнего ACK безопасен и не подтверждает следующую аренду. Для более старых token после последующих подтверждений успех не обещается; они не двигают курсор. ACK другого экземпляра отклоняется.

`DispatchOne` получает аренду, вызывает доверенный обработчик вне транзакции и подтверждает событие только после его успешного возврата. Возвращаемый bool означает начатую попытку, а не успешное подтверждение. Обработчик получает context с пределом 30 секунд; он обязан соблюдать отмену. Ошибка, отмена или потеря аренды оставляют событие для следующей попытки после истечения срока. Не предусмотрены фоновые goroutine, автоматический цикл опроса, heartbeat и продление аренды.

## Граница сохранности и безопасности

Новую таблицу `extension_p1_delivery` создаёт только явный конструктор outbox после проверки версии экспериментального хранилища. Таблица содержит одну строку на instance, с внешним ключом к `extension_p1_instances`. Основные миграции сервера и версия схемы ядра 46 не меняются; конструктор мутаций и обычный запуск сервера таблицу доставки не создают. Нужна предварительная подготовка экземпляра через экспериментальный конструктор мутаций.

Claim и Ack используют короткие транзакции и блокировку одной строки доставки. Бюджет операции — 2 секунды, lock_timeout — 1 секунда, statement_timeout — 1,5 секунды. Во время обработчика транзакция не открыта. Разные экземпляры имеют независимые курсоры и аренды. События читаются только после commit транзакции мутации; сериализация мутаций экземпляра обеспечивает возрастающий порядок ревизий.

Гарантия — повторная доставка (*at least once*), а не exactly-once внешнего эффекта. Если получатель сохранил эффект, но процесс остановился до ACK, событие будет выдано снова. Получатель обязан сохранять event ID и свой эффект одной транзакцией либо использовать эквивалентную устойчивую дедупликацию. Уникальный token ограничивает подтверждение аренды, но не отменяет внешние эффекты уже работающего просроченного обработчика. Два обработчика могут временно выполнять одно событие после истечения аренды; дедупликация обязательна.

Payload не даёт права отправлять уведомления или раскрывать данные. Реальный обработчик должен определять допустимые получатели и заново проверять актуальные ACL в точке чтения/отправки. В прототипе нет доставки пользовательских сообщений, HTTP-запросов или иных внешних действий. API недоступен гостю и сетевому клиенту; перехват token не заменяет привязку доверенного обработчика.

ACK не удаляет строки outbox и не освобождает квоту 4096 событий. Квитанции команд также не очищаются. Retention, архивирование, dead-letter, смена consumer, удаление/обновление instance и согласованный backup/restore всех экспериментальных таблиц остаются отдельными задачами. При восстановлении данных без курсора возможна повторная доставка; восстанавливать курсор отдельно от outbox нельзя.

## Проверяемые сценарии

- Настоящий экспериментальный RPC сохраняет одну мутацию с двумя событиями; Claim и ACK сохраняют порядок и исходный payload.
- Действующая аренда запрещает следующую выдачу; чужой и просроченный token отклоняются; повтор после истечения срока сохраняет event ID и меняет token.
- Повтор последнего ACK не подтверждает новое событие; после двух подтверждений очередь пуста, сами события сохранены.
- Два Store одновременно получают только одну аренду; попытка смены consumer отклоняется.
- Новое открытие Store сохраняет действующую аренду. После имитации потери ACK и истечения срока повторный обработчик сохраняет эффект в тестовый inbox с уникальным event ID; эффект остаётся один.
- Ошибка обработчика и отмена перед ACK не передвигают курсор; после истечения срока возвращается прежнее событие.
- Другой instance не может подтвердить событие своим token; истечение срока во время ожидания блокировки проверяется после её получения.

Сроки в большинстве тестов переводятся в прошлое явным SQL в тестовой БД, без 30-секундных ожиданий. Отдельный сценарий действительно ждёт истечения короткого срока под блокировкой. Перезапуск проверяется новым Store, без SIGKILL процесса доставки; внешний брокер и клиентская сеть не используются. [Предыдущий стенд SIGKILL](SPACE-PLUGINS-P1-MUTATIONS.md#стенд-аварийного-восстановления-записи) проверяет процесс исполнителя мутаций, а не новый обработчик outbox.
