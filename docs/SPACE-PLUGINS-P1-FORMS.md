# P1: ограниченные декларативные формы

11 ноября 2026 года. Прототип добавляет `form.v1`, `input.v1`, `toggle.v1` и `choice.v1`. Контракт — [ui.schema.json](extensions/p1/ui.schema.json), [общий пример](extensions/p1/ui-form.json), [схема команды](extensions/p1/form-payload.schema.json). Это дополнение кандидата `space.ui.p1` до его фиксации, не стабильный публичный UI API.

Форма вызывает только объявленную команду. Она содержит 1–16 плоских полей; вложенные формы, произвольные виджеты, URL, сценарии и выражения запрещены. Текст ограничен 1–512 кодовыми точками Unicode, обязательность задаётся явно. Переключатель передаёт boolean, выбор — одно из 1–16 уникальных значений. Метки проходят ту же локализацию и обязательный английский fallback, что кнопки и разделы. Сохраняются общий бюджет 64 узлов, глубина 4, 16 КиБ документа и уникальность ID.

Состояние и отправка находятся в `ExtensionFormCubit`/Freezed и `ExtensionActions`; виджет хранит только жизненный цикл контроллеров интерфейса. Неверные значения не вызывают обработчик. Во время отправки снимок неизменяем, повторное нажатие не дублирует запрос; отказ сохраняет черновик. Закрытие Cubit не допускает позднего события. Статус успеха подтверждает только stateless-ответ прототипа, не COMMIT пользовательских данных.

Начальные значения — пустая строка для текста/выбора и false для переключателя. Прототип отправляет все поля, а не удаляет необязательные пустые значения. Если выбор необязателен, его серверная схема должна явно разрешать пустую строку как отсутствие выбора; несовпадение UI и схемы отклоняется сервером. В общем примере оба строковых поля обязательны. Автоматического преобразования значений или добавления привилегированных полей нет.

Проверка Flutter не заменяет серверную. `payloadschema.Decode` принимает ограниченный JSON Schema-профиль: плоский object, до 16 свойств, string с обязательным maxLength и необязательными minLength/enum, boolean, явный required и `additionalProperties:false`. Ссылки, регулярные выражения, вложенные объекты, числа, null и неизвестные ключи отклоняются. Dispatcher проверяет payload до авторизации гостевого вызова и до WASM; доверенный context создаётся отдельно ядром. Схемы копируются при регистрации и входят в идентичность пакета. Старые регистрации с пустыми схемами сохраняют прежний hash.

В исходном срезе серверный manifest проверялся по всем 12 обязательным полям. Адаптер поддерживал schema=1, `overview`/`acknowledge`, пустой список permissions и stateless-операции; остальные валидные декларации отклонялись как неподдержанные. Последующее расширение контракта и проверка capabilities описаны в [manifest v2](SPACE-PLUGINS-P1-MANIFEST-V2.md). Мутации и их квитанции не включаются автоматически для нового пакета без одобренной capability.

Вызов из Flutter проходит loopback HTTP → dispatcher → изолированный WASM. Linux использует cgroup, Windows — собственный ProcessHost. Этот HTTP-стенд имеет временные тестовые роли editor/reader; настоящие сессии и ACL отдельно проверяет `TestExtensionP1FormPayload` через gRPC ядра и PostgreSQL. Нельзя выдавать тестовые токены HTTP за рабочие сессии. API навигации и рабочий экран установки здесь не подключаются.
