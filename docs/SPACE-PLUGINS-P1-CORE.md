# P1: dispatcher, сессии ядра и контракт мутаций

Срез подготовки 0.9.0 от 30 октября 2026. Продолжает [демонстрацию WASM → Flutter](SPACE-PLUGINS-P1-DEMO.md). Новый экспериментальный RPC использует настоящие сессии и ACL PostgreSQL. Рабочий сервер не регистрирует ExtensionP1Service автоматически; CI регистрирует его отдельно с тем же authn.Interceptor, что и штатные RPC. Установка расширений, рабочая навигация и запись данных через WASM этим срезом не включаются.

## Реализованный путь доступа

1. Клиент получает обычную сессию через CreateChallenge/CompleteChallenge с подписью устройства. У запроса нет principal_id, device_id, space_id или доверенного context.
2. authn.Interceptor проверяет bearer-токен штатным Store.Authenticate и формирует actor/token. Публичные исключения авторизации на новые методы не распространяются.
3. ExtensionP1Authorizer принимает копию доверенной привязки instance → channel. Клиент не выбирает канал, файл WASM или разрешения host calls. Неизвестный instance и отсутствие токена закрывают доступ; внутренний demo-обход ядра не используется.
4. В короткой транзакции проверяется действующая сессия, grant, auth_epoch, родительский grant и pairing по общему sessionQuery. Push-only запрещён; principal из базы обязан совпадать с actor. Device в контексте P1 — идентификатор действующего grant, не предоставленный клиентом идентификатор.
5. channelAccess применяет членство, блокировку, доступность функции, видимость канала, ACL и scopes устройства. Query требует read; единственная stateless-команда acknowledge требует write. Reader не получает право записи через ACL; архивирование закрывает команду. Это начальная привязка к существующему каналу, не окончательная модель capabilities всех расширений.
6. Сервер получает space_id из server_state. access_revision содержит ревизию канала. Отдельный внутренний AccessStamp учитывает auth_epoch, ревизии настроек и членства, роль, ревизию канала и scopes. Он не передаётся WASM и не заменяет повторную авторизацию.
7. Транзакция закрывается до WASM. После результата dispatcher заново получает весь principal и снимок доступа. Исчезновение сессии, отказ ACL или изменение снимка запрещают выдачу результата. Длительная блокировка PostgreSQL на время выполнения гостя не удерживается.

Общий Runtime и ABI сохраняют прежние лимиты. Проверки доступа ограничены двумя секундами каждая; двухсекундный срок исполнения worker не включает первоначальную авторизацию. Контекст отмены RPC распространяется на SQL и WASM. Отзыв после завершения последней проверки не может отозвать уже переданные клиенту байты; это обычная граница выдачи ответа, а не обещание моментального стирания данных.

Исходные authn/auth/channels не изменены. Серверный модуль теперь явно зависит от вложенного эксперимента через локальный replace; версия wazero сохранена. Это зависимость сборки, не включение runtime в работающих пространствах. Генераторы и зависимости не обновлялись в этом срезе.

## Экспериментальный protobuf API

Канонический [extensions_p1.proto](../protocol/proto/space/v1/extensions_p1.proto) генерируется отдельным workflow plugin-p1-generation.yml с явными ревизиями трёх репозиториев. Существующие контракты не перегенерируются. Сохраняются Go/gRPC, Go Connect, Dart/Connect и OpenAPI.

| Метод | Вход | Результат и границы |
| --- | --- | --- |
| QueryExtension | instance_id, query, payload_json | document_json и ui_api; только overview с пустым объектом payload |
| ExecuteExtensionCommand | instance_id, command, payload_json, effect, idempotency_key, expected_state_revision | Сейчас только acknowledge, effect=NONE, пустой ключ и revision=0; статeless документ без записи |

Обязательный клиентский effect должен совпадать с доверенным описанием команды; он не выдаёт прав. UNSPECIFIED/MUTATION или поля мутации сейчас дают FailedPrecondition/mutation_not_supported до вызова WASM. Подмена через payload, null, дубли ключей и неверный JSON отклоняются. Общий envelope не больше 16 КиБ. Сервер проверяет JSON/UI version, полная UI schema по-прежнему проверяется Flutter renderer.

Ошибки отображаются фиксированными кодами gRPC: InvalidArgument, Unauthenticated, PermissionDenied, FailedPrecondition, ResourceExhausted, Unavailable, DeadlineExceeded, Canceled, Internal. Ошибки PostgreSQL и worker не выдаются наружу. Истёкшая сессия до interceptor даёт Unauthenticated; отказ повторной авторизации dispatcher — PermissionDenied. Маппинг не обещает раскрывать причину отзыва или существование скрытого канала.

Подготовленные Connect bindings ещё не зарегистрированы в HTTP-маршрутизаторе. Нативный Flutter текущего приложения не переведён на новый RPC. Реестр, contributions, lifecycle и стабильный ABI v1 остаются отдельной частью P1.

## Контракт изменения данных: нормативный план, ещё без исполнителя

ExtensionMutationPlan — недоверенное предложение, а не прямой доступ к PostgreSQL. Расширение не получает SQL, соединение с базой, произвольную таблицу или ключи другого instance. Пока транзакционный исполнитель отсутствует, все команды с мутациями явно запрещены.

Для последующей реализации фиксируем следующие правила:

- expected_state_revision относится к хранилищу instance, а не к access_revision. Ноль допускается только для нового хранилища. Каждая успешная непустая мутация увеличивает ревизию ровно на один; переполнение запрещено.
- idempotency_key — 16–128 ASCII-символов [A-Za-z0-9_-]. Область уникальности: установка + instance + principal + команда. В предварительном JSON API это request_id, в protobuf P1 — idempotency_key. Запись результата содержит digest доверенного package hash, ABI, имени команды, ожидаемой ревизии и точных байтов проверенного payload. Семантически равный JSON с иными байтами не считается тем же запросом.
- Повтор с тем же ключом и digest возвращает сохранённый результат, revision и replayed=true. Повтор с иным digest отклоняется как конфликт. Повтор не запускает WASM и не добавляет события. Проверка текущей сессии, устройства и ACL обязательна до поиска/выдачи сохранённого ответа; смена package hash не позволяет исполнить старый ключ заново.
- Проверенный план содержит 1–32 операции, максимум 16 событий, суммарно не более 16 КиБ в текущем P1 ABI. Ключ хранения — 1–256 байт UTF-8, без управляющих символов; это непрозрачный ключ, не путь файловой системы. Повтор ключа внутри плана запрещён. put_json обязан быть ограниченным корректным JSON; delete допустим только true. Неизвестные операции и типы событий отклоняются по доверенному manifest.
- WASM только предлагает план. После его завершения ядро начинает короткую транзакцию записи: блокирует/проверяет сессию и доступ, запись идемпотентности и состояние instance, сверяет package/version и ожидаемую ревизию, повторно проверяет план и квоты. Порядок блокировок должен быть согласован с существующими операциями отзыва и ACL до реализации; прежней проверки после гостя недостаточно.
- Данные instance, новая ревизия, квитанция идемпотентности и outbox событий записываются одним commit. До commit нет внешних побочных эффектов. Отказ любой проверки, ошибка БД, превышение квоты или отмена до commit откатывают весь набор.
- Потеря ответа после commit не означает откат: клиент повторяет тот же запрос с прежним ключом. Внешние обработчики outbox должны быть идемпотентны по event_id; доставка может повторяться. exactly-once вне транзакционной базы не обещается.
- Квитанции сохраняются не менее 30 суток. После удаления полного ответа сохраняется запрет повторного исполнения ключа до удаления instance; исчерпание квоты квитанций запрещает новые мутации, а не позволяет повторить старые. Удаление instance и резервное копирование должны учитывать данные, квитанции и outbox вместе.
- Доступ к текущим Чатам/Комнатам/Обсуждениям/Ленте идёт только через отдельные host adapters с их собственными инвариантами и единым путём записи. Универсальный план не даёт права менять существующие таблицы ядра.

Эти правила — критерии будущего исполнителя, не утверждение о наличии транзакций, хранилища расширений, outbox или дедупликации в текущем коде. В этом срезе не требуется миграция БД: схема остаётся 46.

Проверяемые ревизии: сервер `4c3a2674641d316614fc1ccab62918c8d10853db`, клиент `228ccee9e4144ecd5ba324598c09f8db3d8bff00`, контракт `7f388e2` (полный SHA в generation-inputs.json).

- [Генерация 41063198960](https://github.com/space-protocol-project/space-app/actions/runs/41063198960): buf lint, Go/gRPC/Connect, Dart/Connect и OpenAPI успешны.
- [Ядро 41064075086](https://github.com/space-protocol-project/space-server/actions/runs/41064075086): итоговый статус success, все шаги завершены успешно. Обычный go test ./... и вариант с -race дали по 491 успешному результату (291 верхнеуровневый тест и вложенные сценарии), 10 штатных пропусков. go vet, go mod verify и govulncheck для postgres/extensionp1 прошли; go.mod/go.sum совпадают с нормализованными CI версиями.
- Отдельный привилегированный прогон того же workflow: 5 верхнеуровневых тестов P1 и 6 вложенных сценариев — 11 успешных результатов без пропусков. Настоящий WASM worker запущен под cgroup; RPC использует настоящие сессии, полученные challenge/signature входом. Query и команда вернули разные документы; остановка и очистка cgroup успешны.
- Проверены запреты без сессии, для скрытого канала и команды reader; истечение сессии, отзыв grant, смена auth_epoch, push-only, отсутствие chat.read и блокировка участника. Во время вызова отдельно удалена сессия и изменены ревизии членства/канала — ответы отвергнуты. Подмена payload и попытка мутации не вызывают WASM.
- [Матрица хоста 41064321664](https://github.com/space-protocol-project/space-server/actions/runs/41064321664): девять заданий успешны; семь тестов dispatcher прошли на каждой из Linux/Windows/macOS, прежние проверки изоляции сохранены.
- [Клиент 41063728047](https://github.com/space-protocol-project/space-app/actions/runs/41063728047): анализ без замечаний, 7 widget-тестов, COG максимум 14 при неизменном пороге 15. Изменились только сгенерированные bindings; новый RPC ещё не используется интерфейсом.

[Сырые результаты и метаданные](p1-results/2026-10-30-core/) закреплены SHA-256. Десять пропусков общего ядра относятся к отдельным backup/portable/bundled PostgreSQL/network/TURN/baseline стендам и целевому WASM-тесту: последний затем выполнен без пропуска в привилегированном шаге. Отдельные backup/network стенды этим срезом не повторялись. Новая интеграция PostgreSQL/RPC/WASM проверена только на Linux; матрица хоста не заменяет её проверку на Windows/macOS.

Первый запуск генерации остановился до сборки из-за сокращённого SHA checkout; повтор использовал полные ревизии. Первый серверный запуск обнаружил оставшуюся ссылку на удалённую переменную в тесте; исправление прошло повторный CI. Лимиты и проверки доступа ради тестов не ослаблялись. Локальные сборки и тесты не выполнялись.

## Оставшаяся работа P1

Реестр установок/экземпляров и contributions; полная схема manifest и результатов; транзакционный host API с идемпотентностью/outbox и гонками отзыва; рабочая регистрация Connect/gRPC и клиентский транспорт; SDK и стабильный ABI; завершение платформенной изоляции. Четыре официальных расширения остаются будущими отдельными репозиториями, перенос данных не начат.
