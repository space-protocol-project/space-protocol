# P1: системное хранилище локального профиля и повторный вход

Продолжение от 4 ноября 2026 года к [паролю локального профиля](SPACE-PLUGINS-P1-CLIENT-PROFILE.md). Цель — проверить прежние `LocalProfileVerifier`, `PlatformKeyStorage` и `LocalSessionCubit` в собранном настольном Flutter-приложении с настоящим системным хранилищем и независимыми процессами.

## Стенд

Workflow приложения `plugin-p1-profile-native.yml` собирает отладочный нативный исполняемый файл для Windows, Linux и macOS. `local_profile_native_probe.dart` использует рабочий сервис профиля, настоящий PBKDF2 и локальные сессии. Тестовая оболочка хранилища только добавляет уникальное пространство имён к ключу; значения читает и записывает существующий `PlatformKeyStorage`, без файловой замены и без подмены MethodChannel.

| ОС | Реальный путь хранения | Изоляция и проверка |
|---|---|---|
| Windows | `PlatformKeyStorage` → Windows secure storage → DPAPI | Переопределён только путь каталога стенда; настоящие шифрование и файловые операции. Проверяются заголовок DPAPI, отсутствие открытой записи в файле и чтение следующим процессом через рабочий адаптер. Это не независимая реализация расшифровки DPAPI. |
| Linux | `PlatformKeyStorage` → libsecret → GNOME Keyring | Отдельные XDG-каталоги и D-Bus-сеанс; GNOME Keyring запускается заново с непустым тестовым паролем для каждого процесса. Значение дополнительно сравнивается с независимым чтением `secret-tool`. |
| macOS | `PlatformKeyStorage` → системный login Keychain | Временная отдельная Keychain; после проверки восстанавливаются прежние default/search list. Нативный тестовый канал сравнивает значение прямым `SecItemCopyMatching` в этом хранилище. Политика `usesDataProtectionKeychain: false` сохранена. |

В macOS-сборке стенда временно заменяется только `MainFlutterWindow.swift` на уже используемый тестовый канал Keychain с ключом профиля. Рабочий исходник окна в репозитории не меняется. У каждого запуска — новый PID; Python-координатор ждёт подтверждённого завершения предшественника. Пароль и проверочная запись не публикуются в отчёте: сохраняются статусы, PID, число попыток и SHA-256 привязки устройства/профиля. Данные синтетические; рабочие профили не используются.

## Проверяемая последовательность

1. Создать отсутствующий профиль, подтвердить запись и нативное чтение; завершить Flutter-процесс принудительно после контрольной точки.
2. Новым процессом подтвердить наличие прежнего профиля и исходное заблокированное состояние Cubit, войти правильным паролем, проверить привязку сессии и ручную блокировку.
3. Пять раз запускать отдельный процесс с неправильным паролем. После каждой сохранённой попытки и отказа принудительно завершать процесс. Счётчик обязан последовательно увеличиваться от 1 до 5.
4. Следующим процессом попытаться войти правильным паролем до истечения задержки. Доступ должен остаться закрытым, счётчик — равным 5.
5. После 31 секунды запустить ещё один процесс: правильный пароль открывает ту же привязку, счётчик сбрасывается до 0.
6. Записать намеренно повреждённую тестовую запись. Проверка не выдаёт сессию и не пересоздаёт профиль.
7. Отдельным процессом удалить только ключ стенда и подтвердить его отсутствие. На macOS удалить временную Keychain и восстановить исходные настройки поиска.

Подтверждены 11 независимых процессов и шесть принудительных завершений на ОС. Нативный сценарий проверяет перезапуск после подтверждённой записи; завершения во время системной записи здесь нет. На каждой ОС также запускаются целевые регрессионные тесты профиля, окна, области сессии и политики macOS Keychain. Общий анализ Flutter и COG ≤15 остаются обязательными.

## Границы

Проверяется перезапуск процесса приложения, а на Linux также службы Secret Service. Это не перезагрузка ОС, отключение питания, миграция между учётными записями ОС или восстановление откатанной копии хранилища. Не проверяются системные запросы разблокировки Keychain/Secret Service, биометрия и производительность релизной сборки. Успех API записи с последующим чтением не доказывает сохранность при потере питания.

Пароль по-прежнему управляет локальной сессией и не шифрует журнал расширений. Смена/сброс пароля, несколько профилей, системный выбор каталогов, файловый адаптер и клиентский WASM-исполнитель остаются отдельными блоками P1.
