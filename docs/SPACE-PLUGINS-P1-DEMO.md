# P1: единый контракт хоста и сквозная демонстрация

Продолжение подготовки 0.9.0. Этот срез соединяет экспериментальный сервер, настоящий изолированный WASM worker и декларативный интерфейс Flutter. Рабочие пространства, навигация приложения и существующие RPC пока не используют новый путь. Установка расширений из Git, подпись пакетов и SDK для внешних разработчиков остаются отдельными задачами.

## Платформенная граница

| Платформа локального исполнения | Подтверждённая основа | Статус этого среза |
| --- | --- | --- |
| Linux | cgroup v2, отдельный UID worker, deadline, очистка и восстановление | Сквозной экспериментальный сервер CI |
| Windows | Job Objects, атомарное назначение Job при создании, квоты и очистка | Общий интерфейс компилируется; сквозной HTTP/UI-прогон пока только Linux |
| macOS | Исследование RLIMIT, Linux guest на Intel, аварии launcher/VMM | Защищённый ProcessHost возвращает ErrIsolation; общий предел VMM и ARM64 не подтверждены |

Это состояние реализации, а не объявление готовности платформ к выпуску. Linux/Windows ещё требуют завершения изоляции прав и рабочей интеграции. Ограничение локального исполнения расширений на macOS не запрещает клиенту macOS подключаться к серверу с поддержкой расширений. Небезопасного запасного исполнения WASM в процессе сервера нет.

## Внутренний контракт Runtime

`experiments/extensions/runtime.go` задаёт общий интерфейс P1:

- Создание: `NewProcessHost(root, executable)` проверяет платформенную границу и возвращает готовый хост либо ошибку. Пути выбирает администратор, не расширение.
- `Status()` возвращает ready/draining/stopped, 256 МиБ на worker, 512 МиБ на хост и максимум два одновременных вызова. Это состояние управляющего объекта; оно не заменяет проверку ограничений при каждом запуске worker.
- `Invoke(ctx, Invocation{Module, Input})` исполняет реальную компиляцию и вызов в одноразовом worker. Публичный вызывающий код не выбирает разрешения host calls; диагностический wait отключён, выбран compiler.
- Отмена: context вызывающего кода; общий deadline компиляции/процесса не больше двух секунд. Внутри worker сохраняется отдельный срок вызова WASM 100 мс. Его срабатывание завершает worker и пока отображается общим extension_failed; deadline наружу соответствует отмене/истечению context управляющего процесса. Ответ выдаётся после завершения worker и очистки его ресурсов.
- `Close()` сразу запрещает новые вызовы. При активных вызовах возвращает ErrQuota и оставляет draining; вызывающий код отменяет/дожидается вызовов и повторяет Close. После успешной очистки — stopped. Автоматическое ожидание внутри Close не обещается.
- Ошибки: ErrIsolation, ErrQuota, отмена/истечение context и ошибка исполнения. Подробности внутренних сбоев не возвращаются пользователю.

Интерфейс принадлежит серверному коду. Это не WASM ABI и не протокол для стороннего клиента. Внутренний IPC worker остаётся `space.worker.p1`, гостевой ABI — `space_plugin_p1`, UI — `space.ui.p1`; стабильный ABI v1 ещё не закреплён.

## Реестр и dispatcher демонстрации

Сервер `cmd/p1-demo` слушает только `127.0.0.1` на случайном порту. Его HTTP endpoint `/dispatch` не подключён к публичному Connect API. Перед запуском создаётся изолированный ProcessHost, а адрес готовности записывается после подготовки HTTP listener.

В `demo/manifest.json` расширение объявляет экспериментальные версии, contribution `overview`, query `overview` и command `acknowledge`. Это отдельное ограниченное описание демонстрации, не замена полной схемы package manifest. Администратор стенда связывает его с WASM и идентификатором `demo`; дополнительный `broken` указывает на тестовый бесконечный цикл. Входящий запрос не может выбрать файл, WASM или разрешения хоста.

Запрос содержит ровно пять полей: `protocol=space.dispatch.p1`, `instance`, `kind`, `name`, `payload`. В этом примере payload обязан быть пустым объектом. Лишние поля, неправильный регистр имён полей, дубликаты JSON-ключей, null payload, неизвестные команды и неподдерживаемая версия отклоняются. Лимит входа и выхода — 16 КиБ; правила UTF-8 и глубины сохраняются.

Dispatcher получает Authorize из доверенного серверного кода. Авторизация проверяется до исполнения и повторно перед выдачей результата; изменение identity/space/instance/device/access revision отклоняет ответ. Контекст формируется сервером: ABI, имя операции, пространство, экземпляр, пользователь, устройство, ревизия доступа и deadline. Клиентский context не принимается. Ревизия доступа проверяется как положительная десятичная строка uint64 без ведущих нулей. В CI используется отдельный адаптер с двумя случайными bearer-токенами: читателю разрешён query, редактору query и command. Это проверка границы, а не интеграция с настоящей сессией, подписью устройства и ACL базы данных.

Повторная авторизация после вызова не откатывает побочные эффекты. Демонстрационная команда не пишет данные и не вызывает внешние службы; для будущих мутаций потребуются транзакции, идемпотентность и проверка доступа в точке записи.

После исполнения сервер проверяет JSON и версию UI, клиент — полный поддерживаемый документ, команды, переводы и бюджеты дерева. Полная серверная валидация UI schema ещё не подключена. Ошибки HTTP имеют только фиксированный код: invalid_request, unsupported_version, permission_denied, quota_exceeded, unavailable, deadline или extension_failed.

## Демонстрационное расширение и Flutter

`demo/build.py` создаёт WAT и компилирует его в CI через wat2wasm. Модуль сравнивает ожидаемый префикс сериализации двух поддерживаемых запросов и возвращает один из двух документов: «Готово к проверке» или «Команда выполнена», с кнопкой «Выполнить команду». Текст и структура приходят из WASM, а не подставляются сервером после вызова. Этот небольшой WAT — проверяемая фикстура, не универсальный JSON-парсер и не рекомендуемый SDK. Связь с конкретной сериализацией Go должна исчезнуть при подготовке SDK.

Состояние Flutter находится в `ExtensionDemoSession` (Cubit); рендерер повторно использует ExtensionPanel. Транспорт принимает только явно заданный loopback endpoint, не следует перенаправлениям, ограничивает ответ 16 КиБ и ожидание пятью секундами, закрывает HTTP client. Ошибки показываются общим сообщением без деталей сервера. Повторная команда блокируется до окончания текущей операции, закрытый Cubit не обновляется.

Команда не сохраняет состояние: новый query и горячий перезапуск снова показывают исходный документ. Это намеренная граница примера, не потеря пользовательских данных. UI не зарегистрирован в навигации рабочего приложения; отдельный нативный probe нужен только CI.

## Приёмка в GitHub CI

Серверный `plugin-p1.yml` проверяет общий модуль и dispatcher на трёх ОС, включая race, vet, mod verify и govulncheck, а также сохраняет прежние проверки изоляции. Модульные тесты отдельно проверяют отказ до вызова WASM, формирование доверенного context, отзыв прав во время вызова, версию/команду и отсутствие утечки внутренней ошибки.

Новый `space-app/.github/workflows/plugin-p1-demo.yml` закрепляет полный SHA сервера и выполняет:

1. Настоящую сборку WAT, worker и отдельного loopback-сервера с cgroup.
2. HTTP-отказы без прав, для команды читателя, неизвестной версии/экземпляра, подмены context и зацикленного WASM; затем здоровый query.
3. Widget-тесты существующего рендерера и два сетевых теста: команда редактора обновляет текст; отказ читателю показывает общий экран ошибки, повторный query работает.
4. Нативный Linux probe через Flutter machine: query → нажатие кнопки → ответ WASM → настоящий hot restart → query → повторное нажатие.
5. flutter analyze и проверку COG во всём рукописном Dart без повышения порога. Форматирование также выполняется в CI.

Локальные сборки, тесты и запуск Flutter не выполняются.

[Исходные результаты](p1-results/2026-10-30-demo/) сохраняются вместе с метаданными запусков и SHA-256. Проверка реального HTTP/UI в этом срезе относится только к Linux. Проверки серверного модуля на других ОС не подтверждают сквозной клиентский сценарий на них.

При подготовке исправлены лишний импорт Go и порядок ожидания первого состояния Flutter. Раннее ожидание HTTP 504 для зацикленного WASM оказалось неверным: 100-миллисекундный срок внутри worker завершается раньше внешнего deadline, а текущий IPC не передаёт тип ошибки дочернего runtime. Тест требует HTTP 502 / extension_failed и здоровый вызов после него; сроки не увеличены. Worker размещён в `/tmp` отдельно от checkout, а контрольная echo-фикстура дополнительно запускается под UID nobody. Ранний отказ цикла сам по себе не доказывал ошибку доступа к исполняемому файлу.
