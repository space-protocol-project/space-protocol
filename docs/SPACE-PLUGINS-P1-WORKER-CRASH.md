# P1: совместная авария сервера и WASM worker

Продолжение [транзакционных мутаций](SPACE-PLUGINS-P1-MUTATIONS.md) и [восстановления ProcessHost](SPACE-PLUGINS-P1-RECOVERY.md). Стенд соединяет настоящий серверный executor, сессии, gRPC и PostgreSQL с изолированным WASM. Рабочий сервер по-прежнему не регистрирует экспериментальный API.

## Точки отказа

Worker обслуживает один вызов, затем завершается до начала транзакции записи. Поэтому нельзя считать остановку сервера на SQL-барьере одновременной аварией двух живых процессов. Проверяются три различные точки:

| Точка | Состояние при аварии | Ожидаемое восстановление |
| --- | --- | --- |
| during_worker | Настоящий WASM уже вычислил результат, живой worker остановлен до выдачи ответа хосту | После SIGKILL сервера worker завершается; записей нет; повтор выполняет WASM заново |
| before_commit | Worker уже завершён; SQL-барьер удерживает вставку outbox внутри транзакции | PostgreSQL откатывает запись; повтор выполняет WASM заново |
| after_commit | Worker уже завершён; данные и квитанция сохранены, ответ клиенту удерживается | Повтор возвращает прежнюю квитанцию, WASM не вызывается |

Первый сценарий использует отдельный исполняемый файл только для CI: он вызывает тот же extensions.Worker и останавливает себя SIGSTOP в обработчике вывода после вычисления результата. Тест подтверждает состояние T (stopped) через /proc для PID из cgroup.procs. Сам гостевой код, компилятор, протокол worker и запуск ProcessHost настоящие. В рабочем worker нет тестового переключателя. Это управляемая остановка перед выдачей результата, а не авария в произвольной инструкции компилятора или гостя.

Родитель принудительно завершает процесс сервера и проверяет SIGKILL через WaitStatus. Остановленный worker должен исчезнуть вслед за сервером благодаря существующему Pdeathsig; до запуска нового хоста проверяется populated 0 для его cgroup. Новый процесс открывает тот же Store и создаёт ProcessHost на прежнем корне: восстановление убирает оставшиеся группы. После сценария отдельное восстановление и Close проверяют отсутствие групп space-p1-*. Лимиты времени, памяти и процессов не увеличиваются.

## Проверки сохранности

Повтор использует ту же сессию, команду, ключ идемпотентности и модуль WASM. После восстановления должны остаться ровно одна ревизия, одна запись, одна квитанция и одно событие. Проверяются значение данных, содержимое события, сохранённый protobuf ответа и неизменный ID события после commit. Счётчик входов в Runtime сохраняется в файле с fsync: два вызова до commit, один после commit. Завершившийся повтор проверяется также после Logout: отозванная сессия не получает квитанцию.

Во время аварии PostgreSQL продолжает работать. Отключение питания, авария самой БД, отказ диска, неопределённый COMMIT при разрыве соединения с PostgreSQL и долговременная смешанная нагрузка этим стендом не проверяются. Новый сценарий относится к Linux/cgroup v2; он не подтверждает совместное восстановление на Windows или macOS. P1 целиком остаётся открытым.
