# P1 / E01: последовательные обновления и история версий

Статус на 2 ноября 2026 года: подэтап принят в GitHub CI на Ubuntu 24.04 с PostgreSQL 17.11. Продолжение [WASM-миграций и атомарной публикации](SPACE-PLUGINS-P1-WASM-PUBLISH.md). Это явно включаемый прототип; E01 и P1 в целом остаются открытыми.

Продолжение: [архивное восстановление истории и перенос ZIP между Linux, Windows и macOS](SPACE-PLUGINS-P1-VERSION-ARCHIVE.md). Ниже сохранены границы исходной приёмки последовательных обновлений.

## Последовательность обновлений

Одна установка теперь допускает несколько обновлений подряд. Исходная версия схемы берётся из последней опубликованной записи в БД, а не из заявления вызывающей стороны. Для установки без истории исходная схема равна 1. Следующий план обязан продолжать текущий digest пакета и версию схемы, учитывать текущие ревизии данных и жизненного цикла и пройти прежние проверки сессии, ACL, доверия и согласованной копии.

При подготовке следующего плана сервер проверяет завершённую публикацию и сохранённую историю. Только после этого он удаляет из рабочих таблиц избыточные копии прежнего плана, шагов и артефактов и сохраняет новый план одной транзакцией. Незавершённый план нельзя перезаписать. История опубликованных версий остаётся неизменной. Поддерживается обновление только кода: разные пакеты, одинаковая версия схемы и пустой список шагов.

При перезапуске действующий пакет загружается из последней опубликованной записи истории, в том числе когда следующий план уже подготовлен. Переданный в конфигурации пакет должен принадлежать известной цепочке этой установки; произвольная замена запрещена. Новая публикация по-прежнему оставляет установку выключенной, меняет поколение и историю команд; включение требует отдельного действия владельца.

## Постоянная история

Таблица `extension_p1_versions` и маркер `versions_version=1` добавляются транзакционно. Каждая публикация сохраняет:

- номер в цепочке, digest плана, исходного и целевого пакетов;
- исходную и целевую версии схемы, ревизию lifecycle, автора и поколение публикации;
- полный план, исходный и итоговый документы, целевую регистрацию пакета и модули миграций;
- результаты всех шагов с digest входа, автором, поколением и признаком изолированного WASM-исполнения;
- SHA-256 полной записи для проверки целостности.

История фиксируется тем же COMMIT, что рабочие пакет и данные, аудит и поколение. Уникальные ключи запрещают повтор плана или ревизии публикации. Сервер проверяет непрерывность номеров, цепочку пакетов и схем, артефакты и результаты шагов, соответствие каждой публикации аудиту и соответствие последней версии рабочей установке. Пропуск записи, удаление всей истории или таблицы и повреждение digest блокируют открытие и проверку резервной копии. SHA-256 не является подписью издателя и не защищает от согласованной подмены всей БД её администратором.

Метод доверенного Go-ядра `ListUpgradeVersions(ctx, token, installation, after, limit)` возвращает только метаданные после номера `after`, по возрастанию, не более 100 записей. Он использует существующие проверки сессии владельца, ACL и поколения. Документы и WASM через него не выдаются. Нового protobuf RPC и пользовательского экрана в этом срезе нет.

Существующая публикация предыдущего прототипа переносится в первую запись истории при открытии. Используются сохранённые артефакты, шаги и подлинные автор/поколение из аудита; отсутствующие прежние версии не выдумываются. Исходный пакет до первой публикации известен только по digest, его WASM задним числом не восстанавливается.

## Восстановление после сбоев

| Сценарий | Ожидаемое состояние после открытия |
| --- | --- |
| Обрыв до COMMIT подготовки второго плана | Сохраняются прежний опубликованный план и одна запись истории; новый план можно подготовить заново |
| Подготовка зафиксирована, ответ COMMIT потерян | Сохранён новый незавершённый план; действующим остаётся предыдущий пакет |
| Обрыв до COMMIT второй публикации | История и рабочие данные остаются на предыдущей версии; готовую публикацию можно повторить |
| Публикация зафиксирована, ответ потерян | Новая версия и история уже согласованы; повтор не создаёт ещё одну запись |
| Принудительное завершение процесса до/после второй публикации | После нового запуска выбирается соответствующий пакет; завершение или повтор публикации сохраняет непрерывную историю |

## Границы и продолжение E01

Проверяемая цепочка: схема 1 → 2 → 3 → обновление кода при схеме 3. Сохраняются ограничения P1: один instance на установку, документ до 16 КиБ и 32 ключей, существующие квоты WASM. Одна архивная запись ограничена 5 000 000 байт; автоматического удаления истории и общего бюджета её хранения пока нет. Полная проверка истории растёт с её длиной и не является измеренным производственным SLA.

История версий схем — каталог фактически опубликованных переходов этой установки, а не глобальный реестр схем или поддержка произвольного SQL. Автоматический откат на прежнюю версию, установка из Git и проверка издателей E04 не добавлены. Публичное API обновлений и истории и соответствующий интерфейс управления остаются дальнейшей работой P2/P3; ранее принятые RPC реестра и аудита сохраняются.

Новая таблица включена в проверку резервных копий; полноценный цикл ZIP-экспорта/импорта и перенос нового формата между Linux, Windows и macOS требуют отдельной приёмки. Завершение самого PostgreSQL здесь не моделируется. Рабочие Чаты, Комнаты, Обсуждения и Лента не переключаются на прототип; выпуск 0.9.0 этим срезом не объявляется готовым.
