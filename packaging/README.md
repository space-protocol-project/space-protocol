# Установщики Space

Workflow `desktop.yml` собирает приложение и сохраняет установщики и SHA-256 в артефактах GitHub Actions на 30 дней. Он запускается вручную и при изменениях клиента в main/PR. Это пока сборки приложения, домашний сервер в них не включён.

- Windows x64: Inno Setup, установка без прав администратора в профиль пользователя, ярлык и удаление через настройки Windows. Компилятор берётся из образа GitHub runner.
- macOS: DMG с Space.app и ссылкой Applications; архитектура указана в имени файла. Подпись Apple и notarization ещё не настроены, Gatekeeper может препятствовать запуску.
- Linux x64: самораспаковывающийся `.run`, установка в `~/.local/opt/space`, команда `~/.local/bin/space`, ярлык приложения. `--extract DIR` распаковывает без установки. Нужны совместимая glibc (сборка Ubuntu 22.04), GTK 3 и libsecret; это не универсальный пакет для всех дистрибутивов.

Сборка Linux устанавливает clang, cmake, ninja-build, pkg-config, libgtk-3-dev и libsecret-1-dev только на одноразовом runner. Локальная установка зависимостей и Docker не требуются для изменения проекта.

Поддержка сборки macOS/Linux не заменяет проверки на физических системах: защищённое хранилище, камера и восстановление требуют отдельных проверок. Камера сейчас реализована для Windows.

## Публикация в GitHub Releases

Тег `v0.1.0` запускает сборку установщиков и полный workflow проверок сервера/клиента. После успешных проверок CI публикует экспериментальный выпуск с тремя установщиками и общим `SHA256SUMS.txt`. Версия приложения и Windows Setup берётся из тега.

Тег `home-v0.1.0` запускает сборку комплектов домашнего сервера, проверки перезапуска базы, владельца и приглашённого участника через TLS. После успешных проверок CI публикует архивы, платформенные JSON-дескрипторы и SHA-256. Это отдельный выпуск, который не заменяет последний выпуск приложения.

Перед тегом добавьте одноимённый раздел `## vX.Y.Z` либо `## home-vX.Y.Z` в корневой `Changelog.md`. `packaging/release-notes.py` переносит только содержимое этого раздела; пропуск, пустой или дублированный раздел прекращает публикацию. Ручные запуски и обычные изменения main сохраняют артефакты без публикации. Повторная публикация существующего тега не перезаписывает выпуск автоматически.

В приложении закреплён дескриптор домашнего runtime (`client/assets/home/runtime-manifest.json`). После публикации нового комплекта сначала проверьте его дескрипторы и явно обновите этот файл, затем выпускайте приложение. Пользовательская база при этом остаётся в отдельном каталоге; переход на другую основную версию PostgreSQL требует отдельной процедуры миграции.
