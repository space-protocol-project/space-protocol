# Веб-панель сервера

Первый работающий срез встроен в Go-сервер и открывается по `/space`. [Исходники](../server/internal/spaceweb/assets/) используют общий [контракт](../protocol/proto/space/v1/space.proto). Отдельный frontend-сервер не нужен. Оформление: Gruvbox, радиус областей 12 px, адаптивная компоновка.

Доступны назначение первого владельца, вход по подписи, выход с удалением сессии, название пространства и чата, включение чата и режим регистрации open/closed. Изменения сохраняются в PostgreSQL с проверкой revision и аудитом. Отключение закрывает также API чата, но сохраняет сообщения. Closed запрещает новые корневые идентичности; известные пользователи могут подключать устройства.

## Запуск без Docker

Нужны Go и доступная PostgreSQL. Из каталога `server`:

```powershell
$env:SPACE_DATABASE_URL = 'postgres://space:YOUR_PASSWORD@127.0.0.1:5432/space?sslmode=disable'
go run ./cmd/space-server -setup-code
go run ./cmd/space-server
```

Откройте `http://127.0.0.1:8080/space`. Подтвердите создание локальной идентичности панели, затем введите код. Он действует 15 минут. Повторная команда заменяет старый код; после назначения владельца больше не выдаёт коды. В базе хранится только SHA-256, публичный API код не раскрывает. Не передавайте код другим людям.

Открыть страницу может любой процесс, имеющий доступ к локальному порту. Для управления сервер проверяет действующую сессию владельца и отдельное подписанное разрешение устройства `space.manage`. Адрес `/space` и локальное подключение сами по себе административных прав не дают.

## На сервере нет браузера

Настройте PostgreSQL и переменную SPACE_DATABASE_URL на сервере. Из каталога `server`:

```sh
go run ./cmd/space-server -setup-code
go run ./cmd/space-server -http 127.0.0.1:8080 -origin http://127.0.0.1:18080
```

На своём компьютере создайте туннель, заменив SSH-адрес:

```sh
ssh -N -L 127.0.0.1:18080:127.0.0.1:8080 user@your-server
```

Откройте `http://127.0.0.1:18080/space` в своём браузере. Браузер на сервере не нужен; соединение между компьютерами защищает SSH. Порт 18080 должен быть свободен. Сохраняйте выбранный origin: браузерные ключи привязаны к нему. При порте 8080 с обеих сторон отдельный `-origin` не нужен.

Текущий сервер разрешает только loopback IP и локальный HTTP origin. Публичный HTTPS и reverse proxy ещё предстоят. Этот экспериментальный профиль не предназначен для открытия в интернет.

## Ключи и ограничения

WebCrypto создаёт отдельные root/device Ed25519 CryptoKey. Неэкспортируемые приватные ключи хранятся в IndexedDB, токен — только в памяти страницы. Это не аппаратная защита и не passkey: XSS может использовать ключ для подписи. Панель поставляет свои статические скрипты, использует строгую CSP и проверку Host/Origin.

Идентичность панели пока отдельна от Flutter. Pairing и QR recovery для неё не реализованы. Очистка профиля браузера, смена origin или потеря компьютера могут лишить владельца доступа. Используйте только экспериментальную установку до реализации восстановления. Повторная выдача разрешения устройства требует отдельного подтверждения. Выход удаляет сессию, но сохраняет ключи и grant.

Далее: роли, приглашения, произвольные каналы/views, forum/feed/media, квоты, retention, состояние служб, резервные копии и восстановление владельца. Панель не получает Docker socket, не запускает shell-команды и не отправляет recovery seed на backend.
