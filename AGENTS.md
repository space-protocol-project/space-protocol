# Правила работы с кодом

- Общайтесь и пишите пояснения по-русски. Используйте понятные имена и сохраняйте низкую когнитивную сложность проверок.
- Начинайте с `README.md`, `TODO.md` и профильных решений в `docs/adr/`. Для новой подсистемы согласуйте контракт и критерии приёмки в задаче по `CONTRIBUTING.md`.

## Изменение и проверка контрактов

- Меняйте исходные `.proto` в `protocol/proto/space/v1/`. Сохраняйте номера и типы существующих полей и номера значений перечислений. Удалённые номера и имена резервируйте через `reserved`. При изменении API проверяйте HTTP-маршруты и правила ProtoJSON. [ADR-015](docs/adr/015-api-transport.md)
- Из корня `space-protocol` выполните `buf lint`, затем `buf generate protocol/proto` для обновления OpenAPI в `protocol/openapi/`. Проверьте результат командой `python3 .github/scripts/check_protocol.py`, которую запускает CI. Используйте закреплённые версии инструментов и просматривайте изменения сгенерированных файлов перед коммитом. [Руководство по генерации](protocol/GENERATING.md)
- Если требуется совместимость с прежним контрактом, сравните схемы командой `buf breaking --against <база>` и укажите выбранную базовую ревизию в запросе на слияние. Стабильная базовая ревизия пока не назначена.
- При изменении схем расширений в `docs/extensions/p1/` обновите затронутые тестовые примеры и запустите соответствующие скрипты, например `python3 tools/check_manifest_v2.py`. Используйте синтетические данные. [Проверки схем расширений в CI](.github/workflows/extension-p1.yml)

## Совместимость с сервером и клиентом

- Из корня `space-server` выполните `buf generate ../space-protocol/protocol/proto --template buf.gen.yaml`. Для Connect повторите команду с `--template buf.connect.gen.yaml`. Сохраните обновлённые привязки в `gen/` и выполните `go test ./...`. Для интеграционных тестов задайте `SPACE_TEST_DATABASE_URL` с отдельной тестовой PostgreSQL.
- Из корня `space-app` выполните `buf generate ../space-protocol/protocol/proto --template client/buf.gen.yaml`. Для Connect повторите команду с `--template client/buf.connect.gen.yaml`. Сохраните привязки в `client/lib/src/generated/`, затем из `client/` выполните `flutter analyze` и `flutter test`.
- Для сквозной проверки запустите `space-server/.github/workflows/server.yml` на коммите сервера и передайте SHA приложения в `app_ref`. CI поднимет сервер с тестовой PostgreSQL и запустит проверки Dart, включая Connect. Для проверки настольного чата запустите `space-app/.github/workflows/desktop.yml` на коммите приложения с полным SHA сервера в `server_ref`.
- Проверьте изменённый RPC через клиент. Если нужно поддержать поэтапное обновление, проверьте новый клиент со старым сервером и старый клиент с новым сервером.
- В запросе на слияние укажите связанные коммиты сервера и клиента, проверенные сценарии и ограничения совместимости. Изменения формата обмена сопровождайте схемами и тестовыми примерами.
